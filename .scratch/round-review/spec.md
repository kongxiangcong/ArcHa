# 探针断点调试

Status: ready-for-agent

## Problem Statement

自动探索会连续生成和执行探针，用户难以在执行前检查专家的假设与设计，也难以验证不合理方案来自哪些输入或框架行为。现有单次角色调用和停止功能没有贯通“查看提案、给方向意见、专家重拟、继续”的调试闭环。

## Solution

增加可选的探针断点调试模式：专家成功生成探针后、Executor 执行前停下。用户查看假设、依据与设计，选择继续，或提交方向意见让专家重拟后再次停下。继续会执行当前探针、分析结果并生成下一探针，然后再次停下；遇到完成、阻塞或预算耗尽则沿用现有处理。

CLI 与现有工作台提供相同操作。工作台突出当前探针和操作，历史、完整认知状态及日志按需展开。这是检查自动框架的调试工具，保持最小实现。

## User Stories

1. 作为框架调试者，我希望显式启用调试模式，以便逐轮检查自动探索行为。
2. 作为框架调试者，我希望专家出题后停在执行前，以便检查假设与设计是否合理。
3. 作为框架调试者，我希望看到当前探针、假设依据及必要上下文，以便理解下一步的选择。
4. 作为框架调试者，我希望继续只推进到下一个探针断点，以便逐轮观察结果如何影响专家判断。
5. 作为框架调试者，我希望只提交方向意见，由专家设计具体调整方案，以便检验专家的调整能力。
6. 作为框架调试者，我希望重拟后再次停下且不消耗探索轮数，以便检查修改是否回应了意见。
7. 作为框架调试者，我希望从 CLI 和浏览器完成相同闭环，以便使用适合当前环境的入口。
8. 作为框架调试者，我希望展开相关输入材料、原始输出及错误日志，以便排查不合理假设或执行失败的原因。
9. 作为框架调试者，我希望查看和刷新界面不会推进探索，以便安全检查现场。
10. 作为框架调试者，我希望失败如实显示且保留已提交成果，以便修正问题后继续调试。
11. 作为自动探索使用者，我希望未启用调试模式时保持既有行为，以便继续自动推进项目。

## Implementation Decisions

- 复用专题执行引擎、单次角色派发和提交边界。固定断点位于专家成功提交探针之后、Executor 派发之前；等待时正常结束调用并释放工程锁，不用 stop 模拟等待，不维持后台等待进程。
- 调试选项必须在 CLI 和工作台中明确可见。调试中的继续保持断点行为，不能无提示退回自动运行。参数命名和最少的保存方式由实现结合现有代码确定，不为此引入独立模式管理系统。
- 继续执行当前探针，再由专家吸收结果并决定下一步。若产生新探针则停下；若研究完成、专题阻塞或预算耗尽则返回对应状态。沿用现有收尾消化回合与预算规则。
- 调整只作用于当前未执行探针。专家接收当前提案、用户方向意见和必要的既有目标、认知状态及结果上下文；避免将同一观测重复计入认知状态。提交后的修改仍属于当前轮次，不运行 Executor。
- 重拟复用已有提交与恢复机制；失败不能用半成品替换正式提案或触发执行。保留必要的反馈和诊断材料，不建设聊天记录或提案版本系统。
- CLI 与 HTTP 接口调用同一核心控制逻辑。提供读取当前待执行探针及必要上下文、继续、提交方向意见的能力；接口直接使用权威材料，不另存假设副本。
- 工作台主屏展示当前假设与依据、探针设计和继续/调整操作；上轮结果、判据及成本影响在已有材料提供时展示，不新增评分或摘要生成流程。完整认知状态、历史及日志按需展开，移除重复入口。
- 诊断展示以实际输入材料、原始输出与错误为依据，不推测模型隐藏思维过程，不自动生成归因结论。只补闭环必需的材料可见性，不建立全量输入快照系统。
- 查看与刷新保持只读；复用现有控制开关、工程锁和错误处理。必要的重复操作约束在已有控制边界处理，不增加并发审批体系。
- 用户方向意见限定于当前探针；修改专题目标继续使用既有讨论入口。默认自动运行和既有单次角色调用语义保持不变。

## Testing Decisions

用户已确认测试边界：以已部署 CLI 与现有 HTTP 控制接口为主要入口，补一条真实浏览器链路。不新增内部测试接口。

- 复用现有专题 CLI、轮次调度和工作台控制测试方式，使用可控 Worker 子进程提供确定的探针和结果。验证外部行为及产物，不断言内部函数调用顺序，不要求真实大模型输出一致。
- 经 CLI 验证：启用调试后已有探针而无执行结果；继续恰好完成当前轮次并停在下一探针；重拟确实收到当前提案与方向意见，修改后无执行结果、轮数与预算不增加。
- 经 HTTP 验证：当前探针和必要上下文可读，继续与调整与 CLI 行为一致；读取不触发执行。复用现有控制冲突与错误测试，避免为假设性风险建立新测试体系。
- 覆盖重拟失败时正式提案保留且不自动执行；完成、阻塞、预算耗尽及收尾仍按原有规则处理；默认自动运行可正常结束。
- 经真实浏览器与后端完成“查看断点 → 提交意见 → 查看重拟 → 继续 → 下一断点”，确认刷新不推进、诊断材料可展开。复用现有浏览器验证设施。
- 实现后运行相关测试、前端类型检查与构建，并完成必要回归；真实模型专题可用于人工观察假设质量，不作为确定性测试通过条件。

## Out of Scope

- 任意位置或角色级断点、通用调试器。
- 独立审批状态机、提案版本历史、聊天系统、第二份认知或假设账本。
- 并发审阅产品、自动归因或方案评分系统。
- 工作台重建及与当前调试闭环无关的展示改造。
- 通过局部方向反馈更改专题目标。
