# 固定断点调试的最小范围

Type: grilling
Labels: wayfinder:grilling
Status: resolved

## Question

如何用最少的改动，让用户逐步检查自动探索中的假设和探针设计，并通过方向反馈验证专家能否合理调整？

## Answer

用户确认原有逐轮控制闭环，并进一步明确：用途是检查自动框架每一步是否有缺陷、定位不合理假设的来源；只需类似断点的轻量调试模式。

- 自动流程增加可选调试方式；固定在专家成功提交探针后、执行探针前停下。复用现有材料结束本次调用，不用 stop 模拟等待，不要求后台进程常驻。
- 继续：执行当前探针，专家吸收结果并提出下一探针后再次停下。完成、阻塞和预算耗尽沿用现有处理。
- 调整：用户给当前探针的方向意见，专家结合现有上下文及当前探针重拟，然后再次停下；不执行实验、不新增探索轮次。更换专题目标仍走已有讨论入口。
- CLI 与可视化使用相同核心操作。接口单独提供当前探针及必要上下文；不另建一套假设存储。
- 工作台突出当前假设、依据、设计和继续/调整操作；其余内容按需展开，删除重复入口。为诊断不合理假设，保留查看专家实际输入材料、原始输出及错误日志的能力，不增加模型思维过程推断或自动归因系统。
- 不建设审批状态机、版本历史或并发审阅体系。操作仍复用工程锁和现有失败处理；必要的正确性约束在实现中处理，不扩展成独立产品设计。

实现命名与最少的数据保存方式由现有代码决定，不再单独拆成决策事项。验证重点是断点前不会执行、继续到下一断点、反馈确实进入专家输入且重拟后不执行，以及自动模式与原有失败处理未被破坏。

## Comments

用户先确认固定探针边界、局部方向反馈和精简现有工作台，随后要求将整个功能收缩为排查自动框架问题的断点调试选项。本答案以该最新约束为准，合并原反馈与界面事项。
