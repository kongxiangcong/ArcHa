# 02: 在 CLI 与工作台使用探针断点和继续

**What to build:** 用户可在 CLI 与浏览器工作台启用探针断点调试，查看专家生成的假设与探针设计，选择继续后执行当前探针并停在下一探针。浏览器操作必须通过真实后端驱动执行，不能只保留按钮或模拟状态。

**Blocked by:** None (can start immediately)。

**Status:** resolved

依据：[探针断点调试规格](../spec.md)。沿用既有执行生命周期、工程锁和提交机制，不建立审批系统。

- [x] CLI 和工作台均提供明确的调试入口；调试中的继续保持断点行为，不无提示转回自动运行。
- [x] 专家成功提交探针后、Executor 派发前结束本次调用并释放锁；正常等待不调用 stop，不产生中断错误，也不保留后台等待进程。
- [x] 接口提供当前探针与必要上下文。工作台突出当前假设、依据、设计和继续操作；可展开相关输入材料、原始输出和错误日志，移除重复入口，不增加摘要生成或全量快照系统。
- [x] 继续执行当前探针，专家吸收结果后若生成新探针则再次停下；完成、阻塞、预算耗尽和收尾消化回合沿用既有规则。
- [x] 浏览器按钮连接实际 HTTP 控制接口，接口调用与 CLI 相同的核心逻辑；页面区分请求处理中、实际运行、断点等待及失败，失败如实显示。
- [x] 查看与刷新保持只读。复用现有控制开关、锁及必要的重复操作约束；默认自动运行和既有单次角色调用语义不变。
- [x] 使用可控 Worker，经已部署 CLI 与 HTTP 验证断点前无执行结果、继续到下一断点，以及原有终止与自动运行行为；不新增内部测试接口。
- [x] 经真实浏览器、后端和 Worker 子进程完成“启用调试 → 查看探针 → 继续 → 下一断点”，确认刷新不推进且诊断材料可读；前端类型检查、构建及相关回归通过。
