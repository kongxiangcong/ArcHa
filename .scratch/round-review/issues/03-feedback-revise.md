# 03: 提交方向意见并由专家重拟探针

**What to build:** 用户在 CLI 或浏览器断点处提交方向意见，专家结合当前探针自行修改设计，提交后再次停下。用户无需给出具体方案，可查看修改并继续执行。

**Blocked by:** 02：[在 CLI 与工作台使用探针断点和继续](02-breakpoint-continue.md)。依赖其可用的断点、提案读取及继续闭环。

**Status:** resolved

依据：[探针断点调试规格](../spec.md)。复用当前探针及认知状态，不建设聊天系统、提案版本历史或新的审批状态机。

- [x] CLI 和工作台均可对当前未执行探针提交方向意见；浏览器反馈输入与提交操作连接真实 HTTP 接口及核心重拟逻辑。
- [x] 专家实际收到当前提案、用户意见和必要的目标、认知状态及结果上下文；避免重复计入已吸收观测，不将局部反馈用于隐式更改专题目标。
- [x] 专家负责形成具体设计，成功提交后再次停在当前轮次；不执行实验，不增加探索轮数或预算。用户可再次反馈，或通过已有继续操作执行修改后的探针。
- [x] 重拟沿用已有提交与恢复机制；失败保留正式提案、暴露错误，不以半成品替换提案或自动执行。只保留闭环与诊断必需的反馈材料。
- [x] 工作台实际展示修改后的探针及调整中的状态，错误可见，必要诊断材料可读；查看与刷新不推进任务。
- [x] 使用可控 Worker，通过已部署 CLI 与 HTTP 验证反馈及当前提案进入专家输入、重拟后无执行结果、轮数与预算不增加，以及重拟失败保留正式提案。
- [x] 经真实浏览器、后端和 Worker 子进程走通“查看断点 → 提交意见 → 查看重拟 → 继续 → 下一断点”，验证执行使用修改后的探针；前端类型检查、构建及相关回归通过。

## Answer

CLI `revise --feedback` 与 HTTP `revise` 共用引擎重拟控制。Expert 接收当前探针、方向意见、目标、认知状态及上一轮结果，并明确不重复吸收已计入观测、不改变目标；沿用 staged Expert 提交与恢复，保持当前轮次、预算及 IN_PROGRESS，失败保留正式探针。每轮仅保留最近一次 feedback.md 与重拟日志，工作台提供方向输入、调整活动、更新后探针及诊断材料。

验证：先经 CLI 缺少命令、HTTP 缺少路由、浏览器缺少方向输入得到红测，再逐条实现。部署 CLI 和 HTTP 可控 Worker 验证输入、无实验结果、轮次/预算不增加与失败提案保留。真实 Chromium + HTTP + Worker 走通提交意见、查看调整、读取反馈、继续使用修改后探针并到下一断点。`pytest opc/tests -q` 为 89 passed、2 skipped；执行角色简化后补跑 CLI 重拟、HTTP/生命周期 11 项及完整浏览器均通过。前端 typecheck（build 内）及生产构建通过。唯一警告为现有 Starlette/AnyIO 弃用提示；未以真实模型质量作为确定性验收。
