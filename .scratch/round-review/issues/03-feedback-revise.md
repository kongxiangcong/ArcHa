# 03: 提交方向意见并由专家重拟探针

**What to build:** 用户在 CLI 或浏览器断点处提交方向意见，专家结合当前探针自行修改设计，提交后再次停下。用户无需给出具体方案，可查看修改并继续执行。

**Blocked by:** 02：[在 CLI 与工作台使用探针断点和继续](02-breakpoint-continue.md)。依赖其可用的断点、提案读取及继续闭环。

**Status:** ready-for-agent

依据：[探针断点调试规格](../spec.md)。复用当前探针及认知状态，不建设聊天系统、提案版本历史或新的审批状态机。

- [ ] CLI 和工作台均可对当前未执行探针提交方向意见；浏览器反馈输入与提交操作连接真实 HTTP 接口及核心重拟逻辑。
- [ ] 专家实际收到当前提案、用户意见和必要的目标、认知状态及结果上下文；避免重复计入已吸收观测，不将局部反馈用于隐式更改专题目标。
- [ ] 专家负责形成具体设计，成功提交后再次停在当前轮次；不执行实验，不增加探索轮数或预算。用户可再次反馈，或通过已有继续操作执行修改后的探针。
- [ ] 重拟沿用已有提交与恢复机制；失败保留正式提案、暴露错误，不以半成品替换提案或自动执行。只保留闭环与诊断必需的反馈材料。
- [ ] 工作台实际展示修改后的探针及调整中的状态，错误可见，必要诊断材料可读；查看与刷新不推进任务。
- [ ] 使用可控 Worker，通过已部署 CLI 与 HTTP 验证反馈及当前提案进入专家输入、重拟后无执行结果、轮数与预算不增加，以及重拟失败保留正式提案。
- [ ] 经真实浏览器、后端和 Worker 子进程走通“查看断点 → 提交意见 → 查看重拟 → 继续 → 下一断点”，验证执行使用修改后的探针；前端类型检查、构建及相关回归通过。

## Comments

用户已确认本项依赖断点与继续闭环。测试边界沿用规格中已确认的 CLI、HTTP 和真实浏览器链路，不依赖大模型输出一致，不以按钮占位或模拟成功代替集成验证。
