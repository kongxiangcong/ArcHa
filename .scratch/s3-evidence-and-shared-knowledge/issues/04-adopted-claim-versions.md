# 04: 采用版本的声明与交接

**What to build:** 工作安排和实际结果明确记录采用了哪条主张的哪个版本，用户能够追溯判断依据，材料被读取本身不构成采用。

**Blocked by:** 03 — 按问题查询与授权展开。

**Status:** resolved

依据：[S3 规格](../spec.md)。本项登记并读取采用引用；依据修订后的再判断由事项 05 完成。

- [x] Expert 在已有工作安排中显式声明依赖的主张版本，Engine 检查身份、版本与授权并保留到实际工作交接。
- [x] Designer 在已有结果回传中补充执行时另行采用的主张版本，保存为实际依据，不覆盖最初派发上下文，不增加单独报告。
- [x] 材料被传入或通过工具读取但没有采用声明时，不自动生成采用引用，也不声称理解正确。
- [x] 历史工作、结果及只读观察能定位实际采用版本并展开对应依据；重复恢复不重复登记同一采用声明。
- [x] 无主张采用的工作仍按既有流程运行；无效版本、身份或越权引用被明确拒绝，不静默改为当前版本。
- [x] 通过 Engine 与脚本化 Worker 验证查询后显式采用、仅阅读未采用、Designer 补充引用以及恢复后的引用可追溯；测试观察实际交接和结果。


## Answer

工作计划使用 `adopted_claims: [{task_id, claim_id, version}]` 显式声明采用；Engine 在 Expert 决策生效前检查身份、精确版本及授权，允许引用同份决策将登记的版本。Designer 的新增采用保存在原有 execution 回复，与原派发计划、固定交接上下文分别保留；没有声明的读取不产生采用。实际依据的合并投影进入后续 Expert 历史、已有报告及只读观察出口；Call 身份防止恢复重复登记同一回复。非法 Designer 采用保留原回复及真实错误，但不登记无效引用。

Codex/DSH 原有 Designer 入口共同解析结构化观察 JSON（summary、adopted_claims 及事项 06 使用的 evidence_files）；普通无采用摘要仍有效，尝试提交的非法 JSON 明确报错。保持既有调用方式，不新增报告或独立权威状态。

验证：新增 Engine 采用/恢复/只读观察及非法引用等 8 项通过；实际假 Codex/DSH CLI 的结构化回复 2 项通过。研究循环、Codex、DSH、DAG 组合首次 173 passed、1 failed（既有 DSH 提示词要求带引号的 exhausted，被前序提示词压缩遗漏）；恢复原约定后原失败用例通过，适配器结构化回复同次复验共 3 passed。采用及上下文边界复验 8 passed；新增失败 Call 非法引用分支后采用复验 8 passed。Expert 提示词保持 2597 字符，小于既有 2600 限制；`git diff --check` 通过。未调用真实 Worker/API，未开展正式研究考试。
