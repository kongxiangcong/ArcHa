# 06: 必要原件保留与缺失后补证

**What to build:** 主张引用的必要原件能够跨工作区清理及代码回退取回；原件缺失时暴露真实缺口，通过已有工作流程补证并更新当前依据，保留历史事实。

**Blocked by:** 02 — 主张修订、冲突重判与恢复；03 — 按问题查询与授权展开。

**Status:** ready-for-agent

依据：[S3 规格](../spec.md)。

- [ ] 仅存在临时工作区且被主张引用的必要原件，在清理前进入既有持久成果位置；已有可靠原件直接引用，原生数据与必要 trace 不因候选淘汰或回退丢失。
- [ ] 查询及读取显示具体缺失或访问失败，保留原引用和历史判断；缺失本身不自动反驳主张，不静默改指新文件，不将未展开标为已读取。
- [ ] Expert 能按当前用途在既有任务、权限和预算内选择必要补证；历史解释可带限制作为线索，必须核对原件的判断或验收在缺口未补前不能宣称完成，独立工作可继续。
- [ ] 补证沿已有工作流程产生新观测，Expert 判断其维持、推翻或仍无法确定原主张，再修订当前依据并关联旧引用及补证原因；旧缺口保留，新测量不能冒充指定历史执行。
- [ ] 外部资料失链可正常重新调研，但不增加外部材料归档、版本或读取时间管理；文献不能冒充本次测量。
- [ ] 检查集中在登记、实际读取与必要交付边界，不引入自动清理、全库扫描、额外哈希、工作区镜像或重复原件。
- [ ] 用既有 Engine 与成果读取夹具验证临时原件保留、既有原件无重复复制、清理或回退后可读、缺失后补证及历史保留；从实际后续上下文和只读入口确认新旧依据可辨。
