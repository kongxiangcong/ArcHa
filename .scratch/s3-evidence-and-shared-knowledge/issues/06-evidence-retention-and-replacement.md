# 06: 必要原件保留与缺失后补证

**What to build:** 主张引用的必要原件能够跨工作区清理及代码回退取回；原件缺失时暴露真实缺口，通过已有工作流程补证并更新当前依据，保留历史事实。

**Blocked by:** 02 — 主张修订、冲突重判与恢复；03 — 按问题查询与授权展开。

**Status:** resolved

依据：[S3 规格](../spec.md)。

- [x] 仅存在临时工作区且被主张引用的必要原件，在清理前进入既有持久成果位置；已有可靠原件直接引用，原生数据与必要 trace 不因候选淘汰或回退丢失。
- [x] 查询及读取显示具体缺失或访问失败，保留原引用和历史判断；缺失本身不自动反驳主张，不静默改指新文件，不将未展开标为已读取。
- [x] Expert 能按当前用途在既有任务、权限和预算内选择必要补证；历史解释可带限制作为线索，必须核对原件的判断或验收在缺口未补前不能宣称完成，独立工作可继续。
