# 07: 跨 Run 复用与完整闭环验收

**What to build:** 后续 Run 在明确条件与权限下查询、判断并采用历史主张，完整演示新证据如何改变后续工作，形成可核对的 S3 交付结果。

**Blocked by:** 05 — 依据修订后的工作再判断；06 — 必要原件保留与缺失后补证。

**Status:** ready-for-agent

依据：[S3 规格](../spec.md)。本项交付跨 Run 的实际复用行为，并复用前序测试完成闭环，不把各项测试统一推迟到此。

- [ ] 同一 Task 的后续 Run 可以查询历史主张及原件，看到当前判断、条件、修订与待分析提示，并显式引用实际采用版本；新 Run 的执行历史不冒充旧 Run 的执行。
- [ ] Expert 按当前用途判断代码、输入、工具及测量条件的变化，明确适用时直接复用，有具体疑点才补查；换 Run 不无条件重测，旧观测不标为新实测。
- [ ] 跨 Task 复用只允许明确成果依赖及授权；演示授权材料可读、未授权材料被拒绝，不自动搜索所有项目或推广为通用经验。
- [ ] 用同一连续案例贯通宽泛主张未定、长字段限定主张受支持、短字段反例待分析、有效反例修订宽泛主张及后续 Run 改变选择；观察实际采用版本、派发条件及结果，不只检查记录存在。
- [ ] 复用关键分支验证受干扰测量不直接构成反证、反馈已分析仍可未定；旧原件、旧判断和实际发生的审核仍可追溯，读取缺口与待处理反馈明确可见。
- [ ] 只读观察出口与实际交接、查询及持久记录一致，不触发执行或维护第二份状态；不以字段齐全或读取记录证明模型理解正确。
- [ ] 运行受改动影响的测试及必要框架回归，复用前序恢复、冲突、权限与原件案例；必要时补一个真实轻量 Worker 案例，记录实际后端、条件、产物、结果及未验证范围，不开展正式研究考试。
- [ ] 交付证据沿既有成果与阶段入口组织，避免重复报告；只声明实际通过的验收范围，不以脚本化 Worker 案例证明研究判断正确。
