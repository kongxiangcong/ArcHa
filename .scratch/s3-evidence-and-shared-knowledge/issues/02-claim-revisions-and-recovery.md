# 02: 主张修订、冲突重判与恢复

**What to build:** Expert 能根据新证据修订同一主张，或为实质不同的命题另立主张；历史依据可追溯，过时建议不能部分生效或在恢复时重复登记。

**Blocked by:** 01 — 主张登记与反馈分析贯通。

**Status:** resolved

依据：[S3 规格](../spec.md)。

- [x] 同一主张的证据、判断和理由变化形成可引用修订，保留旧版本及原因；改变命题或实质适用范围另立主张并关联，不把宽泛主张直接改写为限定主张，不以文本哈希判定语义。
- [x] 当前交接、身份读取与只读观察可见新判断、修订原因及历史入口；被替代以关系表达，三态与反馈处理、来源可用性、审核保持独立。
- [x] 修订指明依据版本，版本检查与持久登记在既有单写入及事务边界内完成；任一修订冲突使同份决策的反馈确认、其他修订和下一步选择全部暂不生效。
- [x] 冲突后反馈仍待处理，原工作结果及回复保留；Expert 获得冲突和最新材料重新判断，不能重放旧上下文冒充重判，也不重跑原工作。调用仍遵守预算、暂停和停止约束。
- [x] 已保存回复与已生效决策可辨；在登记后、工作创建前后中断，恢复复用已登记决策，不重复生成修订、工作、调用或费用记录。
- [x] 实际存在的审核保持绑定原对象、版本与范围，新修订不继承通过意见，旧审核不被改写为失败；日常修订不制造审核记录或新调用。
- [x] 通过 Engine 集成案例验证宽泛主张被反驳但限定主张仍有支持；加入一份同时含冲突修订、合法修订、反馈分析及工作选择的回复，核对整体拒绝及重判后的可观察结果；复用既有恢复和审核案例。


## Answer

沿用 `claim_registered` 事件记录可引用修订；Expert 以 `base_version` 声明依据，语义身份由 Expert 判断，程序不以文本相等判断同一命题。当前读取支持指定版本和完整历史，反馈分析、三态与独立审核各自保存。

`record_decision` 在既有事务内检查全部版本并按 Call 身份幂等登记。任一冲突使反馈确认、其他修订及工作选择全部不生效；保留原回复和工作原件，通过 `expert_conflict` 将冲突身份与最新主张交回下一次 Expert 调用，并沿用预算及控制检查。恢复已生效决策不会重复修订、调用或派发。已有成果审核接收并保存实际主张版本，未配置 Markdown 成果入口的任务也保留该审核范围；后续修订不会继承或改写旧审核。

验证：新增 Engine/成果边界案例覆盖宽泛主张被反驳但限定主张仍受支持、同份混合冲突决策整体拒绝后重判、工作创建前后中断恢复、编辑性措辞及修订依据检查、跨 Run 修订后旧审核仍绑定原版本。受影响研究循环、DAG、成果、Codex 配置及计量恢复回归首次 177 passed，唯一失败为提示词长度；压缩重复措辞后原长度边界与主张相关复验 19 passed，完整成果回归 16 passed，`git diff --check` 通过。保留一个既有 Starlette 弃用告警，未运行真实 Worker/API 或正式研究考试。
