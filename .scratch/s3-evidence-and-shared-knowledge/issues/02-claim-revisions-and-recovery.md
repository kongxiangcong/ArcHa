# 02: 主张修订、冲突重判与恢复

**What to build:** Expert 能根据新证据修订同一主张，或为实质不同的命题另立主张；历史依据可追溯，过时建议不能部分生效或在恢复时重复登记。

**Blocked by:** 01 — 主张登记与反馈分析贯通。

**Status:** ready-for-agent

依据：[S3 规格](../spec.md)。

- [ ] 同一主张的证据、判断和理由变化形成可引用修订，保留旧版本及原因；改变命题或实质适用范围另立主张并关联，不把宽泛主张直接改写为限定主张，不以文本哈希判定语义。
- [ ] 当前交接、身份读取与只读观察可见新判断、修订原因及历史入口；被替代以关系表达，三态与反馈处理、来源可用性、审核保持独立。
- [ ] 修订指明依据版本，版本检查与持久登记在既有单写入及事务边界内完成；任一修订冲突使同份决策的反馈确认、其他修订和下一步选择全部暂不生效。
- [ ] 冲突后反馈仍待处理，原工作结果及回复保留；Expert 获得冲突和最新材料重新判断，不能重放旧上下文冒充重判，也不重跑原工作。调用仍遵守预算、暂停和停止约束。
- [ ] 已保存回复与已生效决策可辨；在登记后、工作创建前后中断，恢复复用已登记决策，不重复生成修订、工作、调用或费用记录。
- [ ] 实际存在的审核保持绑定原对象、版本与范围，新修订不继承通过意见，旧审核不被改写为失败；日常修订不制造审核记录或新调用。
- [ ] 通过 Engine 集成案例验证宽泛主张被反驳但限定主张仍有支持；加入一份同时含冲突修订、合法修订、反馈分析及工作选择的回复，核对整体拒绝及重判后的可观察结果；复用既有恢复和审核案例。
