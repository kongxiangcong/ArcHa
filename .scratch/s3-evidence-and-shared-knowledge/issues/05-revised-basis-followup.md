# 05: 依据修订后的工作再判断

**What to build:** 已安排工作或待复用成果的直接依据发生修订时，Expert 在后续使用前决定继续、调整或补证，在途工作与历史记录保持原义。

**Blocked by:** 02 — 主张修订、冲突重判与恢复；04 — 采用版本的声明与交接。

**Status:** claimed

依据：[S3 规格](../spec.md)。

- [ ] 相关工作再次派发或成果再次被使用时，按已登记的直接采用引用发现依据修订，并将新旧版本变化交给 Expert 判断；未知影响不能默认仍适用。
- [ ] 受影响的新派发先完成继续、调整或补证判断；明确继续使用旧版本时记录范围及理由，并使实际交接与所选依据一致。
- [ ] 在途 Call 保留原输入，主张更新不自动取消或热替换上下文；返回后 Expert 结合变化解释结果。
- [ ] 历史工作、旧采用引用及成果保持不变，不自动将下游主张改为 `refuted`；未登记的语义依赖不宣称已覆盖，不新增通知服务或全局依赖图。
- [ ] 变化及处理理由经既有决策、交接和只读观察路径可追溯，不建立独立重审状态账本；不因一条依据变化冻结全部无关工作。
- [ ] 集成案例覆盖已计划工作遇到依据变化、确认沿用旧版本、调整工作以及执行中发生修订；断言真正派发的输入与后续选择，而非只检查通知存在。
