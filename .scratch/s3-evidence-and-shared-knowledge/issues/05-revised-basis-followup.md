# 05: 依据修订后的工作再判断

**What to build:** 已安排工作或待复用成果的直接依据发生修订时，Expert 在后续使用前决定继续、调整或补证，在途工作与历史记录保持原义。

**Blocked by:** 02 — 主张修订、冲突重判与恢复；04 — 采用版本的声明与交接。

**Status:** resolved

依据：[S3 规格](../spec.md)。

- [x] 相关工作再次派发或成果再次被使用时，按已登记的直接采用引用发现依据修订，并将新旧版本变化交给 Expert 判断；未知影响不能默认仍适用。
- [x] 受影响的新派发先完成继续、调整或补证判断；明确继续使用旧版本时记录范围及理由，并使实际交接与所选依据一致。
- [x] 在途 Call 保留原输入，主张更新不自动取消或热替换上下文；返回后 Expert 结合变化解释结果。
- [x] 历史工作、旧采用引用及成果保持不变，不自动将下游主张改为 `refuted`；未登记的语义依赖不宣称已覆盖，不新增通知服务或全局依赖图。
- [x] 变化及处理理由经既有决策、交接和只读观察路径可追溯，不建立独立重审状态账本；不因一条依据变化冻结全部无关工作。
- [x] 集成案例覆盖已计划工作遇到依据变化、确认沿用旧版本、调整工作以及执行中发生修订；断言真正派发的输入与后续选择，而非只检查通知存在。

## Answer

复用既有 Expert 决策和 SQLite 事件事务：派发前核对工作显式采用、明确成果依赖及 `base_attempt` 原成果的直接采用版本。仅有变化的未派发工作进入 `basis_review`；Expert 回传观察到的版本、继续/调整/补证、范围及理由，版本再次变化时整份回复冲突回滚并用新材料重判。继续保留旧引用，调整通过 `work_reconsidered` 投影有效计划并采用实际所选代码父版本；初始计划、旧工作、Call 输入和回复保留。补证沿普通工作派发，无关就绪工作可先继续。

已开始的 Call 按原输入返回，后续 Expert 的 `basis_changes` 展示直接依据变化；不会自动取消或改写在途输入。已完成的基础设施失败需要新 Call 时重新检查，发生再判断的重试保存独立调用材料；继续沿用原局部工作区，调整使用所选版本的新工作区，保留原始输入与回复。观察出口展示同一再判断事件及原计划。未声明的语义关系不推断为依赖。
