# S2：Attempt、Worker 交接与恢复

**Status:** ready-for-agent

## Problem Statement

用户需要在同一 Run 内持续开展多轮工作，确保专家选定的工作有明确输入、执行结果能反馈给专家，中断后能辨认已完成、未完成和未知执行，避免重复工作、遗漏反馈或重复记账。

当前实现偏向串行代码候选流程：先创建 Attempt 再调用 Expert，默认每次角色调用使用新会话，中断工作通常直接 abandoned。现有两个 CLI 适配器和配置冻结不足以证明会话续接、主动取消、环境后端选择及并行交接已经可靠。

用户要求支持 Codex CLI 与 DSH CLI，通过执行环境配置明确选择；同时保持实现轻量，不增加管理 Agent、内部可执行子图或通用编排服务。

## Solution

每个 Run 保持独立的逻辑 Expert 上下文，专家解释已有结果并选择下一项或多项工作。Engine 为选定工作创建 Attempt，维护增量 DAG，按成果依赖、权限、预算和资源条件派发；默认最多三个 Attempt 并行，上限可配置。

工作派发、结果返回和专家接收复用同一套持久记录。恢复只补尚未完成的交接；暂停在当前调用边界收住，停止取消在途执行。两个 CLI 采用相同的工作与控制语义，后端差异由适配器处理。

## User Stories

1. 作为用户，我希望 Run 始终引用明确的执行 revision，以便新草稿或环境默认值不改变历史工作。
2. 作为用户，我希望每个 Run 有独立的专家上下文，以免不同运行的材料混杂。
3. 作为用户，我希望专家持续解释结果并选择后续工作，以免仅在开始时规划而无人推进研究。
4. 作为用户，我希望只有选定工作才创建 Attempt，以免复盘、停止决定或未选备选制造空节点。
5. 作为用户，我希望一次工作能修改代码、只做新测量或分析已有证据，以免被迫制造补丁或填写无意义假设。
6. 作为用户，我希望 Designer 在授权范围内自主调试和调整实现，以免每个工具步骤都需要外层派发。
7. 作为 Worker，我希望收到明确目的、固定起点、前置成果及交付要求，以便执行正确的工作。
8. 作为用户，我希望工作返回实际操作、产物、检查和偏差，以便辨认计划与执行的差别。
9. 作为 Expert，我希望按需读取结果详情和原件，以便判断有证据依据且上下文不无限增长。
10. 作为用户，我希望 Engine 保留未处理反馈，以免专家调用失败、漏读或控制器重启导致结果丢失。
11. 作为用户，我希望专家一次可以解释多份结果并安排补查，以免每个节点都需要额外审核调用。
12. 作为用户，我希望最后一轮结果也有解释或明确待分析状态，以免没有下一轮时遗漏反馈。
13. 作为用户，我希望 DAG 按所需成果可用性放行，以免把上游结束或假设成立误当输入就绪。
14. 作为用户，我希望独立工作使用固定输入和独立工作区并行执行，以免相互覆盖或读取漂移中的起点。
15. 作为用户，我希望默认并发上限为三且可配置，以便控制机器资源和执行成本。
16. 作为用户，我希望正式计时避开其他受控工作的资源争用，以便测量仍可比较。
17. 作为用户，我希望多分支代码只在明确选定整合工作后合并，以免系统擅自组合候选。
18. 作为用户，我希望已有可靠结果在恢复时被复用，以免重新实施、重测或重复扣费。
19. 作为用户，我希望未知执行先核实再决定后续，以免缺回执被误认为没有执行。
20. 作为用户，我希望补完原工作沿用 Attempt、重新派发使用新 Call，以便区分重试与新研究工作。
21. 作为用户，我希望根据结果另选的工作创建新 Attempt，以便保留每轮工作的原始目的和输入。
22. 作为用户，我希望新测量与缓存引用明确区分，以免旧结果冒充独立实测。
23. 作为用户，我希望 Call 与后端会话分别标识，以便续接会话时仍能追踪每次派发和用量。
24. 作为用户，我希望专家会话不可续接时能从持久材料重建，以免会话丢失导致整个 Run 重做。
25. 作为用户，我希望暂停后不再派发新工作、当前调用可收尾，以便保留成果并继续原 Run。
26. 作为用户，我希望停止能取消在途执行且保存已发生事实，以免后台继续消耗或半成品被标成成功。
27. 作为用户，我希望控制状态区分请求已收到和执行已停止，以免未知进程被错误展示为已结束。
28. 作为用户，我希望通过环境配置选择 Codex CLI 或 DSH CLI，以便使用明确指定的工具与安装。
29. 作为用户，我希望合同未限制后端时可在同一 revision 的新 Run 中换 CLI，以免仅换工具就必须重写合同。
30. 作为用户，我希望旧 Run 恢复保持原配置，以免环境修改暗中替换后端或模型。
31. 作为用户，我希望明确切换 CLI 后的新 Run 执行额度从零扣减，同时保留历史用量，以便重新分配投入且仍能追溯成本。
32. 作为用户，我希望普通暂停、重启和失败重试不重置额度，以免恢复改变预算含义。
33. 作为用户，我希望并行时间按各次执行耗时累加，以便预算与实际投入保持一致。
34. 作为用户，我希望 Codex 通过真实轻量交接、控制和恢复验证，DSH 在缺少安装与登录的当前阶段先交付实现并明确未验证范围，以便不因环境缺失阻塞适配开发，也不虚报验证结果。
35. 作为用户，我希望观察入口能关联节点、Call、实际上下文、结果和错误，以便定位失败而无需阅读全部 trace。
36. 作为用户，我希望权限、计量未知和后端不支持的能力被如实报告，以免静默回退、虚报成功或绕过执行边界。

## Implementation Decisions

- 复用现有 Engine、账本、配置解析、Worker 适配器、工作区、进程管理、评价和观察接口。单个 Engine 维护项目级单写入事实；并行 Worker 返回结果，由 Engine 统一登记，不并发调用整条现有串行 Attempt 流程。
- 延续 S1 的 revision 准备、首次绑定冻结、Run 恢复兼容及 closed 不原地重开规则。创建 Run/Attempt、保存记录和程序评价本身不启动模型。Onboard 与终验调用归准备/交付范围，不强塞普通 Attempt。
- Expert 在 Run 层按需调用，解释已有结果并选择工作；同一 Run 的专家决策串行，逻辑上下文连续但 CLI 无需空闲常驻。Designer 默认使用具体工作的独立上下文。局部阅读、工具操作和调试不另拆 ArcHa Call 或 Attempt。
- 选定工作后才创建 Attempt。修改代码、制作产物、独立测量和独立分析均可表达；纯测量不强制 Designer，分析不强制补丁或正式评价。正常复盘、规划和停止决定留在 Run 层。Reviewer 按需，Evaluator 可为程序。
- 派发记录关联工作目的、固定代码/输入版本、所需成果、权限及预期交付；返回关联实际操作、产物、检查、失败及偏差；专家决策引用已处理结果、判断和所选下一步。Engine 自动关联身份、版本、日志和实际用量，不让模型重复填写既有事实或复制整份契约。
- 派发前分配独立 ArcHa Call ID 并持久记录必要输入；后端 session/thread ID 单独保存。结果、用量和交接依据可重复核对而不重复登记或扣费；新调用的实际消耗仍需累计，不能与重复记账混淆。复用账本事务和已有原件，不为幂等关联额外计算内容哈希。
- 返回结果保留待处理反馈，Expert 明确引用结果并解释或安排补查。调用失败、遗漏、仅声明已读不能清除反馈；一个决策可覆盖多个结果。处理反馈不等于假设成立、问题解决或整体完成。需要新判断的后续工作等待该判断，已选且独立就绪节点可继续。
- 专家正常收尾时处理最后一轮结果；暂停、停止或预算退出允许保留明确待分析项，不为了补解释突破控制。决策已保存但后续节点未登记时，恢复核对并补齐，不重复生成工作。
- Engine 维护增量 Attempt DAG，检查成果引用和依赖、拒绝环，只派发输入就绪且权限、预算及资源允许的节点。未选备选不预建；已开始节点保留原输入与依赖，后续调整形成新工作。稳定身份与展示标题分离，标题可标方向及序号，依赖不从标题解析；一次工作可关联多个方向。
- 默认最多三个 Attempt 同时执行，并发上限可配置。节点使用独立工作区和固定输入，依赖满足不要求假设成立或候选被接纳。多分支结果不自动合并；整合需明确选定工作与必要验证。
- 正式性能测量在 Engine 管理的共享计算资源上排他，等待其他争用工作收尾后开始，期间不派发争用工作；不能仅串行评价器却让 Designer 同时争用。框架外主机负载不承诺受控，仍须遵守冻结评价条件。
- 恢复分别辨认已有可靠成果、缺失评价、未处理反馈及执行未知。成果已保存就补后续交接，不重做已确认完成的工作；派发无可靠终态时先查执行事实，不能盲目重发。无法确认则阻塞受影响执行与资源，保留未知及必要工作区，不盲删半成品或仍可能被写入的目录。
- 目的和固定输入不变、仅补未完成执行时沿用 Attempt，重新派发使用新 Call ID。Expert 根据结果另选方法、输入或目的开展后续工作时创建新 Attempt；原授权内局部调试不机械拆分。评价器启动失败后的同候选补测沿用 Attempt，专家选择的独立复测创建新 Attempt；每次实际测量分别记录，旧原件不覆盖。
- pause 在 Engine 观察到请求后停止所有新 Call/评价派发，包括专家反馈；允许在途调用在预算与超时范围内返回，保存结果后暂停。等待时显示仍有执行在途，不提前宣称已暂停；继续时恢复原 Run 并补缺失交接，不冻结进程内部状态。
- stop 阻止新派发，请求取消受控执行，有限等待后必要时终止进程树，保存已发生事实并关闭 Run。检测到明确预算耗尽走取消路径。取消与完成竞争时按可核对事实保存结果，控制请求仍阻止后续派发；无法确认终止时保留未知状态，不能当作已停止。停止收尾不发起研究或终验。
- 复用执行环境配置入口，统一解析准备、Expert、Designer、Reviewer 的实际后端及参数，保留角色间参数隔离。区分后端类型、可执行文件定位和模型/provider 等选项；参数按后端处理，不能只改模型名或将另一后端参数无条件继承。具体字段名与解析结构由实现决定，不新增配置系统。
- Codex CLI 与 DSH CLI 都是正式支持后端。启动前明确选择，不自动路由、不在失败时自动换后端、不热切换。新 Run 保存实际解析配置及来源，恢复复用原配置并核查必要兼容条件，不重新读取环境默认值暗换工具。
- 合同未明确限制 CLI 时，环境选择可在同一 revision 的新 Run 中生效；合同显式限制与本机选择冲突时报错，改变该限制需新 revision。旧 Run 不原地换后端；跨后端从持久材料重建，不承诺迁移原生会话。
- 同后端按能力用明确 session ID 续接 Expert，不猜最近会话；会话不可恢复时记录原因并从该 Run 持久材料重建。保持所需稳定材料入口、权限和工作目录约束。错误需区分会话不可续接、后端故障与请求已执行但终态未知，不能以材料重建掩盖未知执行并重发。
- 两个适配器统一结果、终态、错误、用量及控制语义，后端输出差异内部处理。计量缺失保持未知；沿 S1，仅对实际启用的预算约束要求可靠计量。中断时不承诺精确截断后端尚未上报的 token，也不把未知用量填零。
- **预算修订：** 用户明确切换 CLI 并创建新 Run 时，该新 Run 的时间及已配置 token 执行额度从零扣减，历史真实用量与证据仍保留。普通暂停、重启、失败重试不重置，仅新建 Run 不自动取得重置额度；独立项目总额硬限制仍遵守。无此明确切换时沿用 S1 预算规则，不清空账本。
- 默认额度仍为累计执行时长 7200 秒、token 无上限，既有显式限制有效。并行按每次调用/评价耗时相加，三个 Worker 各执行十分钟扣减三十分钟；暂停等待中的在途执行仍计时。区分历史用量与本次额度扣减起点，不新增平行预算账。
- 复用观察入口展示节点状态、依赖阻塞、待反馈、控制请求与在途执行、Call/session 关联、实际后端、用量及错误，详细上下文/输入输出/原件按需展开。trace 记录实际调用和对外理由，不要求内部思维全文；Expert 在授权内可按需读原件，移除阻碍必要证据核查的限制。
- Worker 文件读取与执行工具遵守实际任务访问边界，模型通信位于可信外层；并行工作区或设置 cwd 不替代隔离。复用既有隔离基础，分别实现两个 CLI 的工具接入；当前真实验证范围按下方 DSH 阶段例外执行。
- 历史 revision、Run、失败记录与原件保留，不批量重写；可读与可执行恢复分开判定，不承诺任意旧格式都可续接。改造在现有代码库进行，切片替代路径后清理已无用途的代码、配置和测试，避免双实现长期并存；仅保留有明确兼容职责的路径。

## Testing Decisions

- 主要测试边界沿已确认的准备 → Engine 启动/控制/恢复 → 账本与观察结果的公开行为，尽量通过同一贯通入口覆盖。复用临时项目、scripted/假 CLI 和小型评价器，不测试私有方法调用顺序或锁死表结构。
- 沿用 S1 的指定 revision、未就绪新草稿不影响旧 Run、冻结来源、关闭后不重开等回归；保留已有冠军引用收尾测试。原中断一律 abandoned 的断言需改为本规格的恢复行为，不能借兼容旧测试保留错误语义。
- 覆盖有补丁、无补丁新测量、仅分析三条路径及无需角色时跳过；核对实际起点、产物、失败分类、反馈处理与最后一轮收尾，不以 Worker 自报成功代替检查。
- 注入四类交接断点：派发后无可靠终态；结果落盘未完成记账；结果已存未反馈；决策已存后续工作未登记。重复恢复应不重复执行、派发或记账；已确认未启动、仍在途和无法判定分别保留真实状态。
- 覆盖同目的重试的新 Call、后续研究的新 Attempt、独立复测与缓存引用；会话丢失后的材料重建、Call/session 身份分离、未知计量与补齐也通过公开结果验证。
- 用受控长调用核对 pause 不启动后续评价/专家、stop 有限取消、预算退出、完成与取消竞争、在途状态未知时保留工作区；无需真实长时间等待。
- 用轻量多分支工作核对 DAG 拒环、缺成果阻塞、默认并发三及可配置上限、固定输入/独立工作区、失败分支不误阻塞独立工作、禁止隐式合并；计时排他需覆盖评价与其他计算工作的争用。
- 用可控用量验证并行耗时累加、普通恢复不重置、明确 CLI 切换新 Run 的额度重置及历史用量保留、项目硬限制继续生效。验证默认值修改不影响旧 Run、后端约束冲突、角色配置隔离，不实际消耗两小时预算。
- 对 Codex CLI 完成真实轻量任务：配置选择、可靠终态与用量、专家续接或有原因的材料重建、暂停/取消及跨进程恢复，并验证实际工具访问边界与并行工作区。记录真实版本和证据；假 CLI、帮助输出或源码阅读不能替代真实接入验证。
- **用户确认的 DSH 阶段例外：** 当前缺少安装与登录，先实现适配，不新增 DSH 专用测试，不安装、登录或执行真实 DSH 验证。已有相关回归不无故删除，公共引擎/配置/预算规则仍用既有可控边界验证。DSH 实现可在此范围内验收，不以其环境缺失阻塞本阶段交付，但须明确“已实现、未运行验证”，不得宣称双 CLI 均已实测通过；后续具备条件再补测试与验证。
- 观察端验证只读、请求与实际状态的区别、反馈和原件入口、实际后端及预算口径；不建立第二套执行逻辑。完成必要回归并清理本次无用途临时产物，只保留复现和验收所需证据。

## Out of Scope

- 正式四题考试及正式 DeepStack/Ramulator 研究；本阶段只做框架回归和轻量案例。
- 常驻专家进程、外层 Supervisor、自动生成 team config、router、总结 Worker 或强制逐轮 Reviewer。
- Attempt 内可执行子图、子 Attempt、任意工具节点编排、消息总线、分布式或多控制器调度。
- 运行中跨后端热切换、失败自动换 CLI、原生会话跨后端迁移、进程冻结或任意工具步骤级续跑。
- S3 的完整证据/知识导航、S4 的完整接纳与交付重设计、S5 的完整工作台；本阶段仅提供交接所需事实与最小观察。
