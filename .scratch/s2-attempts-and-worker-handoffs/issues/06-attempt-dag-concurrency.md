# 06: Attempt DAG 与最多三个工作的有界并行

**What to build:** 专家选定的多项工作按成果依赖逐步推进，独立就绪节点最多三个并行；失败、暂停和共享计时不会破坏输入、反馈或预算。

**Blocked by:** 05 — 双 CLI 会话恢复与切换后的预算重置（包含 03、04 的前置依赖）。

**Status:** ready-for-agent

**Spec:** [S2 实现规格](../spec.md)

- [ ] Engine 增量登记专家选定工作及成果依赖，校验引用并拒绝环，未选备选不预建；已开始工作保留原输入/依赖，调整产生后续节点。
- [ ] 稳定 ID 与标题分开，方向和序号用于展示，依赖不从标题解析；一个工作可关联多个方向，无子 Attempt 或内部可执行子图。
- [ ] 必要成果可用、权限/预算/资源允许才派发；节点结束、假设成立或候选接纳不能单独替代输入就绪，失败分支不无条件阻塞独立分支。
- [ ] 默认最多三个 Attempt 同时执行，上限可配置；同一 Run 专家决策串行。固定输入与独立工作区避免相互覆盖，不自动合并候选。
- [ ] 主 Engine 汇集结果并单写账本，不并发复用整条串行 Engine 流程中的可变状态；恢复与反馈延续已有 Call 身份和幂等收尾。
- [ ] 正式性能测量等待同一受控共享资源上的争用工作收尾后独占执行，期间不派发争用工作；不仅排斥其他评价器，也协调计算型 Designer。
- [ ] 并行结果按调用/评价累计耗时，暂停阻止后续节点、停止取消所有受控在途执行，未知执行仍阻塞受影响资源。
- [ ] 观察端可定位 DAG、就绪/缺成果/资源阻塞、反馈及在途状态，默认简明、原件按需读取，不新增完整工作台。
- [ ] 用轻量多分支夹具验证依赖、默认三并发与可配置上限、隔离输入、失败分支、计时排他及中断恢复；不启动 DSH 专用或真实测试。
- [ ] 保留项目级单控制器约束与必要串行回归，清理被替代调度路径，不引入通用调度框架。真实工具访问隔离与集成交付由 07 完成。
