# 06: Attempt DAG 与最多三个工作的有界并行

**What to build:** 专家选定的多项工作按成果依赖逐步推进，独立就绪节点最多三个并行；失败、暂停和共享计时不会破坏输入、反馈或预算。

**Blocked by:** 05 — 双 CLI 会话恢复与切换后的预算重置（包含 03、04 的前置依赖）。

**Status:** resolved

**Spec:** [S2 实现规格](../spec.md)

- [x] Engine 增量登记专家选定工作及成果依赖，校验引用并拒绝环，未选备选不预建；已开始工作保留原输入/依赖，调整产生后续节点。
- [x] 稳定 ID 与标题分开，方向和序号用于展示，依赖不从标题解析；一个工作可关联多个方向，无子 Attempt 或内部可执行子图。
- [x] 必要成果可用、权限/预算/资源允许才派发；节点结束、假设成立或候选接纳不能单独替代输入就绪，失败分支不无条件阻塞独立分支。
- [x] 默认最多三个 Attempt 同时执行，上限可配置；同一 Run 专家决策串行。固定输入与独立工作区避免相互覆盖，不自动合并候选。
- [x] 主 Engine 汇集结果并单写账本，不并发复用整条串行 Engine 流程中的可变状态；恢复与反馈延续已有 Call 身份和幂等收尾。
- [x] 正式性能测量等待同一受控共享资源上的争用工作收尾后独占执行，期间不派发争用工作；不仅排斥其他评价器，也协调计算型 Designer。
- [x] 并行结果按调用/评价累计耗时，暂停阻止后续节点、停止取消所有受控在途执行，未知执行仍阻塞受影响资源。
- [x] 观察端可定位 DAG、就绪/缺成果/资源阻塞、反馈及在途状态，默认简明、原件按需读取，不新增完整工作台。
- [x] 用轻量多分支夹具验证依赖、默认三并发与可配置上限、隔离输入、失败分支、计时排他及中断恢复；不启动 DSH 专用或真实测试。
- [x] 保留项目级单控制器约束与必要串行回归，清理被替代调度路径，不引入通用调度框架。真实工具访问隔离与集成交付由 07 完成。

## Answer

Expert 可一次选择 `works`，每项保留独立 `work_id`、标题、多个方向与成果依赖。批量登记原子、可恢复且幂等；拒绝未知引用和环。候选、可靠结果及实际保存的文件分别作为输入，未接纳候选不妨碍其消费者。声明的 editable/scratch 产物保存到本 Attempt 的 `outputs/`，不复制整棵工作树；`base_work_id` 显式选择一个前置候选，不自动合并分支。

默认三个并行 Attempt，沿既有 `.opc/local/workers.json` 的 `max_concurrency` 配置并在 Run 冻结。Engine 主线程推进 Attempt 阶段、登记 Call/结果与记账，线程只执行固定输入和原子回执；同步路径复用相同边界。正式评价等待全部受控 Designer 收尾，期间不派发争用工作。用量按 Call 累加，在途墙钟按各调用耗时求和；已完成待收回调用冻结终点，记账和移除活动计时保持一致。本次执行上限与任务尝试预算按节点预留，避免批量超发。

暂停收回所有在途回执并保留下一段，停止取消全部受控进程；主控制器异常取消同伴且不改用户控制意图。未知执行保留工作区并阻塞项目共享资源，普通新 Run 不能绕过。已失败分支不饿死上限之外的独立就绪节点。观察摘要/API 提供 DAG、稳定身份、依赖、缺失成果、资源等待及冻结并发上限。旧串行 Attempt 调度已替换，没有并发调用整条旧流程或 SQLite 写连接。
