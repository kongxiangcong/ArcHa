# 03: 贯通 Run 专家决策与 Attempt 反馈

**What to build:** 每个 Run 的专家持续解释结果并选定工作；执行结果可靠回流，既能实施代码，也能只测量或分析，不制造空 Attempt。

**Blocked by:** 02 — 持久化 Call 与结果，恢复不重复执行或记账。

**Status:** ready-for-agent

**Spec:** [S2 实现规格](../spec.md)

- [ ] Expert 决策归 Run，选定后创建 Attempt；复盘、停止或决策失败保存 Call 与用量，但不制造执行空轮。不同 Run 的逻辑专家上下文分离。
- [ ] 派发包含目的、固定起点、成果依赖和交付要求；返回包含实际操作、产物/检查、失败及偏差，身份和既有契约由 Engine 关联。
- [ ] 贯通代码/产物、纯测量和独立分析路径；无需 Designer 或正式评价时可跳过，不强制补丁、数值排名或竞争假设字段。
- [ ] Designer 在原授权内局部调试不拆 Attempt；补原工作沿用 Attempt、新派发使用新 Call；专家另选后续工作创建新 Attempt，新测量与缓存引用分别记录。
- [ ] 结果保存后保留待处理反馈，专家以具体结果引用给出判断或安排补查；空回复、仅已读、遗漏或调用失败不清除未处理项。
- [ ] 一次专家决策可汇集多份结果；正常收尾处理最后一轮，用户控制/预算退出保留待分析而不额外强制调用。解释不替代验收，待分析不伪装为完成。
- [ ] 建立稳定的 Run 材料入口，允许授权内按需查证原件；不复制完整 trace 进上下文，不增加总结 Worker 或强制逐轮审核。
- [ ] 恢复覆盖结果已存未反馈、决策已存后续工作未登记，避免重复专家处理或重复节点登记；观察端显示反馈及决策关联。
- [ ] 用小型贯通场景验证上述路径与失败反馈，保持串行执行可运行；清理旧的强制 Attempt 内 Expert 流程。原生 CLI 会话续接由 05 接入，DAG 调度由 06 扩展。
