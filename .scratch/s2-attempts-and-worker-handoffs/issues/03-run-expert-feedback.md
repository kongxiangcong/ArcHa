**What to build:** 每个 Run 的专家持续解释结果并选定工作；执行结果可靠回流，既能实施代码，也能只测量或分析，不制造空 Attempt。

**Blocked by:** 02 — 持久化 Call 与结果，恢复不重复执行或记账。

**Status:** resolved

**Spec:** [S2 实现规格](../spec.md)

- [x] Expert 决策归 Run，选定后创建 Attempt；复盘、停止或决策失败保存 Call 与用量，但不制造执行空轮。不同 Run 的逻辑专家上下文分离。
- [x] 派发包含目的、固定起点、成果依赖和交付要求；返回包含实际操作、产物/检查、失败及偏差，身份和既有契约由 Engine 关联。
- [x] 贯通代码/产物、纯测量和独立分析路径；无需 Designer 或正式评价时可跳过，不强制补丁、数值排名或竞争假设字段。
- [x] Designer 在原授权内局部调试不拆 Attempt；补原工作沿用 Attempt、新派发使用新 Call；专家另选后续工作创建新 Attempt，新测量与缓存引用分别记录。
- [x] 结果保存后保留待处理反馈，专家以具体结果引用给出判断或安排补查；空回复、仅已读、遗漏或调用失败不清除未处理项。
- [x] 一次专家决策可汇集多份结果；正常收尾处理最后一轮，用户控制/预算退出保留待分析而不额外强制调用。解释不替代验收，待分析不伪装为完成。
- [x] 建立稳定的 Run 材料入口，允许授权内按需查证原件；不复制完整 trace 进上下文，不增加总结 Worker 或强制逐轮审核。
- [x] 恢复覆盖结果已存未反馈、决策已存后续工作未登记，避免重复专家处理或重复节点登记；观察端显示反馈及决策关联。
- [x] 用小型贯通场景验证上述路径与失败反馈，保持串行执行可运行；清理旧的强制 Attempt 内 Expert 流程。原生 CLI 会话续接由 05 接入，DAG 调度由 06 扩展。

## Answer

Run 层 Expert 使用独立 Call 和稳定 `materials/research.json`，先事务保存决策与结果解释，再按决策 Call 幂等登记选定工作。停止、复盘和失败不创建空 Attempt；恢复补齐已存回执、决策或已登记工作，不重复 Expert/节点。纯测量可用 `designer=false`，分析可用 `evaluate=false`；`select_work=false` 只解释结果。新测量保留独立评价回执，原工作补测仍沿用 Attempt。

待反馈包含窗口外结果的原件引用；仅“已读”不会清除。正常停止要求最终结果已解释，控制/预算退出保留待反馈。观察入口增加反馈与决策关联，并修正 ArcHa Call 与原生 session 的日志归属。内置参数搜索也返回实际测量解释。旧 Attempt 内 Expert 路径已移除。
