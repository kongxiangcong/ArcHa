# 07: 并行工具访问边界与轻量交付贯通

**What to build:** 并行工作的实际读取与执行工具受任务权限约束，用户能从准备到暂停恢复观察完整小任务；以真实 Codex 留下交付证据，明确 DSH 仅完成实现的验证边界。

**Blocked by:** 06 — Attempt DAG 与有界并行（包含前述 CLI、控制与预算依赖）。

**Status:** ready-for-agent

**Spec:** [S2 实现规格](../spec.md)

- [ ] 将既有任务访问边界接入两个 CLI 的实际文件读取/执行工具路径与并行工作区，模型通信处于可信外层；cwd、独立 Git 工作树或进程树管理不冒充访问隔离。
- [ ] 权限与目录绑定在新调用及恢复时保持一致，越界读取/写入/执行如实阻止或报告能力缺口，不静默扩大权限。
- [ ] 用真实 Codex 贯通准备、指定 revision、新 Run、专家选定多分支、结果回流、暂停/继续及观察；独立必要案例覆盖 stop、失败恢复和工具边界，不运行正式考题。
- [ ] 交付能定位实际后端版本、配置来源、节点/Call/session、输入输出、评价原件、预算和错误，明确真实观察、模拟测试及未验证能力的差别。
- [ ] 多分支的共享计时资源排他、结果不隐式合并、最后一轮解释与任务验收边界符合规格；不扩展 S4 完整交付策略。
- [ ] DSH 工具接入仅实现与静态核查，不新增 DSH 专用测试，不安装、登录或真实运行；交付明确 DSH 未实测，不因该已批准例外阻塞本阶段完成。
- [ ] 完成相关框架回归与必要集成检查，确认 S1 身份/冻结/closed 行为、只读观察及已授权预算例外均保持正确；已有失败不得以新增跳过或放宽断言掩盖。
- [ ] 清理本次已无用途的中间产物和被替代路径，只保留复现/验收必要证据；交付记录集中维护既有规格，不新增平行报告或状态账。

本票包含实际工具隔离接入与端到端交付，不是推迟所有测试到最后的独立测试工程；前六票须各自完成所属行为的必要验证。
