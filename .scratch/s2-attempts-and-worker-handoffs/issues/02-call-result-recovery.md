# 02: 持久化 Call 与结果，恢复不重复执行或记账

**What to build:** 一次角色派发从开始到结果落账都有明确身份；控制器中断后能利用已有成果继续，保留未知执行而不盲目重发或重复扣费。

**Blocked by:** None (can start immediately).

**Status:** resolved

**Spec:** [S2 实现规格](../spec.md)

- [x] Engine 在实际派发前生成独立 ArcHa Call ID 并保存必要输入、身份及原件位置；后端 session ID 单独关联，复用会话不复用 Call ID。
- [x] 结果与实际用量关联本次调用/评价，重复核对或恢复不重复登记、执行或记账；实际新调用仍计入消耗。
- [x] 已确认未启动、可靠完成、仍在途和无法确认终态可区分；未知执行先核实并阻塞受影响工作/资源，不把缺回执当未执行。
- [x] 普通 Run 能按可靠证据收尾及补齐计量；缺失计量不填零，仅在实际启用的预算约束需要该计量时阻塞相关派发。
- [x] 已保存 Designer 成果但尚未评价时，从必要评价继续；结果已落盘未完成记账时，只补缺失收尾。保留既有冠军引用恢复能力。
- [x] 不再统一将可恢复工作 abandoned；保留未知在途、未保存成果和恢复所需工作区，只清理无后续用途的已收尾材料。
- [x] 观察入口可关联派发、实际终态、结果、用量及错误；历史记录仍可读，缺少必要事实时明确不能恢复，不批量补造历史。
- [x] 复用失败注入夹具，通过公开恢复入口覆盖派发无终态、结果落盘未记账及重复恢复，保留相关 S1 回归。
- [x] 复用单账本、事务和项目级单写锁，不新增哈希或平行状态账；清理被替代且无兼容职责的旧收尾路径。

## Answer

已在原 Ledger 增加 Call 派发与回执记录，ArcHa Call ID 独立于后端 session；派发输入先落账、原子回执先落盘，完成和扣费在一个事务中幂等提交。Worker 和执行期评价均走同一入口，原有重复评价扣费已移除。恢复复用可靠回执、候选和评价，缺终态保留未完成 Attempt 与工作区并阻塞；评价基础设施失败可沿用 Attempt、以新 Call 和原件目录补测。普通 Run 可通过原账本计量补齐入口对账，未知用量保留明确记录。

验证：Engine、计量恢复、研究循环回归首轮 127 通过；唯一旧 interruption/abandoned 断言已按规格改为保留未知，随后针对交接与中断重跑通过。新增覆盖回执落盘未落账、基线已测未登记、无终态阻塞、评价失败原 Attempt 补测及重复恢复不扣费。未新增或执行 DSH 专用验证。

最终恢复审计补查：Designer 已确认未启动或可靠返回基础设施失败时，保留原计划、输入、工作区及未完成 Attempt；用户继续后以独立 designer-N 原件目录和新 Call 补完，不在同次运行内盲目重试。原调用成本从同账本汇总，已删除被替代的局部成本累加；未知执行仍阻塞，实际工作失败仍交 Expert 判断。两个原工作重试分支与并行独立分支回归通过。
