# 04: 在调用边界暂停，并取消停止中的执行

**What to build:** 用户暂停时当前调用可收尾且不启动下一段；停止或预算耗尽时取消受控执行，保存事实并准确展示仍在途或未知的工作。

**Blocked by:** 02 — 持久化 Call 与结果，恢复不重复执行或记账。

**Status:** ready-for-agent

**Spec:** [S2 实现规格](../spec.md)

- [ ] Engine 观察到 pause 后阻止所有新角色 Call 和程序评价，包括专家反馈；在途调用受预算/超时约束收尾，不等待整个 Attempt 完成。
- [ ] 当前调用未结束时显示暂停请求及在途状态；收尾后暂停，继续沿用原 Run 并补未完成交接。查看状态不能恢复执行。
- [ ] stop 阻止新派发，请求取消，有限等待后必要时终止受控进程树；保存已发生事实并关闭 Run，不为补解释或终验继续调用。
- [ ] 明确预算耗尽走取消路径；不承诺精确截断尚未上报的 token，未报告用量保持未知，不因此假装没有消耗。
- [ ] 完成与取消竞争时按可靠事实保留完整结果或标记未完成材料；无法确认终止时保留未知状态与工作区，阻止受影响资源重复派发。
- [ ] 统一 Worker 与程序评价的控制边界，复用进程管理，不引入进程冻结、工具步骤级恢复或常驻控制 Agent。
- [ ] 用受控长调用从公开控制入口验证 pause、stop、超时/预算退出、取消竞争及恢复；检查 closed 不原地重开与停止后无新增模型调用。
- [ ] 清理旧轮间检查中与新控制语义冲突的路径，保留 S1 契约及历史运行回归。两个真实后端的接入验收由 05 按其验证范围完成。
