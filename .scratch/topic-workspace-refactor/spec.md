# ArcHa：专题工作区与通用 Worker 端到端重构

Status: ready-for-agent

## Problem Statement

用户希望用 ArcHa 持续开展研究探索：从明确目标开始，由专家选择最有价值的下一问，由执行者核查资料或完成最小实验，再把结果吸收到认知状态中。现有流程把这项工作绑定到契约准备、冻结 Run、特定 CLI、主张账本和独立交付审核，增加接入、人工介入和维护成本。

用户需要的是可以直接启动、查看实时进展、停止后修改并继续的轻量闭环。同时，轻量化不能把半写文件当成功、吞掉进程错误、重复启动实验，或交付一套只有内核能用、技能与工作台却失效的系统。

## Solution

以探索专题作为持续工作区，目标、认知状态、逐轮探针及结果承载权威内容。Expert 与 Executor 通过通用命令配置进行无状态调用，按线性探索轮次推进；用户在停止后直接介入，预算耗尽时仍能得到最后一轮的分析与剩余问题。

同步重构命令入口、技能部署、日志整理与工作台，使新协议在目标工程中可实际运行。保留旧研究数据，但不兼容旧执行格式。研究完成由 Expert 根据目标和结果判断，不再意味着独立审核、代码合并或发布。

## User Stories

1. 作为研究者，我希望从明确目标直接初始化专题并启动探索，以便不必先经过强制准备链路。
2. 作为研究者，我希望目标记录范围、环境入口和完成判据，以便专家知道需要回答什么。
3. 作为研究者，我希望初始化不覆盖已有目标、认知状态或 Worker 配置，以便保留已有工作。
4. 作为研究者，我希望空目标不能启动正式探索，以便避免消耗资源开展无方向工作。
5. 作为研究者，我希望多个专题可以并存并独立查看，以便组织不同研究方向。
6. 作为研究者，我希望停止和继续沿用原专题，以便保持认知与轮次历史连续。
7. 作为研究者，我希望同一工程同时最多一个执行者，以便不同专题不会并发修改同一实验环境。
8. 作为研究者，我希望结束执行后能澄清目标、修正环境入口和调整问题队列，以便直接纠正方向。
9. 作为研究者，我希望实质换题时新建专题，以便不混淆两项研究的证据和结论。
10. 作为研究者，我希望修改尚未执行的探针后，继续时使用修改后的内容，以便准确干预下一步。
11. 作为研究者，我希望已完成轮次保持为历史，新实验生成新探针，以便区分原观测和后续验证。
12. 作为研究者，我希望工程条件变化对结论的影响被明确注明，以便知道旧结论仍适用于什么条件。
13. 作为研究者，我希望使用通用命令接入不同 CLI 或脚本，以便不受某个 Harness 私有协议限制。
14. 作为研究者，我希望不同角色可选择各自的 Worker 配置，以便匹配分析与执行任务。
15. 作为研究者，我希望未知 preset、旧字段和错误配置明确报错，以便不会无意调用另一后端。
16. 作为研究者，我希望自定义脚本只需填写实际使用的参数，以便不被无关模型配置阻塞。
17. 作为研究者，我希望 Worker 每次调用使用当前工作区上下文，以便不依赖不可见的旧 CLI 会话。
18. 作为研究者，我希望 Executor 可显式通过标准输出返回正文，以便接入只输出文本的工具。
19. 作为研究者，我希望 Expert 完整更新认知状态并按需生成探针，以便两项职责不会被单份 stdout 混淆。
20. 作为研究者，我希望非零退出、超时和无有效产出立即停止并说明原因，以便错误日志不会冒充结果。
21. 作为研究者，我希望失败不触发自动无限重试，以便控制实验成本和重复副作用。
22. 作为研究者，我希望在调用尚未结束时看到输出，以便了解长时间运行的真实进展。
23. 作为研究者，我希望失败或中断后仍能查看已有日志，以便定位问题。
24. 作为研究者，我希望停止后确认子进程已结束再编辑，以便不被残留进程覆盖修改。
25. 作为研究者，我希望重复停止不会影响之后的新运行，以便控制操作可以安全重复。
26. 作为研究者，我希望无法确认旧执行结束时系统拒绝派发，以便避免两个实验同时运行。
27. 作为研究者，我希望 Worker 半写内容不会成为下一角色的输入，以便恢复后不会沿错误状态推进。
28. 作为研究者，我希望已验证但发布中断的成果能继续发布，以便无需重新运行已成功的调用。
29. 作为研究者，我希望恢复复用已经提交的实验结果，以便避免不必要的重复实验。
30. 作为研究者，我希望清楚知道未提交调用可能重跑且工程修改不会自动撤销，以便判断恢复所需条件。
31. 作为研究者，我希望预算按完成的探针与结果计数，以便一次专家调用不被误算为一轮实验。
32. 作为研究者，我希望轮数上限用尽后专家仍消化最后结果，以便不会留下未分析的末轮数据。
33. 作为研究者，我希望收尾消化不再派发实验，以便轮数上限具有实际约束。
34. 作为研究者，我希望预算耗尽与研究完成分别显示，以便正确理解停止原因。
35. 作为研究者，我希望显式追加轮数时保留历史用量，以便继续工作而不重置成本记录。
36. 作为研究者，我希望专家不能自行增加预算，以便资源控制仍由用户决定。
37. 作为研究者，我希望非法预算修改得到具体错误且现场被保留，以便修正后继续而不是超额执行。
38. 作为研究者，我希望已完成专题不会因运行或追加预算自动重开，以便完成状态保持明确。
39. 作为研究者，我希望执行得到否定结果仍可推进认知，以便不把有价值的反证误判为阻塞。
40. 作为研究者，我希望缺少条件且没有可行替代路径时明确进入专题阻塞，以便知道需要补充什么。
41. 作为研究者，我希望补齐阻塞条件后显式继续，以便恢复保持原专题与有效预算。
42. 作为研究者，我希望进程失败与专题阻塞分开表达，以便区分工具问题和研究条件不足。
43. 作为研究者，我希望每轮聚焦一个关键问题，以便控制探索范围和实验成本。
44. 作为研究者，我希望能通过源码、资料或已有记录回答时优先复用这些材料，以便避免不必要的实验。
45. 作为研究者，我希望探针形式按问题选择，以便不被强制套入 A/B 对照。
46. 作为研究者，我希望执行者核验干预实际生效，以便无效改动不会被当作无影响的证据。
47. 作为研究者，我希望事实、解释和未验证假设清晰区分，以便判断结论可信范围。
48. 作为研究者，我希望关闭分支记录理由与适用条件，以便避免重复探索并在条件变化时合理重开。
49. 作为研究者，我希望认知状态保留结论与证据入口而不无限追加历史，以便后续调用保持聚焦。
50. 作为研究者，我希望历史材料可按需回看，以便精简上下文时仍能追溯具体观测。
51. 作为研究者，我希望默认流程适用不同领域，并可选择 PIM 示例，以便方法不被某种模拟器绑定。
52. 作为研究者，我希望必要原件和脚本能够留存，既有材料可以直接引用，以便复现研究而不复制数据。
53. 作为研究者，我希望仅在需要时生成叙事报告，以便避免每轮制造重复文档。
54. 作为研究者，我希望工作台显示当前角色、轮次、运行时间和真实输出，以便掌握执行状态。
55. 作为研究者，我希望工作台只展示新流程中的角色和收尾活动，以便不被旧审核与评价节点误导。
56. 作为研究者，我希望控制请求发出和实际停止或运行明确区分，以便不会误以为操作已经生效。
57. 作为研究者，我希望重复启动或多个页面同时继续也只产生一个执行者，以便避免重复工作。
58. 作为研究者，我希望状态查询和材料阅读不会启动、恢复或清理任务，以便放心查看现场。
59. 作为研究者，我希望当前认知状态不会被展示成某个历史轮次的快照，以便准确理解历史证据。
60. 作为研究者，我希望材料阅读限制在允许范围且不执行原始 HTML，以便使用工作台查看研究产物。
61. 作为研究者，我希望工作台保留必要的主题、响应式和可访问性行为，以便持续使用已有界面能力。
62. 作为研究者，我希望部署后的目标工程有本地可调用入口，以便不依赖全局安装就能使用技能。
63. 作为研究者，我希望四个技能各司其职但不形成强制链路，以便按当前任务选择入口。
64. 作为研究者，我希望旧研究记录原位保留但执行不被静默迁移，以便保留历史且避免错误续跑。
65. 作为研究者，我希望研究完成不自动触发合并或发布，以便自行决定工程交付动作。
66. 作为研究者，我希望目标要求的测试在探针和结果中得到执行与记录，以便完成判断有实际依据。
67. 作为维护者，我希望核心、入口、部署与工作台一起完成切换，以便交付能实际使用的系统。
68. 作为维护者，我希望被替代模块的调用、测试和文档同时清理，以便没有悬空入口或相互冲突的说明。

## Implementation Decisions

- 采用专题工作区与线性探索轮次，遵循已接受的专题工作区架构决策。P0–P3 是开发分层，共同组成交付，不分别承诺独立发布。
- 通用 Worker 负责命令配置、受管理的进程调用、日志和输出检查；工作区负责正式成果发布；调度内核负责动作选择、预算和角色上下文。同步更新 CLI、技能部署、日志整理和工作台。
- 项目配置优先，缺省使用分发的默认配置；只接受新协议。角色使用显式 preset 或命令数组，输入支持标准输入或提示词文件，输出能力按角色区分。命令模板提供工程、专题、提示词、输出、状态与按需模型参数，不隐式拼接 shell。
- 配置在输入边界校验，拒绝错误类型、未知配置、非法枚举和未提供的模板变量。preset 参数在开发时核实，不默认绕过外部 CLI 的权限机制。
- 目标、认知状态和探针/结果是权威内容；运行期描述、日志、临时提交材料、原件和衍生报告不构成第二份认知账本。
- 专题状态限定为 `IN_PROGRESS`、`COMPLETED`、`BUDGET_EXHAUSTED`、`BLOCKED`，与进程是否正在执行分开。状态头唯一且严格解析，非法内容不静默恢复为默认状态或预算。
- 只在成功退出、未超时、进程树收尾且必需输出有效后接受调用。文件输出不自动回退到 stdout；Executor 的 stdout 模式仅接受正文，错误输出不参与结果发布。
- 复用既有跨平台进程树管理、系统独占锁与 Windows Job 能力。进程登记失败、异常和正常退出均完成必要清理；不能确认旧执行已结束时禁止新派发。
- 同工程所有专题共用一个系统执行锁；稳定锁文件不在持锁期间替换或删除。描述文件和 PID 存活检查不代替互斥与进程归属判断。
- 引擎拥有正常停止与清理责任。外部控制请求等待实际结束，不按旧快照无条件删除工作区材料，重复停止不得影响新运行。
- Expert 先在准备区域生成完整输出，验证后原子转入待发布区域；恢复丢弃未完成准备，继续发布已经验证的提交。提前完成、阻塞和最终收尾使用同一协议。Executor 以单份结果原子发布；动作推导发生在恢复完成之后。
- 双文件发布期间可显示提交中，不宣称跨文件瞬时原子可见。恢复保证针对进程中断，不承诺掉电持久事务或外部副作用回滚。
- 轮数由已提交探针及结果计算，只有日志或临时材料的步骤不计入已完成轮次。预算检查先于派发；非法降低预算保留现场并报错。
- 上限达到后只做收尾消化：目标达成为完成，否则预算耗尽并保留未解问题。正常回合没有可行路径则进入阻塞。预算追加保留历史用量，完成专题不接受追加或自动重开。
- Expert 默认只接收目标、当前认知状态与上一轮探针/结果；Executor 接收目标、状态与当前探针。历史按需访问，不把日志或全部历史注入每轮提示词。
- 默认模板领域中立，PIM 仅为可选示例。探针聚焦一个问题，分支关闭带条件，Executor 核验干预生效；研究目标要求的测试按探针执行，不恢复独立 Reviewer 流程。
- 提供初始化、运行、单步、继续、停止、只读状态查询。继续按需追加预算并显式解除已处理阻塞；停止中断当前调用，首版没有等待本轮完成后暂停的独立语义。
- 工作台前后端共同改用专题身份和新契约，不保留旧 Run/request 历史协议。展示 Expert、Executor 和收尾活动，流式日志保留失败前内容；同轮同角色重试可覆盖上次日志，收尾日志独立保留。
- 保留材料阅读边界及必要界面能力，不解析 Harness 私有事件，不伪造模型活动，不将当前认知状态伪装成历史快照。
- 部署清单只有一个来源，技能使用目标工程内的本地运行时入口，分发全部实际依赖和资源。新组件及消费者先形成可运行切片，再移除旧模块；完整工作台接入后才算全部交付。
- 旧规格和事项保留历史记录，并标明替代关系。旧运行数据不迁移、不删除、不继续执行；清理旧契约、账本、工具拦截、评价与晋升调用以及相应失效测试和文档。

## Testing Decisions

- 测试边界已经在方案评审中确认：主边界是部署到独立目标工程后的真实 CLI 全链路，工作台通过真实后端接口和浏览器验证。此次沿用该决定，不新增测试边界访谈。
- 优先测试用户可见行为、状态和成果，不锁定内部函数拆分、临时文件实现细节或组件私有结构。确定性假 Worker 替代模型输出；编排、工作区、配置与 CLI 尽量从主边界一起覆盖。
- 主流程覆盖初始化、单步、运行、状态查询、停止、恢复、追加预算、阻塞解除和完成后拒绝重开；断言实际输出、完成轮数及下一动作，不能只断言调用次数。
- 只有主边界不便稳定复现的进程与提交故障使用较低层边界：小型真实子进程验证超时、日志流、后代清理和进程登记失败；故障注入验证准备、提交转入、逐份发布及清理前后的中断恢复。
- 提交测试覆盖继续、提前完成、阻塞和收尾；正式结果不得出现半成品，已验证提交应恢复发布，已提交实验不得重跑。断言恢复后的对外行为，不把单一路径排列当规格。
- 配置与输出测试覆盖文件和 stdout 正常结果、未知 preset、旧字段、错误类型、空白产出、非零但有输出、超时和缺少必需输出；所有失败都不得推进调度或无限重试。
- 使用多个真实进程测试同专题及跨专题的工程互斥、停止与新启动竞争、重复停止、未知执行拒绝派发；不能用顺序调用冒充并发验证。
- 预算测试覆盖末轮收尾、实际轮数计算、已有待执行探针时降低预算、追加后继续及收尾仍有缺口的状态。专题阻塞、否定结果、工具失败和预算耗尽分别验证。
- 工作台验证调用结束前即有日志，停止/继续实际生效，角色与收尾展示正确，当前状态不冒充历史，查询不触发写入；同时覆盖阅读边界、主题、响应式及适用的可访问性回归。
- 部署验收从目标工程的本地入口执行，验证模板、传递导入、日志技能及资源完整，不以源码仓库可导入代替分发可用。
- 沿用现有平台测试中的跨进程锁、崩溃释放、父进程退出后孙进程清理及 Windows Job 失败测试方法；沿用技能部署测试的临时目标工程，以及观察控制测试的真实后端、子进程和浏览器联动方式。旧暂停、Run 和账本语义不因复用测试方法而保留。
- 完成核心与工具两组测试的收集及适用回归，并执行前端现有适用检查。真实 CLI 可用时补最小调用验证参数；模型调用不是可重复自动化测试的替代品。

## Out of Scope

- 旧格式自动迁移、旧运行恢复、旧配置字段或旧角色静默兼容。
- 冻结合同、内容哈希树、Claim 账本、Attempt DAG、CLI 会话冻结与切换预算。
- 独立 Reviewer、候选晋升、交付修复循环以及自动合并或发布。
- 同工程并行执行、自动 worktree、实验环境隔离与副作用自动回滚。
- 外部实验恰好执行一次、机器掉电后的持久事务和任意历史编辑后的自动重算。
- 等待当前轮结束后暂停、旧控制请求历史兼容与完整调用审计。
- Harness 私有工具活动解析、全历史默认上下文注入和每轮强制报告生成。
