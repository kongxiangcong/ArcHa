# 05: 按轮数推进探索、处理阻塞并完成收尾

**What to build:** 用户给出目标和轮数预算后，双角色循环持续推进，遇到无可行路径时阻塞，达到上限后分析末轮结果，并能显式追加预算继续研究。

**Blocked by:** 03：中断后恢复已提交成果

**Status:** resolved

依据：[父规格](../spec.md)、[开发方案](../../../archa-refactor-plan.md)、[架构决策](../../../docs/adr/0001-topic-workspace.md)。具体文件清单以开发方案为准。

**范围与归属：** 负责连续调度、预算与四种专题状态、完整角色提示词、上下文裁剪和通用/PIM 模板。复用 01 的锁及 03 的提交接口，不重写 04 的停止清理机制。

- [x] 从已部署入口持续执行探针与结果循环，正确统计完成轮次；专家调用、空步骤或提前完成目录均不增加实验轮数。
- [x] Expert 只接收目标、当前认知状态与上一轮探针/结果；Executor 只接收目标、状态和当前探针，历史按需查阅，不注入全量日志。
- [x] 默认模板领域中立，PIM 可选；初始问题来自目标，探针可采用资料核查、既有数据分析或最小实验，不强制 A/B 形式。
- [x] 角色协议明确事实与假设、证据入口、干预生效核验、带条件关闭分支及按需重开；目标要求的测试在探针和结果中体现。
- [x] 在第 N 轮结果后执行一次收尾消化，不派发第 N+1 轮；收尾日志独立，目标达成标记 COMPLETED，否则 BUDGET_EXHAUSTED 并保留缺口。
- [x] 正常回合由 Expert 判断无可行路径时进入 BLOCKED 并说明所需条件；否定结果与进程失败不自动等同于专题阻塞。
- [x] 显式恢复可解除已处理阻塞；正数追加预算保留历史用量，Expert 不得改变授权预算，完成专题拒绝追加与自动重开。
- [x] 预算检查先于派发，非法降低到已用量以下或不足以覆盖已提交待执行探针时保留现场并报错；预算更新在锁内原子完成。
- [x] CLI 可区分未完成、研究完成、阻塞、预算耗尽和工具失败；研究完成不触发独立审核、合并或发布。
- [x] 确定性 Worker 的端到端用例覆盖提前完成、阻塞解除、最后一轮收尾、追加预算、重复读取末轮结果不重复累加事实及错误不自动重试。


## Answer

实现连续 `run`、显式 `resume --add-rounds`、锁内预算更新、阻塞解除与完成后拒绝追加。完成轮次仅由已提交探针/结果计数；末轮独立收尾日志保留探针生成日志，使用同一 Expert 提交协议，完成目标为 COMPLETED，否则为 BUDGET_EXHAUSTED。run/resume 退出码为完成 0、阻塞 4、耗尽 5；调用/配置失败为 2，step/status 通过 JSON 区分领域状态。

角色上下文只注入约定的当前材料，历史按需读取；协议说明事实/假设、条件性分支关闭、替代路径、干预生效、目标测试及重复读取末轮结果不重复计事实。默认模板中立，`init --template pim` 提供可选领域提示；空模板不能启动。

验证：`opc/tests/test_topic_rounds.py` 的 8 个部署 CLI 测试覆盖末轮收尾/完成、预算追加、阻塞解除、提前完成、上下文裁剪、否定结果、重复吸收、失败即停及非法预算。与 `test_topic_cli.py`、`test_topic_recovery.py` 合跑 **63 passed**；最后更新后的轮次测试 **8 passed**。`git diff --check` 与修改模块编译检查通过。工程所有权和停止生命周期由事项 04 在集成时接入公共 `lifecycle()`。
