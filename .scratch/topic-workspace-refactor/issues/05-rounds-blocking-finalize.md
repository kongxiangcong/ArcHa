# 05: 按轮数推进探索、处理阻塞并完成收尾

**What to build:** 用户给出目标和轮数预算后，双角色循环持续推进，遇到无可行路径时阻塞，达到上限后分析末轮结果，并能显式追加预算继续研究。

**Blocked by:** 03：中断后恢复已提交成果

**Status:** ready-for-agent

依据：[父规格](../spec.md)、[开发方案](../../../archa-refactor-plan.md)、[架构决策](../../../docs/adr/0001-topic-workspace.md)。具体文件清单以开发方案为准。

**范围与归属：** 负责连续调度、预算与四种专题状态、完整角色提示词、上下文裁剪和通用/PIM 模板。复用 01 的锁及 03 的提交接口，不重写 04 的停止清理机制。

- [ ] 从已部署入口持续执行探针与结果循环，正确统计完成轮次；专家调用、空步骤或提前完成目录均不增加实验轮数。
- [ ] Expert 只接收目标、当前认知状态与上一轮探针/结果；Executor 只接收目标、状态和当前探针，历史按需查阅，不注入全量日志。
- [ ] 默认模板领域中立，PIM 可选；初始问题来自目标，探针可采用资料核查、既有数据分析或最小实验，不强制 A/B 形式。
- [ ] 角色协议明确事实与假设、证据入口、干预生效核验、带条件关闭分支及按需重开；目标要求的测试在探针和结果中体现。
- [ ] 在第 N 轮结果后执行一次收尾消化，不派发第 N+1 轮；收尾日志独立，目标达成标记 COMPLETED，否则 BUDGET_EXHAUSTED 并保留缺口。
- [ ] 正常回合由 Expert 判断无可行路径时进入 BLOCKED 并说明所需条件；否定结果与进程失败不自动等同于专题阻塞。
- [ ] 显式恢复可解除已处理阻塞；正数追加预算保留历史用量，Expert 不得改变授权预算，完成专题拒绝追加与自动重开。
- [ ] 预算检查先于派发，非法降低到已用量以下或不足以覆盖已提交待执行探针时保留现场并报错；预算更新在锁内原子完成。
- [ ] CLI 可区分未完成、研究完成、阻塞、预算耗尽和工具失败；研究完成不触发独立审核、合并或发布。
- [ ] 确定性 Worker 的端到端用例覆盖提前完成、阻塞解除、最后一轮收尾、追加预算、重复读取末轮结果不重复累加事实及错误不自动重试。
