# 08: 从工作台停止、继续和追加轮数

**What to build:** 用户可以在浏览器停止当前执行、补齐条件后继续专题或追加预算，明确看到控制请求与实际生效的区别，多页面操作也不会重复启动。

**Blocked by:** 07：在工作台查看专题与实时执行

**Status:** ready-for-agent

依据：[父规格](../spec.md)、[开发方案](../../../archa-refactor-plan.md)、[架构决策](../../../docs/adr/0001-topic-workspace.md)。具体文件清单以开发方案为准。

**范围与归属：** 负责工作台控制后端与前端交互，复用已经完成的引擎控制和预算能力，不再实现第二套锁、停止或恢复协议。

- [ ] 前后端采用一致的专题控制契约，提供停止、继续及必要的追加预算，移除旧暂停与请求历史协议依赖。
- [ ] 提交停止请求后显示等待状态，只有进程树已确认结束才显示停止；超时或归属未知如实显示，不把请求接收当作完成。
- [ ] 继续使用原专题和已提交结果，BLOCKED 经显式恢复后推进，BUDGET_EXHAUSTED 需追加预算；COMPLETED 不提供自动重开。
- [ ] 多个页面或重复点击继续时仅一个执行者；重复停止、旧请求与新启动竞争不破坏新运行或误停其他专题。
- [ ] 控制失败保留当前阅读现场并显示可理解原因；页面刷新或断开不隐式停止或重复启动后台任务。
- [ ] 浏览器通过真实后端完成运行→停止→继续及追加轮数链路，并覆盖阻塞恢复、预算耗尽、失败、未知执行和已完成专题。
- [ ] 研究报告相关界面若保留生成操作，接入 06 提供的新整理能力由 09 做最终整体验证；本项不依赖旧报告服务，也不新增对 06 的虚假阻塞。
