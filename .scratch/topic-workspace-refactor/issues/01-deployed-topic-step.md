# 01: 部署并跑通专题单步流程

**What to build:** 用户在独立目标工程中通过本地入口初始化专题，使用确定性 Worker 完成 Expert → Executor 单步交接，并只读查询下一动作和已完成轮数。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

依据：[父规格](../spec.md)、[开发方案](../../../archa-refactor-plan.md)、[架构决策](../../../docs/adr/0001-topic-workspace.md)。具体文件清单以开发方案为准。

**范围与归属：** 负责新工作区、初始化、单步调度、只读状态、确定性 Worker、最小角色提示词和本地运行时部署的首个完整切片。复用现有进程平台的基础工程锁。先扩展新入口，保持尚未迁移的消费者可用；不先删除旧接口，也不新增旧格式兼容层。

- [ ] 从独立临时目标工程的已部署本地入口完成初始化、两次单步和状态查询；不依赖源码仓库导入路径或全局命令安装。
- [ ] 初始化保留已有目标、认知状态及配置；明确目标、环境入口与完成判据的输入位置，目标为空时拒绝正式执行。
- [ ] 新格式具备唯一且严格解析的状态头、正整数预算及规范轮次；缺失、重复或非法元数据报告具体错误，不静默回退。
- [ ] 单步每次只执行一个角色；认知状态、探针和结果通过新接口交接，完整结果提交后才增加完成轮数，状态查询返回正确下一动作。
- [ ] 提供后续提交恢复所需的准备输出与正式发布边界；本项验证正常路径，崩溃协议由 03 完成，不宣称已经具备完整恢复保证。
- [ ] 所有新执行写操作取得稳定文件上的工程级 OS 独占锁；同工程不同专题的写执行相互排斥，状态查询不派发、不清理、不修改材料。
- [ ] 新执行仅接受新专题格式；旧研究数据原位保留，不尝试恢复旧 Run。
- [ ] 部署清单作为单一来源包含当前切片的实际依赖和资源；适用的旧入口测试与新部署冒烟均通过，临时测试材料清理完毕。
