# 02: 通过通用命令运行真实 Worker

**What to build:** 用户为两个角色配置命令或 preset 后，可从部署入口执行实际子进程，持续查看输出，并在错误或超时时得到明确失败。

**Blocked by:** 01：部署并跑通专题单步流程

**Status:** ready-for-agent

依据：[父规格](../spec.md)、[开发方案](../../../archa-refactor-plan.md)、[架构决策](../../../docs/adr/0001-topic-workspace.md)。具体文件清单以开发方案为准。

**范围与归属：** 负责通用 Worker、配置解析、默认配置、命令模板和流式日志的替换实现；精简复用跨平台进程树能力。旧特定 CLI 适配器的最终删除由 09 负责。

- [ ] 项目配置优先，缺省使用随运行时分发的默认配置；未知 preset、旧字段、错误类型、非法模式、非正超时及不可用模板变量在调用前明确报错。
- [ ] 命令为非空字符串 argv 数组，不隐式拼接 shell；工作目录、专题及各动作的输入输出变量按方案提供，自定义脚本不使用模型变量时无需填写模型。
- [ ] 从已部署 CLI 验证 stdin/file 两种输入；Expert 只用文件输出，Executor 可显式选择文件或 stdout，文件模式不自动回退到 stdout。
- [ ] Worker 保留调用方已准备的状态草稿；只在零退出、未超时且必需输出非空白时返回可提交成果，错误日志不作为正文。
- [ ] 非零退出但有输出、空白输出、缺少输出与超时均失败且不推进下一角色、不自动重复调用。
- [ ] 子进程运行中即可读取 stdout/stderr 日志；中断和失败保留已有输出，同轮同角色重试可覆盖旧日志。
- [ ] 启动后登记失败、异常、超时和正常结束均完成归属进程树收尾；确认后代结束后才能允许发布成果，沿用适用的 POSIX 与 Windows 能力。
- [ ] 用小型真实子进程从 CLI 验证输出、超时和后代清理；默认 preset 参数以实际可用 CLI 的帮助核实，不默认绕过其权限机制，必要资源随部署同步。
