# 03: 中断后恢复已提交成果

**What to build:** 用户重新进入中断的专题时，系统丢弃未完成输出、继续发布已经验证的成果并复用正式结果，使下一角色始终使用完整材料。

**Blocked by:** 02：通过通用命令运行真实 Worker

**Status:** ready-for-agent

依据：[父规格](../spec.md)、[开发方案](../../../archa-refactor-plan.md)、[架构决策](../../../docs/adr/0001-topic-workspace.md)。具体文件清单以开发方案为准。

**范围与归属：** 负责工作区提交与恢复协议、单步入口的恢复顺序和正式轮次推导。终止状态在本项用确定性输出覆盖，连续循环和预算行为由 05 完成。

- [ ] Expert 在准备区域写完整状态与按需探针；成功验证后才进入待发布区域，发布前不改正式材料。
- [ ] 准备阶段中断后可丢弃草稿并重新调用；进入待发布阶段后必须完成剩余发布，不重新调用 Worker、不回滚到半份备份。
- [ ] 状态已发布但探针未发布、所有文件已发布但临时目录未清理等中断点，恢复均得到一致下一动作；只读查询在发布期间可以显示提交中。
- [ ] 普通继续、提前完成、专题阻塞及收尾状态使用同一发布协议；终止或阻塞成果不额外发布实验探针。
- [ ] Executor 仅发布成功验证的单份结果；正式结果已存在时恢复不会重复执行该实验，半写内容不得被识别为成功。
- [ ] 恢复先于状态推导，所有恢复和清理持有工程锁且确认本次待处理进程已结束；跨进程停止归属处理由 04 衔接。
- [ ] 只有日志或临时材料的步骤不计入完成轮次且可复用；破坏结构的手动修改报告具体错误，不静默跳过。
- [ ] 通过故障注入和真实重新启动覆盖准备完成前后、进入提交前后、逐份发布前后及清理前；断言最终材料和下一动作，不仅断言内部调用。
- [ ] 清理仅针对本次运行已无用途的临时材料；保留原件、日志和工程修改，不承诺外部实验恰好执行一次或掉电持久事务。
