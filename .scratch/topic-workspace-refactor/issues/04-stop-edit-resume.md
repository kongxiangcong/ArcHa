# 04: 停止、人工修改与安全继续

**What to build:** 用户能停止当前调用，确认进程结束后编辑目标、认知状态或待执行探针，再继续同一专题；并发与重复控制不会破坏现场。

**Blocked by:** 03：中断后恢复已提交成果

**Status:** resolved

依据：[父规格](../spec.md)、[现行执行协议](../../../opc/README.md)、[架构决策](../../../docs/adr/0001-topic-workspace.md)。原开发方案及文件清单通过 Git 查找。

**范围与归属：** 负责 CLI 停止和继续、当前执行描述、进程归属判断与唯一清理所有者；在 01 的基础锁和 03 的提交恢复上完成控制协议。连续预算语义由 05 提供，合并后由 06 和 08 从技能及工作台贯通。

- [x] 通过部署入口运行长调用并停止，只有确认子进程树结束、完成必要恢复且释放工程锁后才报告实际已停止。
- [x] 引擎负责正常停止清理；外部控制器不按旧快照删除锁或材料，稳定锁文件在持锁期间不替换、不删除。
- [x] 记录控制和展示必需的专题、角色、轮次、开始时间与归属信息；记录文件不是锁，不根据可能复用的裸 PID 盲目杀进程。
- [x] 控制器崩溃后，恢复在取得独占权后处理可确认归属的残留进程；执行结束无法确认时明确报错并拒绝新派发。
- [x] 真实多进程测试覆盖同专题、不同专题竞争，重复 stop，以及旧停止请求与新运行启动竞争；不清理新运行的材料或停止其他专题的新执行。
- [x] 停止后修改待执行探针，继续时实际使用修改；已提交结果不重跑，未提交调用可重试，已完成轮次和工程副作用保留。
- [x] 继续不创建新 Run 身份；目标澄清与环境修正可原专题继续，实质换题新建专题；不增加自动失效扫描、回滚或等待本轮收尾的暂停模式。
- [x] 状态查询区分专题状态、运行中、停止中与未知执行，保持只读；测试同时验证已有错误日志可读及锁最终可再次取得。

## Answer

工程级 `topic_control.lifecycle()` 统一取得锁、确认旧进程树结束、恢复提交和登记执行；单步及 05 的连续运行/继续共享此生命周期。`stop` 绑定执行随机身份，正常停止由引擎收回子进程后清理；控制器崩溃时只有取得锁的恢复者可以清理。Linux 恢复核对启动身份与继承令牌并用 pidfd 发信号；无法核实归属时保留现场并拒绝派发。Windows 正常调用沿用 Job 和创建时间身份，无法确认的崩溃残留明确报错。

`status` 只读返回专题状态及 idle/running/stopping/unknown 活动、角色、轮次、开始时间和归属。稳定锁文件始终保留；已有日志和工程副作用不撤销。执行期间停止后可编辑待执行探针再继续。

验证：部署入口的 6 项真实多进程控制测试通过，覆盖进程树停止、重复停止、同/不同专题竞争、控制器崩溃、未知归属拒绝派发、旧停止快照与新启动竞争及人工探针修改。与 05 合并后，控制、Worker 进程、部署 CLI、提交恢复及预算合计 70 项测试通过，包括实际 `run → stop → 编辑探针 → resume` 流程；未在 Windows 主机执行验证。
