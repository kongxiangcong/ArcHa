# 09: 完成旧实现退役与全仓交付验收

**What to build:** 用户获得一套从部署、CLI、技能到工作台均可使用的新 ArcHa；旧实现和失效说明被移除，旧研究数据仍保留，完整交付有可重复的验收依据。

**Blocked by:** 06：贯通研究技能与按需报告；08：从工作台停止、继续和追加轮数

**Status:** ready-for-agent

依据：[父规格](../spec.md)、[开发方案](../../../archa-refactor-plan.md)、[架构决策](../../../docs/adr/0001-topic-workspace.md)。具体文件清单以开发方案为准。

**范围与归属：** 负责 expand–contract 的最终收缩与全仓集成，不重复建设前八项能力。按开发方案的删除清单逐项确认无消费者后删除，并承接残留调用、包资源、说明和旧测试清理。

- [ ] 逐项核对方案第 7 节：旧特定 CLI 适配器、工具边界与拦截脚本、Claim/结果账本、验收与晋升、旧进展模块、契约准备与简报、评价模板和参数扫描均无残留消费者后删除。
- [ ] 审查旧领域评价器、旧模型/配置类型及跨模块导入，删除无消费者实现；不得留下只能导入但实际执行失效的旧入口。
- [ ] 全部正式 CLI、技能、本地运行时、观察与控制接口使用新协议，撤除开发过渡入口或临时双实现，不承诺旧格式兼容。
- [ ] 整合工作台与按需报告服务，所有保留的报告入口使用新整理能力；调用、部署和资源清单相互一致。
- [ ] 同步根入口说明、引擎说明、初始化资料、技能说明、包资源和测试夹具；新文档不再指导用户调用已退役流程，旧规格与历史记录的替代标记保留。
- [ ] 旧研究数据原位保留，不批量删除或迁移；新运行不会无声恢复旧格式，研究完成不会触发合并或发布。
- [ ] 从干净临时目标工程通过本地入口验证初始化、单步、持续运行、停止、人工修改、继续、追加预算、阻塞恢复、只读状态和按需报告，并完成工作台实际操作。
- [ ] 核心与工具两组测试完整收集并通过适用回归，前端适用检查及浏览器流程通过；各切片已有测试保留，不把最终验证缩减为导入检查。
- [ ] 核对方案第 8 节所有验收边界均有实际验证归属，包含配置错误、非零输出、超时、进程树清理、并发锁、提交中断、末轮收尾与材料阅读。
- [ ] 可用真实 CLI 补最小调用并报告环境限制；离线确定性测试仍独立可重复，不以真实模型调用代替自动化验收。
