# S5：沉浸式工作台、观察接口与运行控制

**Status:** resolved

需求、原型、测试边界及六票粒度与阻塞关系均已获用户确认（2026-11-01）。六票已按编号与依赖实施、验收并 resolved；最终组合路径、回归、双轴审查及未验证范围见 [06 验收记录](issues/06-stop-and-unknown-execution.md#answer)。集成分支为 `feat/s5-debugging-workbench`，变更未提交。

## Problem Statement

用户需要在一个稳定的工作现场判断工作进展、Worker 正在执行的具体动作、阻塞原因，并能暂停、继续或停止当前运行。现有观察页面偏向阶段与内部记录浏览，工作、调用、交接和任务材料没有形成简洁的诊断路径；日志在调用进行时的归属和活动投影仍有缺口，HTTP 也尚未接通运行控制。

仅修改外观无法保证真实状态、错误交接和恢复行为；直接展示所有底层记录又违背用户明确的信息边界。用户不希望在任何工作台入口看到证据、审计、哈希或内部检验材料，也不希望点击控制后看到模拟成功。

## Solution

在既有观察服务和 web 中实现已确认的布局：工作时间线占主要空间，同屏紧凑 Worker 活动区，顶部保留运行状态与控制，导航可收起，详情按需展开，任务文件可扩大阅读并返回原现场。浅深主题和短动效服务选择、定位和真实状态变化。

贯通两条完整操作路径：发现阻塞 → 选择工作 → 查看相关 Worker 错误及必要交接 → 打开任务文件/产出 → 返回现场；请求暂停 → 查看请求与实际生效情况 → 继续同一运行。停止作为同一控制入口的独立操作。

复用现有 Engine、账本、调用记录、冻结配置和恢复契约；只补真实缺失的关联、查询及控制结果事实。生产页面不用原型数据、演示时序或第二套业务状态系统。

## User Stories

1. 作为用户，我希望选择明确的任务和运行，以便始终知道自己正在观察和控制谁。
2. 作为用户，我希望首屏同时看到工作进展与 Worker 活动，以便判断事情和执行者各自的情况。
3. 作为用户，我希望看到每项工作的目标和实际阶段，以便知道已经完成和尚待完成的内容。
4. 作为用户，我希望区分等待依赖、资源等待、执行失败和执行未知，以便理解阻塞原因。
5. 作为用户，我希望直接跳到阻塞该工作的前序工作，以便追查并行工作的关系。
6. 作为用户，我希望时间先后不被画成依赖，以免误解执行关系。
7. 作为用户，我希望筛选需要关注的工作，以便快速定位异常。
8. 作为用户，我希望选择工作时定位关联 Worker，以便查看谁正在处理它。
9. 作为用户，我希望选择 Worker 时定位关联工作，以便理解当前动作的目的。
10. 作为用户，我希望同一角色的并行调用分别可见，以免一个忙碌标签掩盖其他执行。
11. 作为用户，我希望运行级协调活动有独立归属，以免被错误挂到某项工作。
12. 作为用户，我希望看到 Worker 读哪个文件、执行什么命令，以便感知实际活动。
13. 作为用户，我希望动作开始和动作完成明确区分，以免把最近日志当成仍在执行。
14. 作为用户，我希望工具失败和整个调用失败分开，以便看到 Worker 是否还在处理问题。
15. 作为用户，我希望并行工具动作不因新的摘要丢失，以便知道仍有哪些动作未结束。
16. 作为用户，我希望活动时间缺失时如实显示，以免页面刷新时间被当成执行时间。
17. 作为用户，我希望没有新日志时保持最后已知信息，以免看到虚构的思考、等待或卡死判断。
18. 作为用户，我希望后端无法提供具体活动时有简单说明，以免将缺少观测当作工作失败。
19. 作为用户，我希望不必读完全部历史日志就能看到当前活动，以便及时理解长时间运行。
20. 作为用户，我希望查看所选调用的真实错误与必要交接内容，以便处理具体问题。
21. 作为用户，我希望能区分同一工作的多次调用，以免将重试后的输入误认为失败时的输入。
22. 作为用户，我希望打开相关任务文件、代码或产出，以便理解或使用工作结果。
23. 作为用户，我希望文件内容与所选工作和调用关系明确，以免读到不相干的最新文件。
24. 作为用户，我希望从文件返回时保留选择、筛选、局部位置和焦点，以便继续诊断。
25. 作为用户，我希望查看内容不会启动任务、修改文件或隐式重跑，以便放心浏览。
26. 作为用户，我希望用简短文字了解工作或任务未完成的原因，以便判断下一步。
27. 作为用户，我希望交付成功、调用结束与运行关闭不会混为一谈，以免误判结果。
28. 作为用户，我希望所有界面都不显示证据、审计、哈希和内部检验材料，以便专注关键内容。
29. 作为用户，我希望侧栏、弹窗、工具提示及文件入口也遵守这一边界，以免高级详情重新变成审计页面。
30. 作为用户，我希望页面刷新失败时保留已有内容并清楚提示，以免已有成功工作被改判失败。
31. 作为用户，我希望暂停请求收到和实际已暂停分别显示，以免误以为执行已经结束。
32. 作为用户，我希望暂停允许当前 Worker/评价调用收尾并阻止后续派发，以便保留可恢复的工作。
33. 作为用户，我希望暂停等待时仍能查看真实活动，以便理解为何尚未暂停。
34. 作为用户，我希望暂停期间工作保留原阶段，以免被标为完成或失败。
35. 作为用户，我希望实际暂停后可一键继续当前运行，以便无需重新选择配置或重复确认。
36. 作为用户，我希望继续接续尚未完成的阶段并复用成功调用，以免重复开发、评价或扣费。
37. 作为用户，我希望恢复中与恢复已经生效分开，以免启动请求被当作运行成功。
38. 作为用户，我希望恢复失败保留原工作现场并说明原因，以便作出下一步选择。
39. 作为用户，我希望请求超时后先确认实际状态，以免重复启动执行。
40. 作为用户，我希望多次点击或多页面操作不会产生两个执行者，以免重复工作。
41. 作为用户，我希望浏览器刷新或连接中断不改变运行，以便任务不依赖页面持续打开。
42. 作为用户，我希望单独确认停止，并看到它是否实际生效，以免误操作或误判执行已结束。
43. 作为用户，我希望停止后的执行未知得到明确说明，以免继续或重试造成重复执行。
44. 作为用户，我希望运行已经结束时不会把继续偷偷变成新运行，以免改变工作范围。
45. 作为用户，我希望只读或历史运行不能控制时有简明原因，以免点击无效按钮。
46. 作为用户，我希望详情打开时仍能使用桌面运行控制，以便无需退出诊断现场。
47. 作为用户，我希望桌面主体固定、长内容在面板内滚动，以便保持工作定位。
48. 作为用户，我希望窄屏和大字号下仍能阅读和操作，以免为了单屏而裁切重要内容。
49. 作为用户，我希望浅色和深色主题具有一致的语义和可读性，以便适应不同使用环境。
50. 作为用户，我希望键盘操作、Escape 和焦点返回可靠，以便不用鼠标也能完成主路径。
51. 作为用户，我希望减少动态偏好被遵守，以便动画不会妨碍使用。
52. 作为用户，我希望刷新和主题变化不抢走选择或阅读位置，以便持续查看长内容。
53. 作为用户，我希望正式工作台没有演示工具栏、模拟计时和虚假活动，以便相信看到的状态。
54. 作为维护者，我希望既有只读接口、恢复和计量契约保持有效，以便新工作台不破坏其他消费者。
55. 作为维护者，我希望用轻量受控执行贯通真实接口与 Engine，以便验证框架行为而无需先运行正式研究。

## Implementation Decisions

### 已确认的产品与视觉边界

- 在现有 React 工作台中集成，使用已经确认的单文件原型作为视觉/交互参照；不直接将原型脚本提升为生产控制逻辑。工作列表/紧凑时间线是首版主视图，Worker 紧凑活动区桌面同屏；不额外建设完整 DAG 主视图。
- 顶部保留任务/运行选择、实际状态和最小控制；左侧导航默认紧凑可展开。详情是按需非模态右侧栏，不遮挡桌面控制；文件阅读替换中央工作区，返回恢复原现场。窄屏按阅读顺序重排，不用缩字号或裁切兑现单屏。
- 浅色默认、深色可切换，沿产品 CSS 语义变量统一颜色、字体、密度及动效；不引入独立 token 生成管线。可保存主题偏好，保留既有偏好，不持久化一份运行状态。选择/导航复用 URL 与历史，滚动和面板焦点是局部交互状态。
- 新增内容按需读取；数据更新不自动移动选择或阅读位置。减少动态去掉非必要空间移动与循环；快速切换中断上一过渡，不等待动画完成才提交业务动作。必要焦点、模态清理不依赖动画结束事件。
- 所有产品入口均不展示证据链、审计轨迹、主张版本溯源、审核逐项记录、哈希、内部身份/完整性元数据、原始账本/回执/事件包或内部检查报告。删除对应展示和导航，不是默认折叠。原型演示栏、样例材料及模拟请求时序不进入正式页面。
- 页面只消费结构化白名单中的用户状态、任务内容、必要错误和产出。底层的证据、主张及交付记录按 S1–S4 契约保留；已有 API 的内部字段可保持兼容，但不通过递归 JSON、通用 artifact 清单或工具提示重新进入 UI。
- 任务测试命令及其错误片段可展示，系统内部验收/归属/完整性材料不可展示。混合内部检查与任务内容的报告不作为通用阅读原件，应从已登记的任务内容中提供必要结果或片段；不改写原文件，不要求额外 Worker 生成 UI 报告。

### 工作、调用与活动的事实投影

- Run/Attempt、工作身份、Call、后端 session 和工具动作分别保留，沿已有记录关联；不新增独立 Agent 存活数据库或另一套工作状态。UI 标签是有来源的投影，不回写业务状态。
- 工作阶段必须区分等待、执行、待评价、待反馈、已完成、真实失败和未知；使用已有阶段/事件和调用结果，不能将未 decided 一律显示 unknown，也不能仅凭历史 node_waiting 判断当前仍阻塞。
- 同一角色的并行调用各自显示，运行级 Expert 活动不强行分配到单个 Attempt；工作与 Worker 双向定位。当前无调用不意味着进程被冻结、Agent 离线或会话消失。
- 对工具活动提供动作类别、对象或命令、开始/结果状态、结果摘要、可用的退出信息与时间。工具 ID 在一次 Call 内关联开始和完成，不靠行号、文本相似或模型猜测。调用失败与工具失败分开，未知事件保留底层原件但不直接渲染原始 payload。
- 派发、未见结果与实际存活是不同事实；“正在执行”须有可靠运行端依据，否则显示已开始/结果待确认。最近已结束动作不能显示为仍在执行；同一调用多动作并行时保留未结束动作的入口。
- 后端事件时间缺失时不补造；按顺序展示或明确为观察时间。刷新时间、文件修改时间不得充当动作时间。没有活动能力的后端如实提示，不增加心跳猜细分动作。
- 在调用开始时由可信运行端建立 Call 与本次独立日志位置的关联，后端 session 标识在可用时关联补齐；不等待最终回执才使当前调用可读，不把 ArcHa Call ID 当作后端 session ID。沿已有日志隔离、访问权限、替换/截断及归属检查处理旧记录；不采用最近日志，不放宽匹配，不为此重复复制日志或加哈希。
- 当前活动只增量读取完整事件，复用游标与有界内存投影；首次进入提供有界的最近活动结果，日志过多时明确不完整，不能全量扫描结束后才显示现场。进程重启后可以重建派生缓存，但不建立新的持久业务状态库。未展开的历史材料不扫描或读取正文。

### 查询合同与内容导航

- 延续现有观察接口主版本和 Envelope 错误/分页语义，新增明确的工作台读模型，不强迫旧消费者迁移。具体 API 资源约定如下；数字上限继承既有分页与内容读取限制，不另造一套无限返回规则。

| 操作 | 必要查询合同 |
| --- | --- |
| GET /api/observer/v1/runs/{id}/workbench | 所选运行的用户状态/结果摘要、最后观察信息、控制能力及不可用原因、当前/最近 Worker 摘要；不包含完整上下文或全量历史日志 |
| GET /api/observer/v1/runs/{id}/work-items | cursor/limit 与全部/需关注筛选；稳定工作身份、标题、阶段、等待/阻塞原因、必要依赖引用、关联 Call 引用；顺序稳定，不以刷新改动用户位置 |
| GET /api/observer/v1/runs/{id}/attempts/{number}/inspection | 可选所选 Call，默认最近相关调用；提供错误、必要交接输入输出、调用选择项及任务材料/产出引用；跨运行或不关联的 Call 拒绝，不能混用最新输入 |
| GET /api/observer/v1/calls/{id}/activity | 默认有界最近活动，cursor 可增量继续；提供未结束动作与最近完成摘要、可用性及截断/重置反馈，不返回供 UI 递归渲染的原始事件包 |
| 已有 artifact/content 读取 | 复用已确认属于用户任务内容的引用和局部读取/下载能力；读取不能执行、修改原件或暴露通用内部材料列表 |

- DTO 的程序用身份和时间可用于精确关联，UI 不将其当作阅读内容。筛选改变真实结果集合，不仅改变装饰或本地已加载的第一页；按稳定游标取后续记录。
- 必要交接从保存的所选调用输入/输出读取，区分传入材料与已记录工具动作，不声称掌握模型完整隐藏上下文。旧调用输入缺失时明确不可用，不从当前工作文件重建历史。
- 材料是否可展示由其已登记用途、所属任务/调用和内容类型确定，不猜文件标题或靠扩展名判断证据/任务材料。未分类或无法确认的内部对象不出现在工作台清单；任务材料不全时说明该材料不可用。
- 任务代码材料绑定已登记的工作版本或受限工作文件，优先复用既有候选/成果保存和版本读取能力，不为工作台另存完整源码快照；旧版本无法取回时提示不可用，不能悄悄读当前工作树。版本身份留在内部，用户看到有意义的文件名称和内容。
- 继续复用现有授权目录、只读内容读取和可信渲染边界；任务材料中的链接也须遵守展示范围，不能通过 Markdown 链接或下载按钮绕回内部审计材料。HTML/SVG 等不作为可执行页面打开。
- 完成状态与可读未完成原因消费 S4 现有结果，不重新检验或产生报告副本；工作结果、候选、运行关闭与交付完成不混同。展示用户产出，不展开审核记录或主张版本历史。

### 控制入口、持久事实及轻量执行承载

- 保持现有 loopback 服务和只读访问边界。原只读入口默认不取得执行能力；新增明确的运行控制启动模式，在同一服务中启用控制路由。演示数据、只读快照及缺少执行能力的历史运行不显示可用的真实控制。浏览器页面加载/GET 绝不启动任务或初始化执行数据。
- 新增 POST /api/control/v1/runs/{id}/requests，动作仅 pause/resume/stop；输入 request_id 与明确目标运行。新增 GET /api/control/v1/runs/{id}/requests/{request_id} 查询本次反馈。首次接收可返回 202，重放已知请求返回原请求结果；参数错误、能力不足/只读、运行不存在、状态冲突分别返回明确的 HTTP 错误，不用 200 冒充成功。
- 请求反馈包含关联身份、动作、接收/处理/生效或失败/未确认情况，以及可读原因和当前运行观察。相同 request_id、相同目标和动作返回同一请求；相同身份换动作/目标拒绝。身份仅供程序关联，不显示在界面。
- 写入只接受服务端固定项目中的合法目标，不接受浏览器提供任意项目路径、shell 命令、Worker 配置或账本位置。写接口校验浏览器同源和合法 Host/JSON 请求，不开放跨域写能力；不新增远程多用户平台或登录系统。
- 复用既有 SQLite 事务与事件，最小扩展控制请求关联、应用结果及恢复结果；control 仍表达当前指令，Run 仍表达实际状态。请求的传输/处理反馈不是第二套运行状态。受理/去重在事务中完成，沿事件顺序处理并发意图，不用前端时间推断先后。
- 活跃 Engine 消费控制请求，只有运行端登记实际应用结果。启动/恢复入口复用 Engine 和既有 CLI 的配置解析及控制规则，CLI 入口的运行也能被同一控制路径观察/控制；不另做调度器。
- resume 使用一个独立于 HTTP 请求和浏览器连接的本地执行子进程，明确选择原 Run，使用既有环境/冻结配置并取得项目单写入权。该进程推进 Engine，暂停、停止、结束或真实阻塞后退出；不引入常驻编排服务、任务队列或按请求无限线程。HTTP 服务重启/连接断开不被解释为用户停止，运行进程不依赖请求线程存活。
- 保留最小的启动请求关联及可靠结果登记；服务重启后从已有记录查询，不只依靠内存进程句柄或 PID 判断执行。程序无法确认是否已启动/已结束时标为未确认，禁止自动补发执行；明确失败且未启动的请求可由用户以新的请求重试。
- 项目单写入权防止并行控制器；相同请求重试不再启动，相同运行已在执行返回实际情况，其他运行占用时明确失败，不排队、不抢占。旧请求不能把后来收到的 pause/stop 覆盖成 run；Engine 启动/重入须核对本次关联的指令是否仍有效。
- 控制被后续不同指令替代时保留本次请求结果并按当前有效指令执行，不能把旧的 run_paused 当成本次暂停已生效。启动前、锁获取、恢复前置处理和运行循环中的失败都要回到同一请求反馈边界，不能遗留永久处理中或伪装成功。

### 暂停、继续与停止

- 暂停先反馈正在提交/请求已收到，实际运行状态维持最后已知值。Engine 在派发边界阻止新调用，允许已派发 Worker/评价调用收尾并保存回执，之后才显示实际暂停；一次 Worker 调用内仍可有多个工具动作，不能模拟工具级冻结。
- 等待暂停期间实际活动和用量正常记录；工作保留原阶段，成功调用不重做，暂停不当作工作失败或交付完成。若仍有执行未知项，即使 Run 记录为 paused，也不得声称所有执行均已结束。
- 暂停请求等待时不重复提交、不增加撤销暂停模式；继续在实际暂停且恢复条件允许后可用。已处于目标状态的合法请求返回当前情况，不制造新的执行。
- 继续复用同一 Run、冻结配置、预算累计与可靠回执，接续待评价/待反馈等实际阶段；不新建 Run、不自动换后端、重置额度、开启额外终验/修复授权或重复实施。
- 恢复中和恢复生效分开。当前 Engine 在恢复处理前写 active，实施时需新增准确的恢复结果事实，不能仅凭 active 或进程创建成功将请求显示为已生效。恢复后立即结束/阻塞时直接显示实际结果，不强制播放运行中。
- 恢复失败显示简明原因、保留选择和已有内容；只在有依据时提供重试或相关工作入口。请求超时先查询同一身份，不盲目重新 POST。停止/暂停在恢复过程中到达时，后到有效指令不得被旧恢复入口清掉。
- 停止先单独确认，再反馈请求/实际结果；活跃执行按既有取消规则结束并阻止后续派发。暂停且无在途执行时，也必须由 Engine 控制入口完成关闭，不能只写无人消费的 stop，更不能先恢复派发工作才能停止。
- 已 closed 的运行不重开，不把继续偷换成重新开始。停止时终态无法确认则保留已有工作区、回执和未知事实，不准据按钮或倒计时认定已结束；界面展示可读问题，不展示内部检验细节。停止不自动重置预算或宣称交付成功。
- 控制申请和观察读取的失败分别表达；页面不把观察故障写回业务结果。成功工作不能因渲染或读取失败被改判失败，必要事实持久化失败按既有运行契约暴露真实错误。

### 集成与清理

- 拆分现有大页面时只提取当前切片需要的展示组件和查询边界，不预建组件库、通用事件平台或独立重构项目。每条切片从真实记录或受控执行贯通 HTTP 与页面，不按数据库/API/UI 分层分票。
- 每票删除已被替换且无消费者的旧展示与重复状态转换；保持旧只读 API 的必要兼容性，不为避免清理永久保留两套前端或后台监听。全工作台遵守无证据/审计/哈希边界，不限于新页面。
- 正式前端构建、静态资源打包及现有启动入口同步覆盖；演示与真实模式清楚区分，不把原型文件作为生产首页。无依据不升级依赖，不启动真实模型或正式研究。

## Testing Decisions

### 已确认的测试边界

- **主验收边界是既有浏览器 → 本地 HTTP → Engine → 可观察工作结果这一条贯通路径。** 使用普通临时项目、真实 SQLite/文件、受控脚本 Worker/假 CLI 和小型评价器，经过真实控制入口和独立执行进程；只替换模型/外部执行的不可控部分，不 mock 掉 Engine、HTTP 响应或恢复逻辑。
- 浏览器重点覆盖两条用户场景和停止最小分支。将难以稳定安排的并发、失联、启动失败和重复请求，通过同一个本地 HTTP 入口验证请求结果与实际调用次数，不用每个故障都跑一整套浏览器脚本。
- 少量下层测试只补日志归属、增量分页、输入归属/材料范围等高层难以精确触发的情况，复用 ObserverAdapter 与既有 Engine/进程测试，不测试私有函数顺序或锁死表结构。
- 历史 HTTP TestClient 曾出现 AnyIO 等待，不能沿用排除项就声称新控制通过。优先扩展已有真实 loopback HTTP/浏览器测试方式，明确服务就绪/退出与有限等待；确实不能运行时报告未验证，而非只用 adapter 结果替代 HTTP 验收。

### 行为覆盖与现有基础

- 好测试断言用户可见阶段、动作、错误、材料、控制反馈和真实执行次数/结果；不只断言某字段存在或模拟定时器到期。不为可逆外观改动新增镜像实现的单元测试。
- 工作场景：串行失败与并行依赖、单角色多调用、运行级 Expert、旧等待已解除、待评价/待反馈、空态和历史只读；来源不完整如实提示。
- 活动场景：调用未结束时就可读、开始/完成关联、并行动作、无时间戳、未知事件、半行、截断/替换、错误日志归属拒绝、长日志首次与增量读取有界；刷新不遍历未选历史原件。
- 诊断场景：两次不同输入的调用选择，查看失败那次必要交接，打开关联任务文件/产出并返回；保持工作、筛选、阅读位置与焦点；无关输入不可串入。任务材料链接、隐藏面板和渲染后的工具提示同样不暴露禁止内容。
- 控制场景：请求收到不等于生效；Designer/评价及并行调用在途暂停，无后续派发；继续复用可靠结果与同一运行，原额度/配置/意图保持；恢复前失败、恢复中失败、立即完成及真实阻塞。
- 并发与进程场景：同请求重放、不同参数复用身份拒绝、多页面并发、单写入占用、HTTP 超时/断连、服务重启后查询、未确认执行禁止自动重发；恢复过程中暂停/停止不被旧 run 指令覆盖。
- 停止场景：取消确认、活跃调用停止、暂停状态停止、恢复中停止、结束后重复停止、终态未知保留；停止不是交付成功，不通过恢复隐式执行任务。
- 只读及输入边界：GET 不创建运行/修改原件，未启用控制/演示/不可恢复历史不可执行；跨源写、错误目标和任意路径/命令输入拒绝；复用内容渲染及目录范围检查，不添加全库哈希验证。
- 界面：已确认布局、浅深主题、长中文/代码、桌面固定壳体和局部滚动、窄/短视口、放大文字、键盘/Escape/模态焦点与返回、快速开关、减少动态、详情打开时控制可达；浏览中刷新不抢位置，主题变化不重播活动。
- 既有测试基础包括 Observer 的普通项目/并发追加/游标与旧内容归属用例、生产前端 loopback 浏览器检查，以及 Engine 的暂停后恢复、在途 Designer 不派发评价、在途评价不派发 Expert、并行收尾、未知停止与工作区保留用例。旧浏览器脚本中证据导航、内部哈希展示及纯 GET 页面断言需按新的产品范围更新，相关底层只读/安全保障仍验证。
- 每票验证自身切片；六票完成后执行组合贯通和相关框架回归、前端类型/构建与静态资产检查，不另建一票空泛的测试工程。新增或修改的 HTTP 控制不能以历史排除理由跳过。
- 首版不要求真实模型、真实 DSH 安装/登录或正式研究考试。DSH 继承既有阶段例外，使用已有记录与公共投影夹具覆盖其可识别事件，不新增专用真实后端集成验证；公共控制逻辑与假 CLI 必须验证。受控执行证明框架行为，不证明模型科研判断。

## Out of Scope

- 证据/审计/哈希界面、主张版本历史阅读、内部审核/检验材料展示，以及隐藏的高级审计入口。
- 知识编辑、手改 DAG、任意实验启动、自由停靠、完整第二套 DAG 主屏、3D/装饰大屏、主题编辑器或新聊天入口。
- 新业务引擎、常驻编排服务、通用队列、独立 Agent 生命周期库、平行知识/控制数据库或全库扫描。
- 工具级暂停、进程冻结、自动将暂停升级为停止、自动切换后端、自动新建运行或重置预算。
- 通用网络管理、远程多用户平台、登录系统、网页任意命令/文件路径访问或新的 Worker 工具权限。
- 重写 S1–S4 契约、重新审核历史成果、重跑旧测量、为 UI 额外生成报告或要求 Worker 输出内部思维。
- 直接上线原型的模拟数据/状态控制、以夹具冒充真实运行验证、正式研究考试或 DeepStack 建模探索。
- 未经用户另行要求的提交、合并、部署或发布站点。
