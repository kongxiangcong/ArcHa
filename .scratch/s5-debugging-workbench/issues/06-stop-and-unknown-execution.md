# 06: 停止运行与未确认执行收尾

**What to build:** 用户单独确认停止后，能在运行中、已暂停或恢复中停止同一运行，并看到实际结束或无法确认的事实，保留已有结果与现场。

**Blocked by:** 05：继续同一运行与恢复失败处理

**Status:** resolved

实施与测试共同遵循 [S5 规格](../spec.md)，本票验收重点如下。

- [x] 停止需独立确认；取消确认不提交，确认后沿统一控制请求/查询反馈，接收不等于实际结束；详情打开时控制仍可达，模态焦点与返回可靠。
- [x] 活跃运行由 Engine 按既有取消契约停止并禁止后续派发；已暂停且无在途调用时通过 Engine 控制入口关闭，不仅写无人消费的指令，也不先恢复派发任务才能停止。
- [x] 恢复过程中到达的有效停止不得被旧恢复入口重置；去重、锁竞争和失败沿已有控制事实表达，不启动第二个执行者，不暗中排队。
- [x] 终态未知保留必要工作区、回执与未知事实并展示可读原因；不凭按钮、倒计时或连接断开宣称结束，不暴露内部检验材料。
- [x] 已关闭运行重复停止返回真实情况，不重开；停止不意味着交付成功、不重置预算，不将继续偷换成重新开始，也不因暂停等待过久自动升级停止。
- [x] 通过真实 HTTP/Engine 验证活跃、暂停、恢复中、已关闭及终态未知分支，断言无额外派发和工作区保留；浏览器验证确认/取消、实际结束与未知反馈。
- [x] 全部切片就绪后跑两条组合用户路径及停止分支、相关框架回归和前端类型/构建/静态资源检查；验证全工作台信息边界与只读默认。报告未验证项，不以原型模拟或历史 TestClient 排除替代控制 HTTP 验收。
