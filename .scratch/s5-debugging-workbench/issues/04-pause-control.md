# 04: 暂停请求到实际生效

**What to build:** 用户请求暂停后先看到请求反馈，再看到 Engine 收住在途调用后的实际暂停状态；失败或未确认时得到可读原因。

**Blocked by:** 01：真实工作现场与清爽布局

**Status:** resolved

实施与测试共同遵循 [S5 规格](../spec.md)，本票验收重点如下。

- [x] 显式启动控制模式才启用控制请求和查询；既有只读入口、演示及不可执行历史保持不可控，GET 不启动任务或初始化执行数据。固定项目、合法目标、同源/Host/JSON 边界拒绝任意路径、命令和配置。
- [x] 按规格接收、持久化去重和查询暂停请求；相同身份和参数返回同一结果，身份复用但参数不同拒绝；区分接收、处理、生效、失败及未确认，保留关联结果而不建立第二套运行状态库。
- [x] 活跃 Engine（含既有 CLI 入口）消费请求，在派发边界禁止新调用；在途 Worker/评价调用正常收尾、保存结果并计量，随后登记与本次请求对应的实际应用事实，旧暂停事件不能冒充本次生效。
- [x] 顶部反馈区分请求已收到和实际暂停；等待时保留真实阶段与活动，不模拟工具冻结或进度，不重做成功调用，不将暂停当作失败/交付完成。未知执行即使 Run 为 paused 仍明确提示。
- [x] 同请求重放、多页面提交及后续指令按持久事实/事件顺序处理；请求超时查询原身份，不盲目重新执行；已暂停的合法请求返回实际情况。阶段性未实现的继续/停止不能显示为可用能力。
- [x] 用真实 HTTP → Engine 和受控执行验证 Designer、评价及并行调用收尾且无后续派发；验证重复请求、参数冲突、只读/跨源拒绝、持久化与观察失败、旧事件不误报生效，浏览器覆盖请求到实际暂停。
