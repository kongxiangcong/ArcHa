# 05: 继续同一运行与恢复失败处理

**What to build:** 用户从实际暂停继续原运行，看到恢复中、真实生效或失败，浏览器断开也不改变执行；既有成功工作和用量得到保留。

**Blocked by:** 04：暂停请求到实际生效

**Status:** resolved

实施与测试共同遵循 [S5 规格](../spec.md)，本票验收重点如下。

- [x] 继续复用控制请求与反馈，以独立于 HTTP 请求/浏览器的本地子进程重入明确的原 Run，沿既有配置解析与项目单写入权；无需重复确认，不引入队列或常驻调度器。
- [x] 沿冻结配置、累计预算和可靠回执接续实际阶段，不新建 Run、换后端、清额度、重复成功调用/计费或增加终验及修复授权；暂停、结束或真实阻塞后执行进程按约定退出。
- [x] 明确记录恢复结果；进程创建或提前写 active 不等于恢复生效，立即完成/阻塞直接显示实际结果。锁获取、启动和恢复前置/循环失败都进入同一反馈边界。
- [x] 同请求重放不二次启动；同运行已执行返回事实，其他运行占锁明确失败且不排队。HTTP 超时、断连和服务重启后仍能查询持久结果，不仅凭内存句柄或 PID 判断执行。
- [x] 无法确认是否已启动时保持未确认且禁止自动重发；明确未启动的失败允许用户以新请求重试，保留选择、材料和原因。恢复过程中后到的暂停不得被旧 run 指令覆盖。
- [x] 恢复入口保留统一的有效指令检查，使后续停止切片可复用；本票不模拟尚未实现的停止成功。
- [x] 经真实 HTTP 和独立受控执行验证同一运行/额度/配置/成功结果复用、恢复失败/立即结束、重复和并发请求、锁占用、断连、服务重启及恢复中暂停；浏览器覆盖暂停→继续和失败返回现场。
