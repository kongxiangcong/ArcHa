## Problem Statement

研究者需要先理解探索专题的目标、当前认知状态及历轮探针与结果，再按需查看原件或排查执行。当前工作台将材料和日志平铺，研究脉络与底层执行细节缺乏层次；界面改版又容易遗漏已有的停止、恢复、预算追加与探针断点调试能力。

当前 Worker 配置围绕 Codex 预设组织，难以清楚地接入 DSH 或自定义 CLI。研究者希望利用本机已有登录配置和工具链，在不同角色或轮次间选择执行工具，同时保留文件权威、原子提交、失败恢复和轻量本地部署。进程退出、研究产物发布与研究完成必须明确区分，不能因一条成功事件误报研究进展。

## Solution

将工作台组织为三级阅读：L0 默认呈现目标、认知状态和最新轮在前的探针／结果原文摘录；L1 按需打开原件、附件和证据链接；L2 仅由用户主动展开，查看该轮各角色最近一次调用的追加式事件与原始日志。保留已有控制操作、只读模式和材料阅读能力，轮询不抢焦点、不重置阅读状态。

以 Codex、DSH、custom 三个 Provider 替换旧预设。统一从 stdin 读取任务、按文件协议交付研究产物、继承宿主环境，并保持现有研究调度与提交语义。事件是可丢失但须如实标示完整性的派生观测，不决定研究推进；每种角色只保存最近一次调用，不建立历史执行账本。

## User Stories

1. 作为研究者，我希望首屏看到目标原文摘录，以便确认当前探索解决什么问题。
2. 作为研究者，我希望从认知状态的既有小节阅读事实、解释和待解问题，以便了解当前认识。
3. 作为研究者，我希望同时看到轮次预算与已完成轮数，以便判断剩余探索空间。
4. 作为研究者，我希望最新探索轮次排在前面，以便快速找到当前工作。
5. 作为研究者，我希望每轮同时展示探针和已有结果的原文摘录，以便沿证据理解研究演进。
6. 作为研究者，我希望摘录明确标注来源和截断，以便不会将其误认为模型重新总结的核心结论。
7. 作为研究者，我希望缺失结果显示尚未提交，以便不会把进程成功误认为轮次完成。
8. 作为研究者，我希望点击卡片即可阅读完整原件，以便核查假设、观测和认知变化。
9. 作为研究者，我希望继续访问反馈材料、实验附件及 Markdown 证据链接，以便不因改版丢失证据入口。
10. 作为研究者，我希望长文和日志按需分段读取，以便大文件仍然可读。
11. 作为研究者，我希望代码得到高亮且可复制材料路径，以便回到工程中复现。
12. 作为研究者，我希望只有主动打开时才显示执行 Trace，以便运行或失败不打断阅读。
13. 作为研究者，我希望已打开的 Trace 持续更新，以便观察真实工具活动。
14. 作为研究者，我希望了解当前调用使用的 Provider 和可取得的耗时、用量，以便排查执行差异。
15. 作为研究者，我希望工具开始与结束按发生顺序出现，以便不依赖复杂工具卡片也能理解执行过程。
16. 作为研究者，我希望 Expert、Executor、探针重拟和收尾消化的 Trace 分开呈现，以便不会把角色调用混成新轮次。
17. 作为研究者，我希望同角色重试后看到新调用的完整可用事件，以便旧游标不会漏掉新事件或混入旧轨迹。
18. 作为研究者，我希望刷新或重连后恢复当前保留调用的事件，以便继续观察而不重复记录。
19. 作为研究者，我希望旧调用没有结构化事件时明确提示并仍可读日志，以便历史研究无需迁移也能查看。
20. 作为研究者，我希望观测故障显示 Trace 不完整但研究继续，以便展示故障不损害实验结果。
21. 作为研究者，我希望研究状态、当前活动、最近错误和断点等待分别展示，以便准确判断下一步。
22. 作为研究者，我希望无法确认执行归属时保留 unknown，以便界面不会错误宣称空闲。
23. 作为研究者，我希望未运行的 IN_PROGRESS 专题不播放运行指示，以便动效反映真实活动。
24. 作为研究者，我希望保留停止和继续操作，以便中断后仍可继续原待执行探针。
25. 作为研究者，我希望预算耗尽时显式追加轮数，以便继续探索仍有明确成本边界。
26. 作为研究者，我希望完成专题保持关闭，以便恢复操作不会意外重开已完成研究。
27. 作为研究者，我希望启用探针断点调试并提交方向意见重拟，以便在实验前调整设计。
28. 作为研究者，我希望重拟后再次停下且不消耗新轮次，以便先检查调整结果。
29. 作为只读使用者，我希望未启用控制或演示模式下仍可查看材料，以便不会误触研究操作。
30. 作为研究者，我希望轮询保持滚动、焦点和展开状态，以便持续阅读不被刷新打断。
31. 作为研究者，我希望使用明暗主题并尊重减少动态效果设置，以便舒适地阅读长时间研究记录。
32. 作为研究者，我希望为 Expert 和 Executor 分别选择 Codex 或 DSH，以便利用不同工具的能力。
33. 作为研究者，我希望在不同轮次切换 Provider 时仍使用已有研究材料，以便无需迁移聊天会话。
34. 作为新用户，我希望默认两个角色均使用 Codex，以便不因未安装 DSH 而无法开始。
35. 作为研究者，我希望显式配置模型、超时、环境覆盖和 Codex 推理强度，以便适配实际任务。
36. 作为研究者，我希望通过 custom 接入文件协议脚本，以便复用现有工具和可复现实验。
37. 作为研究者，我希望长任务文本通过 stdin 传入，以便不会因命令行长度限制启动失败。
38. 作为研究者，我希望 Agent 实际使用本机登录配置及工具链，以便无需复制凭据或重建隔离环境。
39. 作为研究者，我希望 CLI 无头执行且沿用所选权限配置，以便不会后台等待交互或擅自扩大权限。
40. 作为研究者，我希望最终聊天不会覆盖探针、结果或认知状态草稿，以便保留真实研究产物。
41. 作为研究者，我希望进程失败、超时、取消及非法产物不污染已提交材料，以便可以可靠恢复。
42. 作为研究者，我希望日志洪峰下仍能停止或触发超时，以便诊断机制不会拖住执行控制。
43. 作为维护者，我希望旧配置明确报错并有人工迁移说明，以便无需维护双轨运行逻辑。
44. 作为现有用户，我希望升级不自动覆盖工程配置或改写历史材料，以便保留自己的执行选择。
45. 作为维护者，我希望安装后的固定运行时包含全部新模块，以便源码运行成功也能在用户工程复现。
46. 作为维护者，我希望通过已有 CLI、HTTP 和真实浏览器测试验证可观察行为，以便重构不依赖内部实现形状。

## Implementation Decisions

### 研究与执行职责

- 沿用 TopicEngine、TopicWorkspace 的研究语义、调度、轮数计算、原子提交、恢复与工程串行约束。Provider 不接管研究决策；不增加发布事件钩子或研究状态源。
- Worker Invoker 负责配置选择、暂存产物与 Provider 调用；Provider 负责命令构造及原生输出行解析；公共 Process Runtime 继续管理进程树、停止与超时。新增旁路 Telemetry，扩展 Observer 投影和 Workbench 阅读界面。
- 保留四种调用角色 expert、executor、expert_revise、expert_finalize。两种 Expert 特殊调用沿用 Expert 配置；重拟属于当前待执行轮次，收尾属于最后已完成轮次，不增加探索轮次。
- 进程结果为 completed、failed、timed_out、cancelled。零退出且未超时／取消才是 completed；不得直接沿用底层把所有进程结束记为 completed 的结果。启动失败提供实际错误；有退出码时保留退出码。
- 进程结果只描述进程，不保证产物提交。Worker 产物检查与 Workspace 校验仍在后续完成；非零退出、缺失／空产物、非法状态及中断不得发布草稿，重试不得复用失败残留产物。
- 研究状态继续为 IN_PROGRESS、COMPLETED、BLOCKED、BUDGET_EXHAUSTED；当前活动保留 idle、running、stopping、unknown。最近错误、取消与断点等待另行展示，不通过“有错误”推断 failed，不以 IN_PROGRESS 推断运行。研究完成不代表代码合并或发布。

### Provider 与配置

- 默认配置直接采用 expert、executor 两个顶层角色对象，均为 codex。移除旧 roles 包装、preset、input_mode 和 output_mode；遇到旧格式在派发前明确拒绝并指向人工迁移说明，不自动转换或覆盖工程配置。
- 每个角色要求 provider，支持 model、timeout_seconds、env；默认模型为空表示沿用 CLI 配置，默认超时为 1800 秒，超时允许正的有限数值。env 是叠加到宿主环境的字符串映射。reasoning_effort 仅用于 Codex；不支持的 Provider 选项明确报错，不静默忽略。
- custom 要求非空 argv 数组 command，直接执行而不拼接 shell 命令。保留工作目录、专题目录、提示词文件、输出文件和状态文件的路径占位符，以及已配置的 model 参数占位符；缺失值或未知占位符在配置边界报错。移除 stdout 产物模式和专用 scripted 生产预设，确定性测试使用 custom 或替身 CLI。
- Provider 请求包含调用角色、专题与工程目录、提示词和暂存产物位置及已验证的角色配置；启动描述包含 argv、cwd、环境覆盖。不引入尚无消费方的能力声明、插件注册表或会话恢复协议。
- 所有任务正文从已打开的提示词文件接入 stdin，禁止将正文放入 argv。Codex 使用无状态执行与 JSON 输出；DSH 使用无头执行、stdin 与原生 JSONL。custom 也读取 stdin，临时提示词文件在调用结束后清理。
- 三个 Provider 都通过 Agent／脚本写入暂存文件交付产物。禁止用 Codex 最终聊天输出选项指向协议产物；最终消息只作为日志，不回填产物。
- 完整继承宿主环境，再叠加显式配置；不创建私有 HOME、凭据副本或环境白名单。沿用用户所选 CLI 权限，明确无交互执行；权限不足应暴露失败，不能自动放宽权限重试。
- DSH 模型覆盖通过其原生配置接口传递，不假设与 Codex 具有相同参数。真实联调须证明覆盖生效、登录可用，以及 Agent 内部 shell 能访问实际需要的工具；仅检查入口进程环境不算通过。
- 工程配置优先于分发默认配置；初始化与显式运行时升级继续保留已有配置。安装分发清单加入全部 Provider 和 Telemetry 模块，同步既有使用说明、演示和测试配置。一次性人工迁移说明列明删除字段、保留字段及 custom 参数用法。

### 日志、事件与增量协议

- stdout/stderr 从现有双线程管道读取改为操作系统文件描述符直写同一原始日志。错误上下文称为日志上下文，不声称能从混合日志精确分离 stderr。
- 每轮每种调用角色拥有确定性的日志及同目录 JSONL 事件文件。每次新调用替换该角色的上一份内容，不与其他角色合并；原探针、结果等研究材料仍按现有提交协议管理。
- AgentEvent 保留 seq、ts、kind、title、status、detail 六字段。kind 为 lifecycle、tool、usage、diagnostic；status 为 running、ok、error、info；detail 为可空文本。seq 在单次调用内递增，尾随器统一分配；状态字段与 title/detail 共同描述四类进程结果。
- 首版为追加式列表，工具开始和结束可以是独立事件，不关联成可变工具卡片。Provider、耗时、用量只显示确实取得的信息，不从自由文本反向解析独立指标。custom 不解析工具事件，只显示公共生命周期、必要诊断及原始日志。
- 每次调用在替换事件文件时先写启动 lifecycle。其 ts 使用足够精度、每次调用不同的启动时间值，同时作为不透明 stream 标识；同一角色的新调用必须更换它，不增加事件字段、注册表或内容哈希。文件替换与首条事件发布应避免读到旧流与新流混合；复用文件原子替换方式。
- Observer 新增 GET /api/observer/v1/topics/{topic}/steps/{step}/events，接受 role、after_seq 和可空的 stream；响应包含当前 stream、reset、events、next_seq、more 和必要的诊断。角色限定为四种已有调用角色，after_seq 为非负整数并默认为 0，沿用现有材料访问边界。
- 首次读取返回当前流及起始批次；stream 相同只返回大于 after_seq 的事件；不相同返回 reset 并从当前流开头读取。没有事件文件返回空流与空列表，旧游标不能继续生效。客户端以“专题、轮次、角色、stream”隔离缓存，reset 时清空该角色旧事件，不能只检查文件变短。
- 每次最多返回 200 条完整事件，next_seq 为本批最后事件序号或当前有效游标，more 表示仍有完整事件；客户端逐批获取，忽略已切换专题、角色或请求上下文的过期响应。尚未写完的 JSONL 尾行留到下次，不当作已确认坏记录。读取期间发生文件替换不得拼接两个流。
- stream 只标识当前保留的调用；断线期间被覆盖的调用不恢复。旧调用没有事件文件时显示“此调用无结构化事件”，继续提供原始日志和研究材料，不自动回放或补建历史事件。
- 尾随工作独立于 Process 的停止／超时等待，约每 200ms 处理一批新增内容。每批读取上限 256 KiB，保留跨批行与 UTF-8 解码状态；超长未终止行设置 1 MiB 解析缓冲上限，超限内容留在原始日志并提示 Trace 不完整，不能无限积累内存。
- 进程树结束后处理已写入日志的剩余完整事件；尾随收尾最多等待 2 秒，超过预算停止观测并提示不完整，不能拖住产物校验与提交。尾随任务须受停止标志约束，不能在角色调用结束后继续写入下一次调用的文件。
- 普通非 JSON 文本与未支持的原生事件类型保留日志但不生成事件；已识别事件格式损坏、解析异常或事件文件写入失败，输出一次有上下文的诊断并标示不完整，不静默吞错。必要时停止本次事件提取，研究继续。
- 诊断不能仅依赖事件文件自身写入成功：复用当前命令诊断和原始日志记录可识别的 Telemetry 失败信息，Observer／L2 呈现该信息或缺失终止事件的完整性提示；不另建诊断账本，不把观测故障写成研究失败。原始日志也不可写时由命令诊断暴露真实失败，不承诺磁盘故障下仍可持久化诊断。

### Workbench 阅读与控制

- L0 为左侧专题导航加单列主画布，桌面导航宽 260px，阅读流最大宽 920px。展示目标、认知小节、预算和最新轮在前的卡片，不默认打开 L1 或 L2。
- Observer 对已有材料做确定性摘录：标题最多 120 个 Unicode 字符，GOAL 正文及每份 probe/result 正文最多 240 个字符；STATE 按既有认知小节各取最多 240 个字符。去掉标题标记、空白行和状态／预算元数据，合并正文空白，不做语义改写或模型总结。超过限制追加省略号并标明截断；小节为空显示暂无内容，材料缺失与正文为空分别显示。
- GOAL 优先取 Objective 小节；STATE 使用现有小节，未匹配模板时显示可取得的正文摘录，不伪造“事实”或“阻塞项”。probe/result 取首个标题及其后可读正文，代码和列表仍是原文。摘录只用于导航，完整原件始终可达。
- L1 为桌面 480px 只读抽屉，打开目标、认知状态、探针、结果、反馈、已有进展材料及实验附件。保留工程内证据链接与现有路径访问限制，长文／日志复用分段接口；支持代码高亮和路径复制。
- L2 位于抽屉内，仅由用户主动展开；当前运行或最近失败只改变徽标和诊断入口。已打开的 Trace 持续更新，轮询不得抢焦点、自动展开、强制跳到底部或重置用户滚动。
- 数据更新保持组件身份与轮次键；调用更换只清空相应事件和日志游标，保留抽屉、所选角色和焦点。不以强制重挂载或额外定时器修补动效，不建立额外对象级合并框架。
- 保留停止、继续、追加轮数、探针断点调试与方向意见重拟的现有控制接口与语义；完成专题不可重开，预算耗尽需追加，重拟后再次停下。控制禁用与演示只读模式继续生效。
- 统一明暗 CSS 令牌，颜色与尺寸沿用已确认方案；运行色只用于真实活动，空闲不呼吸。悬停只改变边框或背景，不位移或改变尺寸；抽屉过渡为 220ms，关闭立即移出交互和辅助技术访问，动画结束后卸载内容。减少动态效果设置关闭呼吸与过渡。
- 窄屏抽屉宽度不超过视口，导航可收起；关闭抽屉后焦点回到入口，支持键盘关闭。复用现有浏览器和可访问性机制，不新增布局框架。借用第三方代码或资产时保留其许可声明。

## Testing Decisions

- 用户已确认测试边界：以“已安装 CLI＋真实子进程＋专题文件”为主线，复用 Observer HTTP 和真实浏览器验收；真实 Codex／DSH 联调补充登录、模型与内部工具环境验证。不新增生产测试接口或第二套测试框架。
- 好的测试观察退出结果、已提交材料、错误信息、HTTP 响应和用户交互，不断言内部类数量、函数调用顺序、固定提示词句子或实现行数。替身 CLI 是真实操作系统进程，可控制 stdout/stderr、文件产物与退出；不能据其通过宣称真实模型已验收。
- 既有先例：已部署 CLI 测试 [test_topic_cli.py](../../opc/tests/test_topic_cli.py)，包括配置边界、失败产物不发布、日志可见、进程树清理、最终聊天不覆盖研究产物；轮次与恢复测试 [test_topic_rounds.py](../../opc/tests/test_topic_rounds.py)、[test_topic_recovery.py](../../opc/tests/test_topic_recovery.py)；HTTP 控制测试 [test_workbench_control.py](../../opc/tests/test_workbench_control.py)；真实浏览器链 [observer_browser_smoke.py](../../tools/observer_browser_smoke.py)；技能安装与固定运行时测试 [test_topic_skills.py](../../tools/tests/test_topic_skills.py)。
- Provider／Invoker／Runtime：通过已安装入口覆盖默认 Codex、两种交叉组合与 custom，验证模型／推理强度／环境参数、超过 128 KiB 的 stdin 正文，以及无最终聊天覆盖。旧配置在启动前拒绝；新安装模块齐全，升级保留原配置，人工迁移后可运行。
- 研究回归：正常一轮、收尾消化、预算耗尽与追加、已完成不可重开、停止恢复原探针、同轮多次重拟及重拟失败保留原件。非零退出、缺失／空产物、非法状态、超时、取消和重试残留均不污染权威材料；进程 completed 但校验失败时不得显示轮次成功。
- Telemetry／Observer：替身 CLI 发出真实形状的 Codex／DSH JSONL、普通文本、半行、UTF-8 分片、超长行及坏事件。断言事件顺序、custom 只有生命周期、原始日志保留，以及解析／写入故障可见而合法产物仍提交。文件写入故障使用现有文件边界注入，不新增故障控制 API。
- 增量契约：覆盖首次读取、空批次、分页、重复请求、短流替换、长流替换、断线期间多次替换、浏览器刷新及角色切换；特别验证旧游标为 100 而新流不足或超过 100 两种情况，不漏新调用前段、不混接旧流。并发追加半行及原子替换不能产生假坏记录。
- 控制及时性：大量日志持续输出时执行停止和超时，沿用现有进程树清理判据，确保没有后代继续写工程；尾随最多增加约定的 2 秒收尾等待。不用固定 sleep 推断状态已变化，沿用有截止时间的状态等待。
- Workbench 浏览器验收：真实 HTTP 服务配真实子进程，验证 L0 摘录／排序／预算、L1 原件与证据导航、四角色 L2、旧日志无事件、状态区别及全部控制动作。定时刷新前后验证滚动、焦点和展开态，运行或失败不得自动打开 Trace；验证主题、减少动态效果、关闭后焦点与窄屏布局。构建和类型检查通过不替代浏览器行为验收。
- 真实 CLI 验收：在小型临时工程跑通 Expert=Codex／Executor=DSH 及反向组合，验证产物提交；实际指定模型，执行能证明本机所需工具链可用的 shell 命令，并覆盖长 stdin 与无交互运行。记录 CLI 版本、命令、退出与产物证据，清楚区分源码核查、替身进程结果和真实联调结果；未完成联调不得宣称多 CLI 验收完成。
- 测试数据与证据按需产生，清理无用途临时文件，只保留复现需要的内容；不增加大批快照、重复报告或与实现一一对应的单元测试。

## Out of Scope

- 改变研究决策、探针轮次定义、预算规则、完成判据、恢复协议，或新增 Engine 发布事件钩子。
- 数据库、独立历史状态快照、研究账本、调用注册表、完整重试／重拟 Trace 历史、自动回填旧事件。
- 新的审批流、多租户权限、容器编排、私有 HOME、环境白名单、逐行正则脱敏及内容哈希校验。
- 旧配置运行时兼容、自动迁移或覆盖用户配置、stdout 产物模式及生产 scripted 预设。
- AI 摘要、强制新的研究文档模板、工具开始／结束合并卡片、独立用量指标系统、CLI 聊天会话迁移。
- SSE／WebSocket、DAG 编辑器、泛化插件能力声明、额外前端状态管理框架。
- 在本次规格发布中实施代码、启动真实研究或执行模型联调。
