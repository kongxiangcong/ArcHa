# 01: 通过新 Provider 配置完成 Codex／custom 研究闭环

**What to build:** 研究者通过安装后的 CLI 使用 Codex 或 custom 完成探针提出、实验执行、探针重拟及收尾消化，统一从 stdin 接收任务并以文件交付产物。新配置一次切换，现有工程获得明确的人工迁移路径，研究提交与恢复语义不变。

**Blocked by:** None (can start immediately).

Status: ready-for-agent

**规格：** [Research Workbench 与多 Provider 执行](../spec.md)。本票覆盖 Provider 基础、Codex／custom、配置与安装迁移；DSH 由 02 交付，结构化事件由 04 起交付。本票不以尚未实现的事件文件作为验收前提。

- [ ] 从已安装 CLI 完成至少一轮探针与结果提交，默认 Expert、Executor 都使用 Codex；custom 通过真实脚本进程完成同一文件协议。
- [ ] 先在本票内整理 Invoker、Provider 与 Process 职责，再完成配置和调用方的一次切换；不新增兼容预设、能力注册表或生产测试接口，不改变 Engine／Workspace 研究语义。
- [ ] 新配置直接使用 expert、executor 角色对象，落实父规格中的模型、超时、环境覆盖、Codex 推理强度和 custom argv／占位符规则。非法或不支持的选项在派发前报错，不静默忽略。
- [ ] 移除旧包装、preset、输入／输出模式和 scripted 生产预设；旧格式明确拒绝并给出人工迁移说明。测试与演示改用 custom 或替身 CLI，已安装入口和既有浏览器验收不会依赖被删除的配置。
- [ ] 提示词正文仅通过 stdin 传入，超过 128 KiB 可用；临时提示词按调用清理。stdout/stderr 直接写入原始日志，运行期间可通过既有材料入口阅读，不捕获 stdout 作为研究产物。
- [ ] Agent／脚本自行写入指定暂存产物，Codex 最终聊天不会覆盖探针、结果或状态草稿，包括输出与状态位置相同的收尾调用。
- [ ] 继承宿主环境并叠加显式覆盖，使用无头非交互调用和用户选定权限；不隔离 HOME、不复制凭据，不因权限失败自动放宽权限。
- [ ] 四种角色调用均通过新配置执行，重拟与收尾使用 Expert 配置；停止／继续、预算追加、断点重拟和收尾规则保持不变。
- [ ] 非零退出、缺失／空产物、非法状态、超时、取消及失败重试残留均不污染已提交材料；日志保留实际失败上下文，进程树退出后没有后代继续写工程。
- [ ] 新安装包含全部本票模块，工程配置优先于分发默认配置；显式升级保留现有工程配置和研究材料。人工迁移后的工程能通过已安装 CLI 运行。
- [ ] 复用已部署 CLI、研究轮次、恢复、进程控制与安装测试验证以上行为；原始日志通过现有 HTTP／浏览器链仍可读。只按可观察行为调整测试，不加入最终形态尚未交付的 Trace 断言。
