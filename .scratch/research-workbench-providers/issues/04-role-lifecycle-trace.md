# 04: 在 L2 查看四种角色的调用生命周期

**What to build:** 研究者主动打开 L2，即可看到该轮四种角色各自最近一次调用的生命周期及原始日志。重试、刷新和重连后展示当前保留调用，既不漏掉新调用开头，也不混入旧调用事件。

**Blocked by:** 01 — 通过新 Provider 配置完成 Codex／custom 研究闭环；03 — 通过 L0／L1 阅读并控制探索专题。

Status: ready-for-agent

**规格：** [Research Workbench 与多 Provider 执行](../spec.md)。本票贯通调用事件落盘、Observer 增量协议与 L2；验收使用 Codex／custom 生命周期，不以 DSH 或原生日志解析为前提。

- [x] 四种角色各自产生父规格定义的六字段生命周期事件，与各自日志同轮存放；新调用仅替换该角色旧内容，不新增索引、历史目录或注册表。
- [x] 启动事件的时间标识区分每次调用，按原子替换发布新流；seq 仅在单次调用内递增，重拟与收尾正确归属既有轮次。
- [x] 生命周期准确区分 completed、failed、timed_out、cancelled，显示可取得的退出码与上下文；启动失败可诊断，零退出后产物校验失败不得显示为轮次提交成功。
- [x] Observer 按专题、轮次和四种角色读取，落实 stream、after_seq、reset、events、next_seq、more 及每批最多 200 条的合同；沿用材料访问边界，半行等待续写，不读取成假坏记录。
- [x] 首次读取、同流增量、无事件空流和换流重置均符合父规格；读取期间替换文件不会混接两个流。旧游标为 100 时，新流不足或超过 100 两种情况都从新调用开头展示。
- [x] 客户端分页获取并隔离专题／轮次／角色／流缓存，忽略过期请求响应；刷新、断线期间多次替换和角色切换后没有混流或重复事件，不恢复已被覆盖的历史。
- [x] L2 仅由用户主动展开，显示四角色最近调用的生命周期和对应原始日志；运行／失败只改变提示，已展开内容持续更新，不抢焦点或强制滚到底部。
- [x] 换流同时重置该角色事件与日志游标，保留抽屉、所选角色、焦点和其他阅读状态，不通过重挂载整个阅读器解决重试问题。
- [x] 旧调用无事件时显示“此调用无结构化事件”，仍能读取材料与日志；不自动回放旧日志，新调用正常生成事件。
- [x] 生命周期事件写入失败有独立于该事件文件的诊断途径，不阻止合法产物提交；新调用观测故障不得伪装成存量无事件。
- [x] 通过已安装 CLI、真实子进程、HTTP 和浏览器验证完整链路，覆盖进程结果与提交结果不一致、同轮多次重拟、收尾、分页和重连；安装分发包含本票新增模块。



## Answer

四角色调用在同轮日志旁发布六字段事件；纳秒启动时间标识当前流，原子替换首条事件，后续追加，重试只替换对应角色。进程终态与研究产物校验分开；Telemetry 写入故障通过命令 stderr 与原始日志独立提示，Observer/L2 不将故障误作历史无事件。没有历史索引、事件回填或研究提交钩子。

L2 由材料抽屉的「执行 Trace」主动展开，逐批读取当前角色事件，切换调用同时重置日志游标；角色、抽屉及焦点保持。旧响应按 effect 生命周期丢弃，日志读后复核 stream，换流时丢弃该日志响应。原生日志解析与尾随预算属于 05，本票仅公共生命周期。
