# 06: 日志洪峰与观测故障下仍可控制研究

**What to build:** 日志大量输出、超长行或观测故障发生时，研究者仍能及时停止研究或等待既定超时，合法产物正常进入校验与提交。无法完整展示的 Trace 明确说明原因，不拖住控制流程、不串入下一次调用。

**Blocked by:** 05 — 在 L2 实时观察 Codex／DSH 工具事件。

Status: resolved

**规格：** [Research Workbench 与多 Provider 执行](../spec.md)。本票交付受限资源和故障条件下的端到端行为，不替代前序各票自己的正常路径测试与验收。

- [x] 尾随独立于 Process 停止／超时等待，每批读取最多 256 KiB，跨批解析保持正确；单个未终止行的解析缓冲最多 1 MiB，不能持续积累内存。
- [x] 超长行仍完整保留在原始日志，可停止对该行的事件提取并明确提示 Trace 不完整；超限不得导致无限循环、整段日志重复扫描或研究失败。
- [x] 进程树结束后处理剩余事件，尾随收尾最多增加 2 秒等待；超时停止观测并提示不完整，随后正常执行产物校验与提交，不伪造“Trace 完整”。
- [x] 尾随任务受停止标志约束，角色调用结束后不能继续写入下一次调用的事件文件；快速重试、同轮重拟及角色切换不会混流。
- [x] 大量 stdout/stderr 输出期间，CLI 与工作台停止以及既定超时仍及时生效，沿用现有进程树清理判据，结束后没有后代继续写工程。
- [x] 解析失败、事件写入失败和观测收尾超时在命令或原始日志中提供必要上下文，Observer／L2 提示 Trace 不完整；既有正常研究结果不被观测诊断改成失败。
- [x] 原始日志也不可写时暴露真实错误及上下文，不声称已持久保存诊断；不新增诊断账本、静默回退、哈希或逐行正则流水线。
- [x] 用户可继续分段阅读原始日志、查看已提交材料；运行／失败／观测故障均不自动展开 L2，不抢焦点或重置当前阅读状态。
- [x] 复用真实子进程与浏览器链验证持续日志洪峰、超长行、观测故障、收尾超限后提交、停止和重试；使用有截止时间的状态等待，不以固定 sleep 推断行为成功。
- [x] 运行受影响的已有轮次、恢复、控制、安装及浏览器回归，确认六票组合仍满足父规格的研究与观测边界；不重复制造前序已充分覆盖的证据或另建总结报告。

## Implementation evidence

- 已安装 CLI＋真实进程＋HTTP 的红绿测试复现并修复：超长行诊断被后续输出埋没后，Observer 错报无观测故障。现在后台尾随只写独立事件，调用收尾统一将诊断写入原始日志；Observer 同时识别结构化诊断。原始日志写入失败会在 stderr 暴露具体错误。
- 解析前限制跨批行缓冲；逐事件检查停止与两秒收尾期限；DSH tool_result 直接展示原生 callId，不保留无限增长的调用关联表。停止后的旧尾随不能通过路径向重试的日志写诊断。
- `test_observation_faults.py` 覆盖 2 MiB 未终止行与原始日志分页、百万事件收尾超限但探针提交、stdout/stderr 洪峰中的 CLI 停止和超时、真实后代清理、立即重试隔离、OS 文件大小限制导致事件写入失败，以及原始诊断路径不可写。真实浏览器覆盖洪峰停止、故障重试、材料阅读保留、L2 不自动展开和显式诊断显示。
- `pytest opc/tests tools/tests -q`：149 passed、3 skipped、12 subtests；`npm run build --prefix web` 通过；`workbench_control_smoke.py` 通过。该全量回归启动于 05 集成之后，随后合入 02 原生模型配置修复；最终组合的 fault＋DSH 定向回归为 15 passed、1 skipped（真实 Provider 验收由 02 单独记录）。
- 审查回归闭环：已安装 CLI 用 `/dev/full` 复现 DSH 第二个临时文件写入失败后的残留，修复为创建作用域内清理并保留真实错误；真实浏览器先复现材料链接跨轮询丢失 DOM／焦点，再以稳定 Markdown renderer 修复。延迟真实材料分页 HTTP 响应，确认 A 的迟到内容曾覆盖已打开的 B；请求代次隔离后 B 保留且相对证据链接仍正确。Reader 未强制重挂载。
- 最终生产构建及两条浏览器 smoke 均通过（含上述新增红绿场景）；原生 DSH 无模型启动＋Provider／原生事件定向回归 `15 passed`。未重复付费 Provider 验收。
- 最终组合全量回归：`pytest opc/tests tools/tests -q` → `150 passed, 4 skipped, 12 subtests passed`；所有 06 验收项闭环。
