# 06: 日志洪峰与观测故障下仍可控制研究

**What to build:** 日志大量输出、超长行或观测故障发生时，研究者仍能及时停止研究或等待既定超时，合法产物正常进入校验与提交。无法完整展示的 Trace 明确说明原因，不拖住控制流程、不串入下一次调用。

**Blocked by:** 05 — 在 L2 实时观察 Codex／DSH 工具事件。

Status: ready-for-agent

**规格：** [Research Workbench 与多 Provider 执行](../spec.md)。本票交付受限资源和故障条件下的端到端行为，不替代前序各票自己的正常路径测试与验收。

- [ ] 尾随独立于 Process 停止／超时等待，每批读取最多 256 KiB，跨批解析保持正确；单个未终止行的解析缓冲最多 1 MiB，不能持续积累内存。
- [ ] 超长行仍完整保留在原始日志，可停止对该行的事件提取并明确提示 Trace 不完整；超限不得导致无限循环、整段日志重复扫描或研究失败。
- [ ] 进程树结束后处理剩余事件，尾随收尾最多增加 2 秒等待；超时停止观测并提示不完整，随后正常执行产物校验与提交，不伪造“Trace 完整”。
- [ ] 尾随任务受停止标志约束，角色调用结束后不能继续写入下一次调用的事件文件；快速重试、同轮重拟及角色切换不会混流。
- [ ] 大量 stdout/stderr 输出期间，CLI 与工作台停止以及既定超时仍及时生效，沿用现有进程树清理判据，结束后没有后代继续写工程。
- [ ] 解析失败、事件写入失败和观测收尾超时在命令或原始日志中提供必要上下文，Observer／L2 提示 Trace 不完整；既有正常研究结果不被观测诊断改成失败。
- [ ] 原始日志也不可写时暴露真实错误及上下文，不声称已持久保存诊断；不新增诊断账本、静默回退、哈希或逐行正则流水线。
- [ ] 用户可继续分段阅读原始日志、查看已提交材料；运行／失败／观测故障均不自动展开 L2，不抢焦点或重置当前阅读状态。
- [ ] 复用真实子进程与浏览器链验证持续日志洪峰、超长行、观测故障、收尾超限后提交、停止和重试；使用有截止时间的状态等待，不以固定 sleep 推断行为成功。
- [ ] 运行受影响的已有轮次、恢复、控制、安装及浏览器回归，确认六票组合仍满足父规格的研究与观测边界；不重复制造前序已充分覆盖的证据或另建总结报告。
