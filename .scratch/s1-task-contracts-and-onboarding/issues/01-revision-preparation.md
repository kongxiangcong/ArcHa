# 01: 指定 revision 的准备与候选修改

**What to build:** 用户可对明确的 Task/revision 开展准备，在正式执行前反复完善同一候选；准备结果只证明实际检查过的内容。工程任务无需地图即可进入，“只准备”到准备完成为止。

**Blocked by:** None (can start immediately).

**Status:** resolved

**Spec:** [S1 实现规格](../spec.md)

- [x] 准备入口接受并交接明确的 Task/revision，不因最新目录或另一 revision 的回执而替换准备对象。
- [x] 准备检查或审核不冻结候选；修改、拒绝审核后的修复及失败重试沿用候选编号。已被执行 Run 冻结的合同仍受保护。
- [x] 回执关联 Task、revision、检查时内容摘要和必要资源身份，复用既有账本保留记录，不生成每轮草稿副本。
- [x] 候选变化后旧回执不为新内容背书，仅补查受影响部分，不重复扫描无关资源。
- [x] 准备失败、能力未实现或必要条件缺失时不启动正式 Worker；已授权且可自主完成的准备继续处理，外部阻塞展示具体原因及依据。
- [x] “只准备”即使 ready 也不执行；必要准备审核仅按合同启用，不增加常驻或默认审核角色。
- [x] 观察入口默认显示准备对象和状态，按需展开回执及来源，不新增状态账。
- [x] 通过已有 Onboard → Engine 测试边界验证候选修改、审核后重试、跨 revision 回执隔离、失败不执行和只准备停止；保留已有旧回执兼容回归。
