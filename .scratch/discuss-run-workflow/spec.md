# ArcHa：讨论定锚与执行循环的两入口减法重构

Status: resolved

## Problem Statement

用户希望先与模型多轮讨论探索什么、为什么值得研究，再将明确目标交给自主探索与优化循环。四个技能增加选择与维护负担，单一入口又容易模糊讨论与执行的边界，造成目标尚未收敛就启动，或已经授权执行却反复询问。

探索还需要始终联系全局目标，避免预先拆出一批缺少证据的细碎方向，以及在非关键局部持续消耗轮次。旧规格、过时入口和仍承载有效协议的开发方案混在一起，会误导后续使用与开发；简单批量删除又会丢失当前约定。

当前代码已取消强制四步链，报告也已离线化。本次解决剩余的入口、行动指引和文档问题，不以消除不存在的模型报告调用作为重构理由。

## Solution

保留 `/archa-discuss` 与 `/archa-run` 两个技能入口。前者通过多轮对话与材料查证形成目标，并明确执行准备；后者在目标、环境就绪与反馈回路均已确认且已有执行授权后，管理探索、优化、停止、恢复、进展查看与按需报告。明确任务也要讨论环境怎么搭建、如何判断就绪、结果如何形成可用反馈，不能因目标明确就直接运行。两个入口共享专题材料，讨论与执行阶段明确，但已有授权时不要求用户手动重复调用。

沿用专题工作区和线性探索轮次，逐步形成全局机制模型，并据目标收益、信息价值和验证成本选择探针。调查、反事实改动与优化验证在同一循环内交替进行。清理旧技能和被替代的文档，保留必要协议与原始证据，不增加新的状态系统、交接文档或认知账本。

## User Stories

1. 作为研究者，我希望通过讨论入口多轮澄清需求，以便尚未确定研究方向时也能开始交流。
2. 作为研究者，我希望模型先查阅已有工程材料，再询问需要我取舍的问题，以便不用替模型查找事实。
3. 作为研究者，我希望讨论目标包含研究目的、范围、环境入口和完成判据，以便执行有明确依据。
4. 作为研究者，我希望只讨论方向时不启动实验或优化工程，以便保留决定何时执行的权利。
5. 作为研究者，我希望目标足以指导下一步后才创建专题，以便不为每次未定锚讨论产生工作区文件。
6. 作为研究者，我希望未立项讨论留在会话，跨会话时自行带入摘要，以便无需维护额外的讨论日志系统。
7. 作为研究者，我希望技术未知可以保留到执行中调查，以便不必在立项前解释完整系统。
8. 作为研究者，我希望明确任务也先讨论必要的执行准备，并复用已有答案与授权，以便既不仓促启动，也不重复访谈。
9. 作为研究者，我希望启动前检查实际使用的 Worker 配置，以便配置问题不会被误认为研究结果。
10. 作为研究者，我希望轮数使用已授权预算，以便启动和追加轮次的成本边界明确。
11. 作为研究者，我希望首轮优先明确系统边界、已有基线和关键未知项，以便后续探针有全局参照。
12. 作为研究者，我希望系统模型随证据修正且允许留白，以便模型不会为填满模板编造解释。
13. 作为研究者，我希望每次探针说明其对全局目标的价值，以便局部调查不会无限偏离主问题。
14. 作为研究者，我希望选择探针时综合收益潜力、信息价值和成本，以便不会机械追逐最大开销或最大未知项。
15. 作为研究者，我希望反事实代码或配置改动也能作为归因探针，以便不必先完成纯调查阶段才能验证机制。
16. 作为研究者，我希望工程优化限于已授权范围，以便纯调查目标不会自动变成工程修改任务。
17. 作为研究者，我希望优化验证干预生效、正确性与端到端收益，以便局部指标改善不会被当成整体目标达成。
18. 作为研究者，我希望有效改动保留、无效实验由当前任务清理自身改动，以便后续轮次基于清楚的实际工程状态推进。
19. 作为研究者，我希望关闭分支时保留理由与适用条件，以便条件变化或反证出现时能够重新审视。
20. 作为研究者，我希望普通恢复继续原待执行探针，以便停止不会无故丢弃已有计划。
21. 作为研究者，我希望明确纠偏后由 Expert 根据新目标重新出题，以便旧探针不会继续带偏执行。
22. 作为研究者，我希望纠偏保留已完成轮次、证据与授权预算，以便历史结果不会被改写。
23. 作为研究者，我希望只查看进展时不生成报告或改变状态，以便低成本了解当前研究。
24. 作为研究者，我希望需要报告时能离线整理已有材料，以便无需额外模型调用或第二份认知账本。
25. 作为研究者，我希望研究完成、专题阻塞和预算耗尽得到准确解释，以便知道目标是否达成及如何继续。
26. 作为使用者，我希望安装后只发现两个新技能，以便旧入口和兼容别名不会继续造成选择困扰。
27. 作为使用者，我希望技能安装不隐式升级目标工程的固定运行时，以便既有项目保持可控。
28. 作为维护者，我希望当前协议各有一个有效来源，以便删除草稿后仍能理解并维护执行行为。
29. 作为维护者，我希望过时文档入口与失效链接得到修正，以便后续 Agent 不把旧架构当成当前规范。
30. 作为维护者，我希望通过 Git 查找旧规格和验收说明，并保留原始实验材料，以便清理工作树时不再生成归档副本。
31. 作为研究者，我希望讨论所需环境、搭建方式及必要准备，以便执行者知道任务在哪里、怎样运行。
32. 作为研究者，我希望明确环境就绪的判据及其验证依据，以便安装完成或配置可读不会被误认为任务已经可执行。
33. 作为研究者，我希望明确执行产生哪些观测、如何判断正确性与收益、Expert 如何吸收结果，以便反馈能够支持下一步决策。
34. 作为研究者，我希望启动前确认必要准备已经满足，以便尚未解决的环境问题不会混入正式探索循环。
35. 作为使用者，我希望开发完成后的项目 README 对齐最新使用流程，以便从首页就能正确开始讨论、完成准备、启动执行并在需要时纠偏。

## Implementation Decisions

- 技能职责按讨论定锚与执行循环分开；保留多轮需求澄清，不将一次技能调用视为启动授权。明确目标与已有授权不能替代执行准备讨论；目标、必要准备及反馈回路均明确且满足就绪判据后才交接，不增加必须逐一手动调用的步骤。
- 讨论未定锚时只使用当前会话；立项后沿用目标文档、认知状态和逐轮探针／结果。目标保留完成判据，技术未知交给后续探针，不要求前置方向清单或完整系统分解。
- 讨论明确环境搭建方式、必要依赖与运行入口、环境就绪判据和验证依据，以及执行观测如何记录、如何判读、如何回到 Expert 支持下一步决策。复用已有材料和证据，只补实际缺口；必要的准备操作按已有授权执行。相关约定写入现有目标与环境说明，不新增准备状态、独立验收文档或通用预检流水线。配置检查通过不能代替任务环境就绪和反馈回路确认。
- 执行技能复用现有部署入口与 CLI，管理配置检查、运行控制和报告。删除旧四技能以及可由现有 CLI 直接完成的薄封装；安装器复用备份方式退役旧入口，不保留兼容别名，不建设通用迁移框架。
- 既有工程固定运行时继续显式升级，保留原有升级与备份边界。配置检查保持只读，不用真实模型调用代替检查。
- Expert 提示负责渐进建立全局机制模型，在现有认知状态结构中记录证据、适用范围和下一步理由。优先级使用收益潜力、信息价值和成本，不建立评分系统；性能任务关注关键路径及收益上界，其他任务不硬套耗时方程。
- 探索和优化沿用同一探针协议。允许在授权范围内用最小干预检验解释，并验证正确性与目标收益；Executor 留下有效改动，清理自身无效实验，记录实际基线，不撤销他人工作。
- 关闭分支保留适用条件，条件变化或反证出现时允许重新打开。完成判断仍由目标和证据决定，研究完成不代表独立审核、合并或发布。
- 普通恢复沿用待执行探针。明确改变目标或关注点时，先正常停止并完成提交恢复，再更新目标与受影响的认知，移除最后一个尚无结果的待执行探针，让 Expert 重新决策。沿用现有调度能力，不新增重规划命令、内容哈希或自动变更检测。
- 已完成轮次、状态头与授权预算保持既有约束；实质换题新建专题，已完成专题不重开。删除待执行探针不撤销已提交认知或工程副作用。
- 报告继续按需离线生成，独立报告技能退役；普通进展查看只读已有状态与材料，不新增自动历史账本。
- 文档清理先迁移仍有效的协议到现有对应文档并修复引用，再删除已被替代的根方案和旧阶段规格／工单。原始实验材料留在原位，历史说明通过 Git 查找，不新增归档索引。
- 修正当前文档入口中的旧流程与失效链接；保留较新的专题重构记录，标明其中旧四技能约定被本规格替代。不扩展为全库历史材料重写。
- 功能开发完成后，按最终实现更新项目入口文档，覆盖两个技能的职责、安装与旧入口退役、开放探索和明确任务都需要的准备讨论，以及启动、停止、纠偏、恢复和按需报告的使用流程。详细命令与协议通过现有主题文档引用，避免首页重复维护。
- 不改变运行时状态模型、轮次计数、提交恢复协议或工作台功能；复用现有保证，不增加重复校验与防御分支。

## Testing Decisions

以真实技能交互作为主验收入口，既有安装与 CLI 集成链作为辅助回归。两个场景都包含执行准备讨论；目标是否明确仅影响需求澄清深度。

- 主验收从用户调用已安装技能后的真实交互开始，观察需求澄清、授权边界、交接和实际工程行为。仅检查技能文字或跑通 CLI，不能证明模型不会提前执行。现有安装与项目本地 CLI 集成链作为辅助回归，不新增生产接口或测试框架。
- 主场景在小型独立工程中，从目标未明确的讨论开始：经过多轮澄清仍不启动实验；目标明确但未授权时仍不启动；讨论并确认环境搭建、就绪判据及反馈回路；必要准备满足且获得执行授权后开展探索；停止并改变关注点后重新出题；恢复完成至少一轮并按需生成离线报告。检查可观察的目标、探针、结果、工程改动和状态，不要求固定提问措辞或固定研究路线。
- 明确任务场景从目标已给出、环境或反馈方式尚有缺口开始，验证模型仍会讨论搭建方法、环境就绪判据及反馈回路，不因已有执行授权直接启动；补齐准备并有就绪依据后才交接。已有答案和授权应复用。至少一次实际结果应被 Expert 吸收并用于下一步决策或完成判断，以证明反馈可用，而不只是命令退出成功。使用既有轮次材料补查普通恢复和纠偏的差别，不为每个分支另起真实模型循环。
- 真实交互验收使用受控的小型任务和明确轮数预算，不预设性能收益数字；清楚区分技能对话行为、Worker 真实执行和脚本模拟结果。真实性证据不能由脚本化 Worker 通过推断获得。
- 自动回归优先复用安装器与项目本地 CLI 的现有测试：新技能可独立安装和部署、旧入口退出可发现范围、无关技能不受影响；纠偏重出题且保留已完成轮次和预算；普通恢复使用原探针；报告离线生成且不改变权威材料。
- 复用既有初始化保留、配置只读检查、运行时显式升级与跨平台测试，不为本次技能调整复制其内部逻辑测试。文档验收检查当前入口及迁移引用，不为历史全文增加扫描框架。
- 技能格式校验只是结构检查，不替代行为验收；语义检查以实际可观察行为为准，不断言提示词的固定句子、标题或字数。
- 最终对照已验证的用户流程审阅项目 README，确保示例、命令入口及链接与实现一致，明确任务的示例也不能跳过环境就绪与反馈回路确认。

## Out of Scope

- 单一总入口、旧技能兼容别名、强制四步链、契约冻结、前置细碎任务地图。
- 独立的探索／优化状态机、首轮强制完整分解、通用评分系统。
- 讨论日志、讨论草稿生命周期、自动跨会话恢复、额外交接文件和自动历史账本。
- 通用快照、自动回滚、独立交付晋升、自动目标变更识别、为假设风险增加哈希或重复校验。
- 新的 Worker 接入层、核心运行时重构、工作台改版、自动合并或发布。
- 旧执行数据迁移、隐式升级目标工程运行时、删除原始实验材料或批量重写全部历史文档。
- 本次规格发布不安装全局技能、不运行真实研究、不继续此前提前产生的实现改动。
