# 04: 清理过时材料并对齐 README 使用流程

**What to build:** 功能开发完成后，用户从项目 README 即可按最终实现开始讨论、完成准备并进入执行；维护者从当前文档找到有效协议，旧流程不再冒充现行约定，同时保留必要原始证据。

**Blocked by:** 01：贯通讨论、执行准备与首次探索轮次；02：以全局模型推进探索与优化；03：贯通人工纠偏、恢复与进展查看。

**Status:** ready-for-agent

依据：[父规格](../spec.md)。依赖前三项完成，以最终行为更新使用说明；本事项不重新设计执行流程。

- [ ] 梳理父规格列出的两份根方案中仍有效的执行协议，将必要约定收拢到现有对应文档，修复引用后再删除旧方案；每项约定保持一个权威来源，不遗漏当前模板变量、状态约束和提交恢复语义。
- [ ] 删除父规格指定的旧阶段 S1–S5 规格与工单，历史说明通过 Git 查找；原始实验材料留在原位，不新增归档索引、迁移报告或数据副本。
- [ ] 保留较新的专题重构记录，修复迁移引用，并明确其中旧四技能约定已被两入口方案替代；不抹去已有验收限制，也不扩展为全库历史全文重写。
- [ ] 修正文档入口将旧阶段或旧改造称为“当前”的表述、已退役操作指引及失效链接，让现行流程与历史材料可辨认。
- [ ] 功能完成后更新项目 README，说明两个技能的职责、安装与旧入口退役、讨论到执行的交接，以及停止、纠偏、恢复、查看进展和离线报告的完整使用流程。
- [ ] README 的开放探索和明确任务示例都包含必要的执行准备讨论，明确环境就绪与反馈回路确认；不让“目标明确”或“已有授权”被误读成可以直接启动。
- [ ] 首页保留核心规则、可用示例和导航，详细命令及协议引用现有主题文档，不复制维护同一内容。
- [ ] 对照 01–03 已验证的行为检查首页示例、命令入口与引用，确认当前使用链没有指向被删除材料，原始证据及保留记录仍在；复用既有验收结果，不为文档整理重复运行完整研究或新增扫描框架。
