# 03: 贯通人工纠偏、恢复与进展查看

**What to build:** 用户可以通过新入口停止专题、调整关注点并恢复；普通恢复继续原探针，明确纠偏后 Expert 根据更新后的目标重新出题。用户还可以只读查看进展，或按需获得离线报告。

**Blocked by:** 01：贯通讨论、执行准备与首次探索轮次。

**Status:** ready-for-agent

依据：[父规格](../spec.md)。本事项不依赖 02 的探针选择策略，可沿用现有 Expert/Executor 循环验证控制行为。

- [ ] 普通停止与恢复保留已有待执行探针，实际执行其内容；停止确认结束后才允许人工修改专题材料，既有提交恢复边界保持有效。
- [ ] 用户明确改变目标或关注点时，讨论入口更新目标和受影响的认知，处理最后一个尚无结果的待执行探针；恢复时由 Expert 重新出题，新探针反映纠偏后的目标。
- [ ] 仅编辑目标不会被宣称为已自动替换旧探针；移除待执行探针不会撤销已提交认知或工程副作用。已完成轮次与证据保留，预算只按用户授权追加。
- [ ] 技术未知由循环内探针继续解决；需要改变用户目标、范围或完成判据时回到讨论。实质换题新建专题，已完成专题不重开。
- [ ] 状态查看只读已有材料，不启动执行或生成报告；用户明确要求时离线生成衍生报告，不调用 Worker、不改变权威材料、不新增历史账本。
- [ ] 准确解释研究完成、专题阻塞、预算耗尽及调用失败；保留真实错误和日志入口，不自动无限重试，不把研究完成当成合并或发布。
- [ ] 在 01 的真实交互流程中演示停止、纠偏、重新出题、继续及按需报告；结合现有材料与自动回归验证普通恢复、已完成轮次和预算保持、报告前后权威材料不变。
- [ ] 复用现有调度、停止和提交恢复能力，不新增重规划命令、目标哈希、自动变更检测或通用回滚机制；验收记录引用已有证据，避免重复报告。
