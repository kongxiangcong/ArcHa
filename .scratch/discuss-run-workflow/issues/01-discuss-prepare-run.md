# 01: 贯通讨论、执行准备与首次探索轮次

**What to build:** 用户安装后只通过 `/archa-discuss` 与 `/archa-run` 开展研究：先多轮澄清目标及执行准备，必要条件满足且获得执行授权后启动，首轮结果实际回到 Expert 并影响下一步决策。明确任务同样经过准备讨论。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

依据：[父规格](../spec.md)。已有未提交修改仅作为候选实现核对，不能代替本事项验收。

- [ ] 两个新技能可以安装、部署并通过工程本地入口使用；旧四技能及冗余薄封装退役。安装时旧入口移入现有备份位置，不保留可发现的兼容别名，无关技能不受影响。
- [ ] 开放探索支持多轮讨论和工程材料查证；未定锚讨论留在会话，目标足以指导下一步后才立项。只讨论时不启动正式探索，不强制预拆方向或另写交接材料。
- [ ] 明确任务也讨论环境搭建方式、必要准备、环境就绪判据及验证依据，以及执行观测如何记录、判读并回到 Expert；复用已有答案，不因目标或执行授权已经明确而跳过准备。
- [ ] 确认目标、范围、环境入口、完成判据和优化授权范围；必要准备满足且有执行授权后交接。沿用用户授权轮数，不重复索取相同授权，不增加准备状态或通用预检流水线。
- [ ] Worker 配置检查保持只读，配置检查通过不等于任务环境就绪。初始化保留既有专题材料和配置，安装技能不隐式升级工程的固定运行时。
- [ ] 在小型独立工程中，从真实技能交互分别验证开放探索与明确任务场景：缺少准备或执行授权时不启动，满足条件后实际执行，至少一次结果被 Expert 吸收并用于下一步决策或完成判断。
- [ ] 复用安装、部署与本地 CLI 集成测试验证机械行为；真实技能对话、真实 Worker 执行与脚本模拟证据明确区分。仅格式校验、提示词检查或 CLI 成功不算完成主验收。
- [ ] 相关调用入口和必要引用随本事项同步可用；完整 README 流程对齐由 04 在最终实现上完成。复用现有测试和证据，不新增测试框架或重复报告。
