# 02: 以全局模型推进探索与优化

**What to build:** 用户通过新流程开展探索时，Expert 从系统边界、已有基线和关键未知项出发，选择对全局目标有价值的探针，并让调查、反事实改动与授权优化在同一循环内交替推进。

**Blocked by:** 01：贯通讨论、执行准备与首次探索轮次。

**Status:** ready-for-agent

依据：[父规格](../spec.md)。使用 01 提供的新入口和交接流程进行行为验收。

- [ ] 首轮优先明确相关系统边界、已有基线与关键未知项；系统模型随证据修正，允许留白，不要求首轮完整分解或预先穷举方向。
- [ ] 沿用现有认知状态结构记录证据、适用范围和下一步理由；探针选择综合目标收益潜力、信息价值与调查成本，不机械追逐最大开销或最大未知项，不新增评分系统。
- [ ] 性能任务区分局部改善与端到端收益，按需考虑关键路径或收益上界；非性能专题不强制使用耗时分解式。
- [ ] 同一探针协议允许资料核查、反事实改动与优化验证交替进行，不要求先完成纯调查阶段，也不以归因完全确定作为所有干预的前置条件。
- [ ] 工程改动限于目标授权范围；验证干预实际生效、正确性及目标收益，纯调查目标不自动扩大为工程优化。有效改动保留，无效实验清理自身改动并记录实际基线，不撤销他人工作。
- [ ] 分支关闭保留原因和适用条件，之后重新审视全局模型；条件变化或反证出现时允许重新打开。否定结果作为证据处理，不直接等同于专题阻塞。
- [ ] 通过新技能在受控小型任务中观察至少一次实际结果被吸收并影响下一步探针或完成判断，检查机制解释与工程观测是否一致；不预设性能收益数字，不用提示词字符串断言代替行为验收。
- [ ] 尽量延续 01 的验收工程和原始证据，不为各分支另建真实模型循环；保持现有轮次、预算、收尾消化回合与提交恢复语义，不引入新的探索／优化状态机。
