## 目标与复杂度

在保持模型语义的前提下，加速一组跨机制、跨输入规模的 DRAM bank 评估负载。复杂度来自 sector 映射、共享端口服务、L2 缓存与布局评估之间的耦合，不以规定最少轮数、故意削弱基线或无限放大输入制造难度。一次正确且充分的优化允许完成；是否有多轮研究价值由强基线与未见输入上的表现判断。

本规格替代此前“首版关闭 L2 cache、只测单一热点”的临时建议。仍限制为单 cluster；多 cluster、NoC 和完整 DeepStack DSE 留在本题之外。

## 三个负载族与一个综合验收

| 负载族 | 内容 | 主要权衡 |
| --- | --- | --- |
| A 地址映射与合并 | 连续/跨步/重复 sector，线性及 tile 布局，合法 XOR/cyclic swizzle，request/wave 合并语义 | 向量化与临时内存、去重成本、小输入固定开销 |
| B bank 与共享端口 | 全连接及部分连接层、不同 bank/row 几何、热点与均匀访问 | bank 并行、端口冲突、recharge、稳定 tie-breaking；不能把部分连接简化为全连接 |
| C L2 与访问序列 | 无 L2、确定性 FIFO L2、不同容量、output pressure、不同 CTA 遍历与 batch 输入 | 命中/缺失状态依赖、缓存失效、trace 复用与构建成本 |

综合验收调用冻结的布局搜索入口，跨多个 shape、tiling、stage、物理配置和缓存配置输出全部候选的结果以及 best。包括代表性采样与小规模精确枚举；每个案例采用的模式和采样点固定。保持候选集合、次序及平局选择语义，不允许少评估某些候选；可以复用等价的共同计算。

三个负载族是同一调优题的评价维度，不拆成必须依次完成的题，也不向执行者指定优化路线。分别设置公开开发输入与未见验收输入；公开覆盖范围，封存具体验收实例。无需穷举所有参数的笛卡尔积，但需保留能暴露交互问题的组合。

## 允许修改范围（建议）

- 允许改题内 `bank_oracle/engine.py`、`layout.py`、`l2_cache.py` 与 `gemm.py` 的内部实现，新增题内辅助实现。可重组数据结构、向量化、批处理、减少重复计算或引入受约束缓存。
- 输入/输出 dataclass、公开函数签名、物理规格及默认值保持兼容。数据类的内部实现可调整，但序列化字段、顺序语义、类型及可见行为不变。
- `gemm.py` 内候选生成、采样点/权重、校验规则和 best 选择语义作为冻结契约，不因文件可编辑就允许改变。内部算法可重写，结果必须满足契约。
- `spec.py`、评价器、负载生成器、基线副本和验收容差由操作者冻结；`parallel.py` 的执行策略固定为串行。上游 tests 可作为公开回归材料，修改测试不影响外置验收依据。
- 首版使用冻结的 Python/NumPy 环境和一个 CPU 执行线程；不把增加进程数或依赖更换当作改进。若后续允许本地编译扩展，应在开考前统一工具链与编译成本口径，不在考试中临时扩大权限。
- 既有 `pipeline.py` 可作为只读消费者检查返回兼容性，不增加流水线方程或多 cluster 的调优目标。

## 输出等价标准

| 输出 | 检查方式 |
| --- | --- |
| sector/bank/row/request 标识、row mask、计数及离散权重 | 精确相等；数组 shape、dtype、规范顺序也要一致 |
| FIFO 命中/缺失/部分命中、逐操作数 line 统计、resident 峰值/最终值 | 精确相等，检查多次调用顺序、配置改变和缓存失效 |
| bank 服务时间、逐 bank/row job 周期、总 load/store、下界 | 整数语义的值精确相等，即使返回类型为浮点；真实分数运算按预先校准的字段容差比较 |
| sampled_profiles、spatial_summaries、采样权重及 Little's-Law 限制标记 | 离散部分精确相等，浮点部分按同一字段规则；不能只对齐总周期 |
| 每个布局的预测及完整结果、best、validated_results（纳入输入域时） | 全部检查；best 和平局处理精确匹配，不能以浮点容差掩盖排名变化 |
| runtime_seconds 等运行观测 | 不要求相等，不用于申报主成绩；由外置计时器测量实际成本 |

不要将整个浮点结果树交给宽松的默认 allclose。准备阶段先复跑基线，按字段单位与计算形式制定容差清单；规则在任何候选提交前冻结，不能看到候选误差后放宽。若参考本身存在语义错误，暂停该案例并统一修正/更换基线，不能让候选自行修改真值。

参考方案由冻结实现负责完整差分，另以小输入标量实现核对地址解码、行 mask、FIFO 状态和简单 bank 服务，并检查守恒关系。上游已有部分标量检查可借用，但同源测试本身不自动成为独立真值。新共享端口和 L2 组合须在开考前核实可靠性。

## 计时、评分与资源

- 主计时单位为固定的异构工作负载批次；每轮使用新进程和空的候选私有缓存。公共解释器/冻结公共依赖预加载后开始计时，随后导入候选模块、执行候选初始化、按冻结顺序完成整批调用并物化输出。候选私有依赖导入及预计算纳入时间。
- 实例与 shape 构造、公共输入反序列化、外置结果比较可在计时外；候选不得在计时前接触当前输入或预生成答案。输入相关缓存只能在被计时的批次内建立；通用复用允许，但计入构建时间和内存。
- 重复输入的热缓存性能另行报告，不替代主成绩。模型内部的 FIFO L2 状态与优化实现的 memoization 是不同对象，二者都必须保持规定生命周期。
- 相同机器、CPU配置、依赖与负载，基线/候选交替顺序测量至少7对；报告中位数、离散程度、每个负载族及整体的速度比。profiler 不参与正式计时。
- 正确性先行。排名可使用三个负载族速度比的等权几何平均；综合批次另行报告且作为一致性检查，避免重复计分。公开各族及最差案例退化，不能只选最有利样例。
- 完成必须有超出已冻结噪声范围的收益，并满足每族退化上限。噪声判据和退化阈值在新增负载资格预检后确定，不能预先宣称一定能达到2倍或规定最少研究轮数。
- 允许一个 CPU 执行线程，记录峰值 RSS 与候选私有缓存大小。内存硬上限与每批超时在资格预检后写入 manifest；对基线和候选一致，不允许用无界缓存换取速度。

## 准备与停止条件

新增组合的有限预检已完成：512³部分连接＋FIFO首次评估约1.116秒，当前探针RSS约100–104MiB。需保留上游已有L2 trace缓存，以及带L2时的小问题精确profile切换语义；首次与热调用分开评价。下一步将已观察机制转为含快路径、重路径及容量边界的输入分布，再核实最终计时与内存上限。若只需一个通用局部替换即可在所有负载族达到满意结果，承认题目容易，不事后增加隐藏要求。若扩展导致评测时间过长，缩小精确枚举范围，保留关键机制覆盖。

开考前完成材料封装、字段等价清单、独立验收、固定基线、计时资源配置和读取隔离。当前不启动正式考试，不实现候选优化。四题之间仍无成果继承。
