# 研究进度增量记录

## 定位与执行

使用用户指定或工作台当前选中的工程和 Run。缺少范围时查询账本；多个候选无法唯一确定时，只询问任务或 Run。不根据目录名、最近时间或运行状态猜测。暂停、阻塞、结束的正式 Run 都能记录；准备阶段没有正式 attempt 时说明尚无可整理轮次。

先读取项目约定，再调用本技能的独立脚本：

```bash
python3 <archa-log>/scripts/log.py --project <工程目录> --run-id <实际Run标识> --timezone Asia/Shanghai
```

时区采用用户或项目约定，示例为上海时区。仅查看已有日志加 `--read`。默认日志位于合同明确关联的任务简报目录下的 `PROGRESS_LOG.md`；没有目录归属时询问保存路径，并通过 `--output <工程内Markdown路径>` 指定。不得写入冻结合同、原简报或执行产物。

脚本复用本机已有 Expert 的 Codex/DSH 模型配置做一次文字整理，不派发研究 Worker，不恢复 Run，不执行实验，不改变验收或调度。整理耗时独立于 Run，不伪装成研究用量；模型 CLI 的实际调用仍会产生正常费用。没有新增事实时不调用模型。

## 增量与归属

只读取已有账本事实、工作计划、实施结果、正式评价和反馈分析。一条记录只归属一个 attempt，轮次严格使用其真实序号。同一 attempt 内多个实验步骤合并叙述；后续新增评价或分析追加“第N轮补充”，不修改原记录。不把纯格式修正、重复回执另计一轮。

运行暂停、阻塞或收尾等变化单独记录为“运行进展”，不伪造 attempt。当前脚本不自动归档未进入账本的主会话补跑；不得将其冒充 agent attempt。

脚本用 Markdown 注释保存 Run、记录归属和已消费事件序号，重复更新不重复追加。新文件只增加任务标题及新增记录；已有内容逐字保留。历史错误通过补充更正，不回写旧文。

## 四段式结构化写作

每轮记录严格遵循以下格式，分段清晰、分点明确，语言通俗易懂：
### 1. 开头总结段（必写）
先用1-2句话通俗易懂总结本轮核心内容，是假设-实验-结论的精简版本，避免专业黑话，必要时用生活化类比，读者不用看下面细节就能知道本轮做了什么、结果如何。示例：
> 第X轮验证PIM硬件计时器的计数规则和性能观测探针对执行的影响，发起了N次测试进程实验，每次跑网络的一层或者两层，看重新跑时周期计数会不会从零开始，接着跑时周期数会不会累加。结果是重新跑从零开始，接着跑会累加，但观测探针可能会拖慢性能，需要进一步验证。

### 2. 固定四段结构（必写）
每轮严格按「当前问题—假设—实验—结论」四段展开，用词和开头总结段保持一致：
- **当前问题**：明确说明本轮要解决的具体疑问、之前遗留的问题，背景信息清晰。
- **假设**：明确说明本轮要验证的猜想，不要模糊。
- **实验**：
  - 明确说明实验环境：是PIM模拟器测试进程还是真实物理PIM硬件，P0开关要写明打开后记录模拟器内部的性能数据；
  - 实验次数写成「发起了N次测试进程实验」，明确每次跑网络的一层还是两层；
  - 对照实验要写清对照设置：一次关掉P0、一次打开P0，跑同样的一层或两层，这样的比较叫一对；
  - 专业术语第一次出现时用大白话解释清楚区别，避免读者混淆（如外层探针vs P0性能探针的差异）；
  - 内部术语统一翻译：「投影」写成网络的一层或两层；「跨对象」「跨会话」写成重新跑或接着跑。
- **结论**：
  - 明确写清什么被验证了、什么问题还没解决，不模糊表述；
  - 严格区分功能验证、模拟观测结果和物理硬件性能结论，不夸大结果适用范围；
  - 失败、负结果和被推翻的假设如实记录，不隐瞒。

### 3. 写作规范
- 总字数控制在300-1000字，信息少时允许更短，不凑字数；核心数字加粗显示；
- 用户已经在用的名称保持原样（如P0开关就写P0开关），不随意替换术语；
- 缺项写“未记录”或“尚未确定”，矛盾说明矛盾，不猜测，不为补齐结构而编造内容；
- 正文不罗列路径、哈希、命令、调用标识、资源消耗、原始JSON或内部思考过程；
- 环境故障只有影响研究推进时说明原因与后果，不记录无关的环境问题；
- 防御性表述：删除仅为防止被质疑、但不推进论证的句子，减少不必要的“may”“might”“could”“potentially”等模糊限定词，将模糊限定改为具体的条件或适用范围。

### 4. 下一步说明
如果有明确后续安排，在结论后单独说明下一步；尚未决策则等待研究协调分析；暂停则等待用户恢复；阻塞说明前提；预算耗尽需新的预算授权；未完成收尾说明缺口和有依据的恢复条件；只有确认完成才写暂无后续执行安排。不得承诺自动继续。

## 返回

追加完成后报告日志路径和新增记录数量。没有新增内容时直接说明。失败保留旧日志，说明原因，不自动重试模型或研究。仅在用户明确调用或点击更新时执行，不接入每轮研究结束的自动流程。
