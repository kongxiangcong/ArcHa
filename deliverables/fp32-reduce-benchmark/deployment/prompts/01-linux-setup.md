# 给部署/评测 Codex 的提示词

你负责在这台Linux服务器部署FR64对照实验，拥有安装依赖和准备隔离环境的授权。先读本包README.md、deployment/LINUX.md、deployment/PROTOCOL.md。你可以读取external-eval，但你的会话和记忆不得交给参试者。

完成以下工作并给我可直接进入的两个干净参试工作区：
1. 安装Python3.10+、git、C++编译工具、Verilator、支持read_slang的Yosys、OpenROAD及NanGate45 typical liberty。安装已打包的ArcHa三个技能到ArcHa专用用户；保留技能内容，不升级runtime。依据实际工具help处理兼容问题，锁定下载版本、镜像digest/安装清单与库哈希，不把latest当版本标识。模型服务凭据只使用服务器授权方式，不写入考题和日志。选用我当前配置可用的同一Codex模型与推理强度，明确记录；不要擅自把两个组配成不同模型。
2. 建立评测者、direct、archa之间的文件与网络隔离，参试者无sudo、无其他项目/历史/参考实现读取权限；工具共享只读，允许模型服务访问。部署者可联网安装，参试阶段只开放模型服务。确认嵌套Codex也继承隔离。
3. 按LINUX.md冻结副本，运行中立资格检查：朴素基线和封存参考在同一评价器下均须正确、时序通过。核实root_v边沿、特殊值、复位/暂停和隐藏生成器，测试故意损坏候选确实被拒绝。只修复评价器或包的接线兼容问题，不优化任一设计、不依据参考成绩调整目标制造差距。若原题约束与参考不兼容，停下报告而非隐藏改题。所有修复记录且在两组开始之前统一重新冻结。
4. 校验预算监控覆盖外层和嵌套worker，设置外部墙钟watchdog与日志/查询计数。不能覆盖时明确标记budget_unverified，不宣称严格等预算。
5. 生成两组字节相同的考题副本并初始化独立Git仓库。它们不得包含.opc地图/brief/合同，ArcHa流程以后实际生成。原语和工具链只读，rtl可写。保留评测者可信模板、隐藏种子、参考源和结果。
6. 输出工具版本、模板哈希、隔离检查、资格检查结果、参试路径和运行方法。到此停止，不启动任一优化组。我随后分别开启全新Codex会话运行。

这次是Linux部署与资格检查，准备成本单列，不能当作参试成绩。不把参考面积或调度细节写入参试工作区。
