# FR64 v1：流式 FP32 归约优化

目标：在固定数值语义、输入吞吐、输出延迟和综合时序约束下，最小化映射标准单元面积。共同起点是独立编写的朴素实现，不是空白生成任务。不得把相对朴素起点的收益当成超过成熟参考设计的收益。

## 功能与接口

顶层 `reduce64`，端口见 `rtl/reduce64.sv`。所有信号在 clk 上升沿采样。pacc[32*k +: 32] 是 lane k，k=0..7。
一行有64个binary32原始位模式，每个有效拍提供8个。cap=1时，sub依次为0..7，row_last当且仅当sub=7。行内没有空拍；en=0不算拍，允许任意暂停。相邻行首相差8的正整数倍个使能拍，允许连续行；行间cap=0的空隙是8拍的整数倍。不合法输入无需处理。

数学语义：x[8*sub+k]=pacc[k]。先令v=x；依次令n=32,16,8,4,2,1，对i=0..n-1计算v[i]=ADD(v[i],v[i+n])。最终v[0]输出。这个配对和每次舍入都是契约；不得使用任意重排、融合或实数求和替代。
ADD为binary32、round-to-nearest ties-to-even，输入和输出subnormal清为同符号零；任何NaN运算及异号无穷相加返回0x7fc00000。精确抵消为+0，-0+-0为-0。固定 `primitives/` 提供4拍流水加法器及数值实现。只优化归约组织，不改写、复制修改或绕过浮点原语的计算逻辑。允许任意数量原语实例及公开原语允许的延迟参数。

## 时序（用边沿消除歧义）

若最后一拍在使能上升沿e被采样，root_v必须在e+27上升沿之后有效，即包括e在内第28个使能沿。其他使能沿root_v=0。此时root和root_o都必须等于该行结果。root_o只是相同数值的第二输出，不要求额外物理寄存器。
en=0时root/root_o/root_v必须保持；cap=0仍推进已有流水。rst为同步、高有效，优先于en；rst后root_v=0，取消所有未完成行，数据输出无需清零。复位后可以开始新行，行首对齐从新一轮输入重新建立。rst允许出现在行中。
连续输入要求每8个使能拍接收一行，无ready背压接口。测试排除复位当拍的输入。

## 范围与评判

只修改 `rtl/*.sv`，顶层端口不变。可新增该目录内SV文件。不得依赖仿真/综合分支产生不同功能、文件IO、外部进程、层次化窥探testbench、不可综合实数或未定义黑盒。额外实验记录放notes/，不会作为RTL提交。
冻结SPEC、primitives、评测程序、时钟/工艺库与工作负载。环境配置由部署者生成，正式开始后冻结。评测者只导入提交的RTL到可信模板，独立运行。
首版指标：`area_um2`（Yosys映射面积，越小越好）、`wns_ns`（OpenROAD/OpenSTA零布线寄生的综合后STA，>=0）、`correct=1`。clock=10ns、uncertainty=0.1ns、输入/输出delay=1ns、输入transition=0.1ns、输出load=0.01pF。NanGate45 typical库；不代表布局布线后时序、硅后实测或功耗。
所有数据端口受时序约束，仅clk例外；en、rst不是false path。单元面积不是芯片面积。程序不会用缺失指标、空网表或未测状态冒充0。
功能采用独立整数参考模型、定向与随机仿真；没有声称全输入形式化证明。最终隐藏集由外部评测者预先生成种子并封存，公开的是测试规则，不是最终向量。

## 开发命令

在项目根目录运行：
```bash
python3 harness/evaluate.py --out /tmp/fr64-dev-001
```
每次使用新的输出目录。exit 0表示功能与时序均通过；exit 1表示候选失败；exit 75表示工具/配置基础设施故障。日志、网表和metrics.json均保留。时序不达标会保留面积/时序诊断但不能成为合格冠军。
预算、模型、评测次数和运行标识见部署者冻结的 `campaign.json`。提交最终RTL、设计解释、实验记录与最终Git commit；不选择隐藏集结果最好的中间版本。
