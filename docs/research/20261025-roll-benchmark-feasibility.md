## 2. 当前回测具体做了什么

源码 [exploratory.py](D:/dsh-proj/Roll/backend/src/roll/research/exploratory.py) 是一个独立纯函数 `backtest(rows)`：

- 至少25行，按日期唯一递增，校验有限且正的OHLC、非负成交量、RAW `adjustflag=3`、普通主板/non-ST范围。
- 以前20根数据预热；上一日可得收盘数据计算SMA5>SMA20，次日开盘选择全仓或现金。
- 10万元模拟本金、100股整手、每天最多一次开盘交易；代码以这种简化安排表达T+1，而非通用的逐笔可卖持仓模型。
- 费用为代码里的研究假设：佣金万3最低5元、过户十万1、卖出印花万5、双向5bp滑点；不能解释为用户实际费率或本轮核验的现行官方费率。
- 停牌、零成交、方向涨跌停、一字/单一价、滑点落在日线区间外、超1%成交量参与率不成交；期末收盘估值、不强平。主板10%也是该代码明确的适用假设。
- 同日同费率比较策略、买入持有、现金；保存成交、拒绝成交、每日净值与最大回撤。

现有 [test_assistance.py](D:/dsh-proj/Roll/backend/tests/test_assistance.py) 覆盖现金守恒、未来末行收盘变化不影响此前成交、停牌/涨跌停、公司行为截尾/拒绝、数据错误等。[verify_assistance.py](D:/dsh-proj/Roll/scripts/verify_assistance.py) 提供离线重算与独立现金/净值重放。它们是有价值的冻结资产；本轮未运行，不能把历史通过当当前通过。

## 3. 最值得解决的实际限制

1. **窗口不完整**：120自然日加截尾，不能覆盖用户提出的完整半年；已有样本也不足以稳定评价高自由度策略。
2. **规则不可替换**：当前策略内嵌在 `simulate`，没有通用“截至当日的资料→次日目标仓位”接口；不存在已核实的Markov实现。
3. **公司行为处理不是连续账本**：全局找最后一个昨收断点再截尾，[exploratory.py:23](D:/dsh-proj/Roll/backend/src/roll/research/exploratory.py:23)。从源码推断：若追加的新数据出现公司行为断点，重新计算可能移除过去已存在的交易/净值。这符合当前“只看action-free tail”明确契约，但不适合作为连续每日策略研究引擎；需改变研究契约后处理，不能简单称现有实现违约。
4. **没有样本外策略选择闭环**：固定规则尚未调参；新策略需要训练/开发/最终测试隔离，旧已查看数据只能作探索材料。
5. **成交假设用途有限**：用当日high/low判断模拟滑点成交是否可能是日线近似，不能推断开盘排队、日内触价顺序或真实成交概率。

README历史状态还记录正式量价模型G4/G5失败、其他不确定及数据覆盖缺口；它们解释旧正式策略的失败，不阻止ADR0005认可的独立探索。当前单次真实样例已经完成，不应把项目概括成“全部做不出来”。

## 4. 三种“最优”的边界

| 概念 | 可计算什么 | 如何用于测试 |
|---|---|---|
| 历史事后最优 oracle | 给定完整未来价格路径、冻结费用/可交易约束，枚举或动态规划求该路径的最高净值 | 只作不可交易的上界、执行/DP正确性测试；不能作为当天可得信号或监督目标泄漏给策略 |
| 模型条件最优动作 | 给定状态、转移概率/收益模型与效用目标，求模型内最优动作 | 可用小合成MDP准确核验Bellman/策略计算；模型估计错误时仍会亏损，不能称真实市场最优 |
| 样本外有效策略 | 仅利用当时可得资料选动作，在最终未用于选择的时间段按冻结引擎重放 | 看扣费后收益、风险、换手和稳定性；不能用事后oracle差距直接证明或否定可预测性 |

若尝试Markov，状态至少需要包含与执行有关的持仓、可卖数量/持有时钟、现金等；只把涨跌划成几个状态，不足以表达完整交易可行性。市场是否近似Markov、状态数是否有足够样本支持，都是待验证假设。

## 5. 建议的最小 ArcHa benchmark

**任务名：江西铜业离线逐日策略研究闭环。** 交付一个命令，以冻结价格/公司行为输入运行候选策略，输出每日动作、模拟成交、净值、对照和数据缺口；策略收益为负也算工程完成。

建议先有两个明确阶段，避免让候选一边改变裁判一边刷收益：

- **准备阶段（评价器工程）**：从Roll现有独立探索路径抽出策略接口，确定是否支持现金分红/拆送等公司行为；支持不了的局部事件冻结为不可评分或禁止开仓，同时保留此前账本。校验逐日前缀一致性、T+1可卖约束、现金/持仓守恒、费用及执行时点。准备完成后冻结引擎、数据、费用、规则、基线及最终评分器。
- **研究阶段（ArcHa vs直接Codex）**：仅允许改策略模块（必要时包含训练逻辑）；均线、简单滞后规则和可选Markov等都可竞争。每次仅用开发窗口评价，冠军冻结后一次性最终留出复验。相同初始项目、资源上限与工具；不得让主控手修候选。

建议冻结的验收：

| 层次 | 指标/门 | 用途 |
|---|---|---|
| 确定性正确性 | 无未来数据访问；截断/追加未来不改变已完成历史动作；现金/持仓/可卖量守恒；同输入重放一致 | 必须全部通过 |
| 数据完整性 | 请求与实际日期覆盖、缺失/停牌/公司行为数量、来源/单位/复权与hash | 不能静默缩短或删掉不利区间 |
| 工程可用性 | 离线CLI成功、输出schema、失败可诊断、日志/交易/拒单完整 | 不依赖真实账户、外部LLM或新数据取证 |
| 研究质量 | 相同执行约束下扣费后收益与现金/BH/固定SMA对照、最大回撤、换手率/成交数、最终留出表现 | 不预设一定获利；不足支持保留不确定 |
| Agent开销 | 端到端及阶段墙钟、各类token、候选/评价次数、失败与人工干预 | 报告效率/收益轨迹，不能仅数迭代轮次 |
