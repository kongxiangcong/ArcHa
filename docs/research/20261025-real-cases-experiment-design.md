# ArcHa 真实案例选型与两项对照实验卡

日期：2026-10-25。状态：**供审阅的调研与实验设计，未批准实施**。

本轮没有安装依赖、构建工具链、下载模型权重、运行 benchmark/回测、启动 archa-map/task/loop 或迁移项目。实际执行的只有源码/版本读取和 WSL 环境探针。文中预算与验收门槛都是建议，不是实测结果或收益承诺。

## 1. 判断与减法

最终推荐：工程实践选 **ONNX Runtime 上受精度、内存约束的 DistilBERT CPU 部署改进**；探索优化选 **ZigZag 固定硬件与空间映射下的有限预算时间映射搜索**。两者分别给出真实 CPU 部署结果与冻结模型内的映射质量，不能合成一个总分，也不能预设 ArcHa 胜出。

推导链：

1. **事实**：ORT 提供真实模型推理、量化/图优化及诊断入口；ZigZag 提供映射、存储分配、成本评价与 SALSA 基线，见下文固定来源。
2. **事实**：本地 WSL 可以访问，但尚无本次任务所需 Python 依赖；openTPU 已有 ISA/RTL 仿真，架构工具链项目 README 明确仍是提案。
3. **设计假设**：我们要测的是受反馈影响的研究与工程推进，而非环境排障能力，故先由中立准备过程固定可执行评价器，两臂共享。
4. **推断**：ORT 的精度—算子边界—融合—延迟关系，ZigZag 的合法性—复用—存储分配—搜索预算关系，有机会提供可改变下一步决策的反馈，且不必先搭建完整芯片工具链。
5. **结论边界**：源码只能支持“有合理研究空间”，不能证明本机强基线仍有改善余量。若后续中立预检发现饱和，选题判为区分度不足；不得删除已有优化或提高难度来制造多轮。

本轮删掉从零写 openTPU 功能仿真器、FT06 主效果验证、恢复已有编译规则；推迟完整 ASIC/RTL/PPA 流程、AccelForge 全栈接入、联合架构与映射搜索；Roll 先作为独立应用备选。原先 CPU 成本模型仍有价值，但首批只保留两项，避免同时建设测量标签系统和验证 agent。

需要检验的默认前提是“难任务自然能证明多步能力”。多次失败也可能仅是环境不稳定，连续变好也可能仅是随机搜索。我们改用**前次证据与后续决策的可追溯关系，加同预算自主 Codex 对照**，不拿轮数本身作能力证明。

### openTPU 已有什么仿真/建模工具

- [isasim.py](https://github.com/FeSens/openTPU/blob/7e42a626f714edd07867702c38c954082d51f587/opentpu/isasim.py)：位精确功能模拟器，是 RTL 对照 golden。
- [rtlsim.py](https://github.com/FeSens/openTPU/blob/7e42a626f714edd07867702c38c954082d51f587/opentpu/rtlsim.py)：Verilator 构建/运行路径，源码依赖 POSIX `fcntl`，WSL 比原生 Windows 更合适；本机未找到 Verilator，未构建。
- [Lens 的边界](https://github.com/FeSens/openTPU/blob/7e42a626f714edd07867702c38c954082d51f587/docs/lens.md#L127)：ISA profile 没有周期模型，按指令名义工作串接，不能拿它宣布硬件提速；RTL trace 才提供重叠/仲裁等时序信息。
- [LES 模型](https://github.com/FeSens/openTPU/blob/7e42a626f714edd07867702c38c954082d51f587/tools/offload/lesim.py)：已有针对 MoE offload/prefetch 的专用时间线模型，参数和未建模项在源码中说明，不能泛化为完整 openTPU 周期模型。

因此先复用现有功能/RTL判定器；只有未来要显著降低 RTL 查询成本且有参考 trace 时，才考虑补快速时序模型。

### E1：受约束的 DistilBERT CPU 部署

固定 [ORT v1.31.0](https://github.com/microsoft/onnxruntime/releases/tag/v1.31.0) / `402979ac1bef89dcd55add41eaa7277c407599eb`（本轮核到当前稳定release）；[DistilBERT SST-2](https://huggingface.co/distilbert/distilbert-base-uncased-finetuned-sst-2-english/tree/714eb0fa89d2f80546fda750413ed43d93601a13) / `714eb0fa89d2f80546fda750413ed43d93601a13`；[SST-2](https://huggingface.co/datasets/stanfordnlp/sst2/tree/8d51e7e4887a4caaa95b3fbebbf53c0490b58bbb) / `8d51e7e4887a4caaa95b3fbebbf53c0490b58bbb`。源码证据详见[工程证据附录](20261025-engineering-candidate-evidence.md)。任务基于公开模型、数据与ORT的真实部署问题重新定义；不冒充一个当前未修复的issue。历史 [ORT #17389](https://github.com/microsoft/onnxruntime/issues/17389) / [#6695](https://github.com/microsoft/onnxruntime/issues/6695)只能说明量化并非天然提速，不能证明今天同一bug仍在。

- **需求/价值**：相同 CPU 服务多种 batch/序列长度，在精度和内存限制下减少延迟。交付从固定 checkpoint 到可重建 ONNX 工件的构建器及推理入口，不交一段无法重放的调参记录。
- **基线/边界**：完整 ORT 图优化 FP32、官方 transformer 优化入口的可用方案、标准 dynamic INT8 的 per-tensor/per-channel、标准 static QDQ 的适用方案均保留。以开发集上最强可行完整方案为起点；不关闭 runtime 现有优化。可改逐节点量化选择、量化边界和等价图变换；冻结权重、tokenizer、runtime/EP、线程、输入契约和 judge，不微调、不换模型。
- **正确性/效果**：原始 checkpoint 的独立 FP32 推理确认导出；浮点等价变换用 logits 误差门，量化用标签 accuracy 损失门并另报 logits/预测一致性。评测实际 `session.run` 的P50/P95和新进程峰值RSS，初始化与预处理另列；profile只诊断，不计入正式计时。
- **反馈/一轮风险**：层级量化误差、Q/DQ边界、融合失效、不同shape瓶颈会改变下一次图变换；但调用标准API即可达标的风险较高。基线已充分解决时应结束，不人为抬门槛。
- **开发/留出**：官方train中固定不重叠校准和开发子集；完整validation 872条封存作最终部署精度检查。模型训练曾用train，这个划分不能研究模型训练泛化；这里只测固定模型变换损失。性能按未见batch×长度组合留出；输入样本和最终标签由外部judge持有。
- **公平/成本/证据**：用第4节协议。准备成本是模型/数据锁定、导出验证、强基线组合与独立judge；主要反馈不要求重编ORT。单次候选成本=构建/量化+开发集推理+各shape重复计时+独立RSS进程，均未实测。建议每臂4小时/250k token上限供审阅，无最少轮数。已读官方文档和相关量化源码；没有导出、校准或计时。

### E2：openTPU 编译器内存与布局

版本固定 `7e42a626f714edd07867702c38c954082d51f587`。[需求及当前机制](https://github.com/FeSens/openTPU/blob/7e42a626f714edd07867702c38c954082d51f587/docs/compiler.md)，[实现](https://github.com/FeSens/openTPU/blob/7e42a626f714edd07867702c38c954082d51f587/opentpu/compiler.py#L1134)，[已有best-fit回归](https://github.com/FeSens/openTPU/blob/7e42a626f714edd07867702c38c954082d51f587/tests/test_config_matrix.py#L230)。这是从真实编译约束提出的改进任务，尚未证实有一个现存未解决容量缺陷。

- **需求/价值**：对真实Qwen/LFM模型的attention、MLP、DeltaNet块自动改善临时张量布局/分配，减少可运行所需TMEM，保持bank合法性与硬件循环语义。覆盖实际模型层形状与已有targets，不能以手造碎片序列替代主工作负载。
- **基线/边界**：完整现有liveness/next-fit、`trace_fit` best-fit回退、奇数row-stride与现有kernel调度。可改编译器分配/重定位及其必要分析，冻结模型计算、量化、ISA、硬件容量、golden/RTL与judge。不靠减小batch、删层、改精度或扩大TMEM实现“通过”。
- **正确性/效果**：独立跑候选程序，比较语义可观察的输出与KV/模型状态；不能比较被重定位后物理地址不同的整个TMEM字节图。精度要求与原数值路径一致；独立检查别名、spare/RMAX、loop存活和银行约束。效果是编译覆盖率、固定输入的最小可行TMEM、有效/占址峰值、编译成本；RTL cycles作为不得恶化的约束。仅ISA检查时只能报告功能与内存结果。
- **反馈/风险**：碎片改善可能增加假相关，布局变更可能改善MXU排空却增加逐行DMA；循环存活错误会在多次迭代后暴露。典型小TMEM例已被best-fit修好，只换一个分配heuristic可能一轮完成，也可能完全无改善，需先核实真实剩余瓶颈。
- **划分**：以模型块/模型家族及真实target配置分组，开发可见Qwen普通attention/MLP，最终留出不同GQA、DeltaNet或真实长上下文组合；从整体支持范围预先取样，不能结果出来后挑失败点。微型随机测试只检验语义，不作主收益样本。
- **公平/成本/证据**：第4节共用；候选研究最多建议8小时/400k token，上限是计划而非预计时长。准备比E1高，需Verilator/C++构建与冻结RTL参考；每次=trace/compile+功能仿真+必要RTL复验，本轮没有成本实测。已读源码和回归测试，没有运行；因环境与余量未知列备选。

### X1：ZigZag 有限预算映射搜索

固定 ZigZag **3.9.1 / `7f9188329368ec72c586ce25f4cb55895171794e`**，来源：[项目](https://github.com/KULeuven-MICAS/zigzag/tree/7f9188329368ec72c586ce25f4cb55895171794e)、[SALSA论文](https://arxiv.org/abs/2304.12931)。详细源码证据和配置见[映射附录](20261025-mapping-candidate-evidence.md)。

- **需求/基线**：在有限编译预算内找到低能耗合法映射，输出可用于新层的搜索算法。完整原生及开发集调优energy-SALSA作强基线和starter；小域LOMA穷举只作正确性校验，大域高预算结果只称best-known。
- **可改/冻结**：可改候选生成、邻域、重启、剪枝、学习排序；冻结硬件、成本表、spatial mapping、未合并LPF域、MemoryAllocator、CostModelEvaluation、预算计数器与输入集。首轮唯一主目标`energy_total`，不联合搜架构；延迟副指标完整保留。
- **独立评价**：外部进程反序列化mapping，重建维度覆盖、分配合法性和成本。不是接受agent自报分数；同一ZigZag模型的复算不等于硅后能耗验证。
- **多步/风险**：合法率、重复率、不同层的局部最优、跨家族退化会改变搜索策略；SALSA本来就很强，可能没有改进余量。完整已穷举域不作为主要优化对象。
- **划分**：真实ResNet18/AlexNet dense Conv开发，MobileNetV2支持的dense/pointwise Conv整族留出，去重相同规范化工作负载。ONNX二进制本轮未解析，正式层清单必须后续先审，不把不支持层跳过后称完整网络优化。
- **公平/成本/证据**：第4节共用；固定每层oracle预算并同时报告求解墙钟，所有查询路径都计账。建议每臂4小时/250k token；求解预算曲线256/1024/4096次查询是待校准提案。单次=实例×查询预算×实测评价成本+搜索开销。已读API、SALSA/LOMA、allocator调用与配置，未运行。

### X2：SCALE-Sim 快速周期预测模型

固定 `9f98c4371055a54c75209c2e02b640b897550532`。[代码](https://github.com/scalesim-project/SCALE-Sim/tree/9f98c4371055a54c75209c2e02b640b897550532)、[v3论文](https://arxiv.org/abs/2504.15377)、[真实Transformer GEMM拓扑](https://github.com/scalesim-project/SCALE-Sim/blob/9f98c4371055a54c75209c2e02b640b897550532/topologies/GEMM_mnk/transformer_partial.csv)。

- **需求/基线**：少量仿真标签支持快速架构方案排序；从已校准阵列解析式、roofline与同标签量表格回归起步，不能只比常数。已有cycles→time线性工具不等于这里的shape→cycles预测器。
- **可改/冻结**：可改特征、分段模型、残差模型和采样；冻结稠密单核USER带宽模式、参考simulator、配置域和标签预算，不接Ramulator/CACTI。最终predict不得调用oracle或读取留出标签。
- **独立正确性/质量**：输入域与有限非负值门；独立进程重跑参考标签，测中位/P90相对误差、极短任务绝对误差、配置选择regret、预测时间/RAM。只是软件模型逼近，不能称真实芯片准确率。
- **多步/划分**：容量边界、尾块、阵列填充/排空、带宽切换给残差定位线索；按CNN/Transformer家族、shape区域、SRAM/带宽组合留出。已知公式足够时允许结论为不必复杂建模。纯随机分相邻配置会虚高。
- **公平/成本/证据**：同标签数且同采样oracle时间，第4节其余规则共用；建议4小时/250k token，标签规模待实测决定。准备要生成独立标签；单次训练与预测成本未知，oracle矩阵展开可能很贵。已读单层simulator、topology与现有线性模型；未运行。比X1多一层标签建设，列备选。

- **正确性/质量**：未来追加不改变已完成动作，现金/持仓/可卖量守恒，输入前缀和重复重放一致；样本外扣费收益、相对BH、回撤、换手、交易数、分窗口稳定性。负结果完全有效，历史事后最优不是可执行目标。
- **多步/留出**：交易成本吃掉收益、状态样本稀疏、制度切换或跨时期退化可推翻假设。按时间滚动训练/开发，最后未参与选择的连续时段一次终评；不是随机拆日期。已查看窗口不重新命名为未见。不得使用未来数据修订后的新闻/财报作当时信息。

## 4. 两臂共同实验协议

### 4.1 同一任务与两种成本视角

先冻结公共任务书、源码/模型/数据SHA、允许修改目录、评价器、主指标、约束、预算、信息权限。ArcHa按archa-map→archa-task→archa-loop完成；前期Codex模拟用户使用预注册回答脚本，不能看终评结果后改变需求。直接Codex获得同等原始任务、资料、可执行开发评价器，也可自主调查、修改、测试、记录笔记、回滚并继续迭代。

分别报告：

1. **执行期对照**：两臂拿同一份冻结brief、starter与环境。ArcHa的流程组织是实验变量；直接Codex不被强制成单次生成或使用相同角色划分。
2. **端到端成本**：从原始任务开始，ArcHa map/task/onboard、模拟用户、所有角色、失败和评审都计账；直接Codex的任务理解/计划也计账。不得把前期Codex的研究免费转移给ArcHa。两种结果分列。

两臂同模型快照、推理强度、工具、CPU/内存与并发上限。共同的资料包和搜索权限；测试labels不在agent可读目录，关闭终评反馈通道。第三方文档可查询，已合入的完整解不能只给一臂；保存外部读取日志。可以借已有方法，但必须通过未知输入复验，不能据此声称方法原创。

### 4.2 外部观察者和冻结范围

启动后外部Codex只收集日志/快照，不提示瓶颈、不修候选、不给下一步建议。两臂均可在可改范围内自行debug。框架/环境修复必须保留故障和消耗，标成干预；需要外部修候选时该运行不再是纯自主结果，修复后的续跑另列。调研报告里的路线例子若要给agent，必须两臂同时给；不能只在ArcHa受阻时递提示。

ArcHa当前有max_attempts、wall/token预算以及champion/反馈字段；读取了实现但未核验这些新任务。max_attempts仅可作为足够宽的故障上限，不设最少轮数，也不把达标后继续跑强制成多步能力。已有token账本不保证统一提供input/cache/output细分：从原始worker事件补齐，拿不到则标未知，不反推。judge与模型调用并行时同时报端到端墙钟和CPU秒，不能把各角色耗时相加冒充墙钟。

### 4.3 中立预检和预算（未来阶段，本轮不执行）

准备只运行冻结基线和判定器自检，不为任何臂开发新优化。测开发集P50/P95评价耗时、RAM、重复计时噪声、强基线饱和和支持域。出现以下任一情况则该卡不进入主研究：标准方案已全部解决且无有信息量的剩余目标；评价波动覆盖预期差异；大量实例不受支持；正确性判定器不可靠；单次评价占据研究预算大部分。不能根据ArcHa先输/先赢再换数据。

主推荐建议先每任务每臂 **4小时墙钟、250k总输入+输出token，先到者停止**；这是可调整的研究资源上限，不是耗时预测，缓存读取另计成本且不得作为免费无限上下文。中立准备若显示评价太贵，在正式两臂运行前对称调规模并重新冻结。基线、准备、终评花费单列；最终比较同时包含这些成本。

先做一对可行性pilot，结果不冒充统计结论。若任务仍适合，建议3个独立配对重复，固定数据划分、变更研究随机种子，随机交错运行顺序，隔离缓存和工作区；3对只支持描述性比较，不能轻率宣布显著优势。失败运行也纳入。

### 4.4 必交曲线与过程证据

| 观察对象 | 记录/计算方式 |
| --- | --- |
| 正确性/任务完成 | 全域通过率、约束失败类型、可重建工件；无效候选不能改善质量曲线 |
| 最好有效质量—累计墙钟 | 每个候选独立开发复验后，`Q_best(t)=max Q_j`（j通过全部硬门且评价完成时间≤t）；没有新有效候选时曲线持平，前期不可行则标“尚无可行解” |
| 最好有效质量—累计token | 同一批候选，横轴计所有角色与失败/修复token，不只冠军成本；另给端到端和执行期两条口径 |
| 同质量成本 | 预注册目标质量档位的首次达成时间/token/oracle调用数；未达到标“预算内未达到/右删失”，不拿预算上限当达成耗时 |
| 最终留出 | 先按开发分选冠军并冻结哈希，再一次终评；可事后盲测预注册检查点，结果不返回agent，也不据此重新选冠军 |
| 无效和失败成本 | 编译错误、数值错误、越界/非法mapping、超时/OOM、目标退化、基础设施故障各自次数与资源；重复查询、候选去重率另列 |
| 人工干预 | 谁、何时、改了什么、理由、时间/token、是否接触优化方案；包含框架修复和环境恢复 |
| 反馈改变决策 | 保存候选前假设/预期/反证条件，评价原始JSON/trace，结论引用，下一候选的相关diff、父候选与复用文件哈希 |

“我反思了”不算过程证据。有效例子应能追溯到：上一候选的某项误差或stall/非法率→明确否定哪个判断→下一候选改动哪个部件→该指标是否随之变化。允许有依据地继续同一路线，也允许最终无改善。曲线和日志仍不能单独证明反馈的因果作用；若将来要声称“反馈机制造成优势”，另做预注册去反馈/打乱反馈消融，本轮不扩大到该实验。
