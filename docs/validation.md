# OPC v0.1 本轮验证记录

日期：2026-10-21。结论：**状态机控制层及受限数值探索可运行；真实模型自主研发闭环尚未验收。**

## 1. 实际范围

本轮新增实现文档、合同模型与模板、官方源码核查和离线 GEMV 原型。原交接文档没有修改。目录最初不含 Git 仓库，因此没有创建 commit/分支/PR；用户引用 `implement` 的用途是借鉴其审核流程，本轮没有执行自动提交。

实际依赖为 Python 3.14.0、LangGraph 1.0.9、Pydantic 2.12.5、pytest 9.0.2，以及标准库 SQLite。没有启动付费模型 API、EDA、FPGA 或外部仿真作业。聊天中的研究和审查 agent 属于本次协作；它们尚未作为可由原型自动派发的 provider 接入。

## 2. 合同校验

命令：

```powershell
python contracts/validate_examples.py
python -m mypy contracts --follow-imports=silent
python -m ruff check contracts
```

实际结果：6 种对象样本可解析；6 份 JSON Schema 与模型同步；4 个反例被拒绝（未知字段、零实验预算、重复同一审核轴、一个审核轴失败却要求 accept）；草案因未解析授权/资产而不可派发。3 个源码文件的类型检查和 Ruff 通过。

边界：这验证结构和少量局部规则，不是 REST 服务、真实身份、权限或端到端合同 adapter 已实现的证明。生成的 JSON Schema 本身不执行 Python 的业务 validator，服务仍须执行同一模型校验与运行语义检查。

## 3. 真实运行的离线探索

正式原件为[审核修复后报告](../examples/gemv_loop/runs/final-reviewed-20261021/report.json)、[暂停回执](../examples/gemv_loop/runs/final-reviewed-20261021/paused-report.json)及同目录的 `domain.py` 原件。初版运行原件保留为历史，不能用于证明修复后的 evaluator。

工作负载 `(M,K)` 为 `(1,1)、(5,7)、(17,13)、(32,64)`，累加器上限 12。固定输入含负值与零，精确整数 golden 与候选代码的分块计算路径不同。实际测量 LOAD 回调计数；最终输出写按 M 计入模型，不模拟中间写、cache、bank 或流水线。

| 轮次 | tile | 模型标量传输量 | 结果 |
| --- | ---: | ---: | --- |
| 1 | 1 | 4665 | 功能/资源通过，建立基线 |
| 2 | 2 | 3523 | 通过，保留 |
| 3 | 4 | 2952 | 通过，保留 |
| 4 | 8 | 2663 | 通过，保留 |
| 5 | 16 | 2522 | 资源超限，拒绝 |
| 6 | 12 | 2586 | 根据失败边界二分得到，通过并保留 |

减少比例：`(4665 − 2586) / 4665 × 100% = 44.5659%`。此数仅代表冻结模型和四个形状的标量搬运数，不是加速比、时延、能量、面积或全局最优。停止原因是 `budget_exhausted`，意味着完成受限实验预算并交付已验证候选，不是任意研发目标都已完成。

第 2 轮后安全暂停并结束 CLI；第二个 CLI 进程恢复。实际保留暂停时已有的 4 个 job invocation，总计 16 个作业（8 次实验、8 次独立进程复核），没有重复已完成的实验。主 agent 另行重算8份manifest与其中原件、核对源文件摘要及暂停/最终job集合，通过。原型 README 提供复跑命令，run 目录需为新目录。

## 4. 独立审查实际发现的问题

不同审查 agent 分别做 [Standards 轴](review-standards.md)与 [Spec 轴](review-spec.md)。它们都有同一 OS 文件权限，能独立检查与复算，但不构成生产权限隔离。

两轴共同复现：初版计划 tile=12，候选源码实际 TILE=13；这组形状的 `ceil(M/12)` 与 `ceil(M/13)` 相同，流量一致，因此初版审核错误放行超出12个累加器的代码。这是需要修复的验证器漏洞，不是允许改变容量的理由。

已完成修订：核对源码唯一顶层正整数 TILE 与冻结计划一致，矛盾、重复声明或不能确定时拒绝；增加4个回归用例；重跑整个演示形成新 evaluator 摘要。另将实施文档中 AAT 的基线统一为本轮实际核查的 v2 SHA。审查报告保留原发现与修复后的复核状态。修复仅适用于受限模板，不证明任意代码的实际峰值资源占用。

两条独立审查线均已复核关闭初审问题。Standards 轴原1项P2、Spec轴原2项P2（其中1项为同一tile问题），当前没有未关闭的P1/P2；不将其解释为生产平台验收。

## 5. 验证覆盖与未覆盖

| 能力 | 本轮状态 |

| 真实编译器/RTL/EDA/硬件或PIM | 未运行；研究结果不能外推 |

审后完整测试 **12 passed**，JUnit 为 [tests-reviewed.xml](../examples/gemv_loop/runs/tests-reviewed.xml)；Ruff 与两个原型源码的 Mypy（跳过第三方内部导入检查）通过。完整名称和命令见[原型结果页](../examples/gemv_loop/RESULTS.md)。依赖存在两条兼容性/未来默认值警告，已在原型 README 说明；当前测试通过不代表所有 Python/框架版本组合均可用。

## 6. 可得出的结论

可以进入真实 provider 纵向集成：接口与控制分层有可运行载体，错误结果和错误审核假设能被独立检查发现并修正。还不能宣称完整 OPC 已上线或能自动完成开放科研。下一验收应复用同一合同与冻结 evaluator，真实派发专家、设计、验证三种调用，补上身份、费用、隔离和恢复证据。
