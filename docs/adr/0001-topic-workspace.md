# 以专题工作区替代冻结 Run 与账本

ArcHa 将研究执行模型改为专题内的线性探针轮次，以目标、认知状态和探针/结果作为权威内容，替代冻结 Run、Claim 账本和独立交付晋升。保留原始研究证据但不兼容旧执行格式，是为了让人工介入和无状态 Worker 接入保持简单；代价是不再提供旧 Run 审计与独立验收保证，同一工程串行执行，研究完成也不代表代码已发布。具体执行协议与替代范围以[重构方案](../../archa-refactor-plan.md)为准。

## 讨论定锚与执行循环

四个技能收敛为 `/archa-discuss` 与 `/archa-run`。讨论入口允许多轮澄清需求和比较方向，也负责明确任务的执行准备讨论；执行入口在目标、环境就绪与反馈回路均已确认且已有授权后，管理运行、配置检查和报告。分开入口是为了明确目标仍可讨论与已作为行动依据的边界，避免仅因调用技能就启动执行；已有启动授权无需重复确认。两者共用专题材料，不增加交接文件。取消强制前置方向拆分；首轮优先明确测量边界、已有基线与关键未知项，允许系统模型留白并随证据修正，不要求首轮完成全貌分解。沿用现有认知状态结构，按目标收益、信息价值与验证成本选择下一步，不引入评分系统或独立的探索／优化阶段。

目标明确不等于可立即执行。讨论阶段需明确环境搭建方式、就绪判据及验证依据，以及执行观测如何记录、判读并回到 Expert 支持下一步决策；复用已有答案和证据，只补实际缺口。相关约定沿用现有目标与环境说明，不增加准备状态、独立验收文档或通用预检流水线。

目标已授权优化时，探针可在约定范围内直接修改工程，验证干预生效、正确性及目标收益；有效改动保留，无效实验由当前任务清理或撤回自身改动。纯调查目标不自动扩大为工程优化，不建设通用快照、自动回滚或独立晋升流程。

普通恢复继续原探针；用户明确改变目标或关注点时，由 `/archa-discuss` 在正常停止后处理旧的待执行探针，让 Expert 根据更新后的目标和状态重新出题。直接编辑目标不意味着自动撤销旧探针或既有工程副作用；不增加内容哈希、变更检测或新的调度状态。

未定锚的讨论保留在当前会话，目标足以指导下一步后再创建专题；跨会话继续未立项讨论需带入已有摘要，不建设讨论日志、草稿状态或会话恢复机制。已有专题的讨论在确认后更新现有目标与认知状态。

保留按需离线 `report`，移除独立报告技能，不新增 `HISTORY.md` 或第二份认知账本。文档清理范围为两个根方案与 `.scratch/s1..s5`：先将仍有效的协议收拢到现有对应文档并修复引用，再删除被替代的材料。旧规格与工单的历史说明通过 Git 查找，原始实验材料保留原位，不新增归档索引；同时修正文档入口中的过时流程与失效链接。较新的专题重构记录保留，并更新被两入口方案替代的说明。

安装时旧四技能移入现有备份位置，不保留可发现的旧入口或兼容别名；目标工程的固定运行时仍需显式升级。
