# S0 共同边界与测试方法

状态：**需求已收束（2026-10-31）**。用户授权余下取舍直接采用建议；实现细节进入 S1–S5。四题材料及环境自检见 [benchmark](../../../benchmarks/README.md)，正式考试尚未启动。准备题面和环境无需先走 Matt 流程；ArcHa 通用机制改造仍按后续阶段形成 spec/tickets。

## 共同执行语义

| 对象 | 边界 |
| --- | --- |
| Task | 持续的任务身份及意图 |
| revision | 一版目标、范围、权限和验收契约；已执行版本不改写 |
| Run | 引用一个生效 revision 的完整持续执行，可暂停恢复；不是一次实验 |
| Attempt | 专家选定的一项有边界工作；可以检验不同假设，也可以推进同一方向 |
| Call | 一次 Worker CLI 派发；不同于逻辑 session，也不同于会话内工具调用 |

目标或验收含义改变：回 Task 更新 Brief，Onboard 准备新 revision，再新建 Run。意图不变的接入问题交 Onboard；范围内研究和计划调整留在 Loop；方向或任务依赖需要重整时回 Map。同一 revision 可有多个独立 Run；兼容条件下暂停继续沿用原 Run。预算按既有授权累计，不因重启重置。

Expert 在 **Run 层**解释证据、提出假设和选择工作；选定后才创建 Attempt 并调用 Designer。Expert 按需 Call，续接同一 Run 的逻辑会话，CLI 不空闲常驻；后端不支持续接时从持久材料恢复。Designer 默认按工作使用独立上下文，局部实现、测量和调试不再机械拆 Attempt。准备与终验调用归其实际范围，不强塞进普通 Attempt。

Engine 维护**增量 DAG**，Expert 提议工作与依赖。只派发必要输入已就绪且资源允许的节点，不预建所有假设的所有步骤。依赖满足依据所需结果可用，不要求假设成立或代码被接纳。不同方向不自动独立；同方向可并行。各节点使用独立工作区和固定输入版本，计时共享资源受协调，候选代码不会隐式合并。

稳定 ID 与标题分开，例如 `A004｜a-02｜验证边界输入`；边显式引用 ID/输入，不解析标题。已执行事实不改写；后续调整形成新工作。具体状态与字段交 S2。

## 记录、判断与观察

成果保存与采用分离：代码未采用，仍保留有价值的数据、反证与解释。默认只读**短结果索引 → 单项详情 → 原始数据/trace**，Agent 按需展开；条件、关键失败和未决项在索引可见。小记录可合并，大记录再拆；CSV/JSON/JSONL 原件可独立读取。不强制每轮多报告、每条结论一个文件、总结 Worker 或逐轮 Reviewer。

提示词/skills 只补项目特有入口、索引未展开什么、原件在哪里，不重复泛化阅读要求。复用账本、成果入口、工作区、评价器和观察器，避免新增重复事实源或通用编排服务。

Expert 判断继续价值并建议停止/交付，Engine 执行契约要求的验收。停止不等于完成；没有可信提速就未完成调优目标，有价值反证不自动完成整体探索。允许保留的未知事先写进题面，不事后降标。资源上限、用户控制、执行受阻照实记录，不按连续无收益次数机械停止。

首版工作台贯通 DAG/阻塞、Call/会话、实际交接材料、证据和判断变化，并支持**暂停、继续、停止**，由 Engine 执行并留痕。知识编辑、手工改 DAG、页面发起任意实验后置；不新建第二套状态权威。

## 四题及最低验收

| 题目 | 最低完成依据 |
| --- | --- |
| [开发](../../../benchmarks/deepstack-development/TASK.md) | 单层 ring/mesh 通信代价模型满足公开接口与边界语义，通过外置功能核对 |
| [调优](../../../benchmarks/ramulator2-optimization/TASK.md) | 固定 DDR4 Generic/FRFCFS 路径保持逐事件和完整统计等价，在多类负载取得超过冻结门槛的可信墙钟收益 |
| [探索](../../../benchmarks/deepstack-exploration/TASK.md) | 解释 3D 存储输入到估计的机制、假设和必要上下游，关键主张有可复查证据 |
| [独立端到端](../../../benchmarks/deepstack-end-to-end/TASK.md) | 完整解释流程、架构、映射、调度、tiling、模块成本组合与输出，自主选择代表性链路深入核对 |

两类探索都区分来源描述、实现事实、运行观察和推断。可保留范围外变体、不可获取的校准来源及不可见内部细节，但须说明接口作用、影响与证据限制。可读实现未追踪、实际调用链未区分或关键矛盾未处理不能简单标“未知”通过；不可观察部分实质阻断核心交付时报告未完成/受阻。验收不预设研究答案、实验次数或唯一解释。

四题并列且没有先修关系，各从独立原始材料和全新上下文开始。端到端不继承模块题成果。题面为 Markdown，可直接作为 `$archa-map` 需求输入，不预填地图、Brief 或合同。开发题隐藏现成目标实现；调优题给完整可运行基线；探索题给足够上下游；端到端给完整原始发行版和论文。原始工程保留 `/root/DeepStack`、`/root/ramulator2`，不用迁移，均不开放给考试 Worker。

操作者负责固定材料、公开语义、外置验收及环境；Agent 自主决定研究路线。源码/依赖本地封装并保留许可，参考实现和研究笔记不进题内。仅 cwd 不构成隔离，所有 Worker 读文件/执行工具须接入题内权限边界；本次本地执行隔离与正式 Worker 接入是不同验证项。

## 后续阶段与迁移

| 阶段 | 必要实现与轻量反馈 |
| --- | --- |
| S1 | revision 生效、入口分工、兼容检查；用修订/续接小案例验证 |
| S2 | Run 专家会话、Attempt DAG、并行工作区与资源协调、Call 身份/恢复、Worker 工具隔离；验证依赖阻塞与恢复 |
