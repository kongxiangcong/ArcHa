# S6 四题独立验证

状态：方法已由 [S0](../00-foundations-and-test-methods/README.md) 确定，环境准备见 [benchmark 索引](../../../benchmarks/README.md)。正式考试等待 S1–S5 必要改造与集成验收，不把本次环境自检记作考试。

采用开发、调优、探索三个模块题，加独立端到端课题；题面、材料边界和最低验收分别见各题 `TASK.md`。四题从自己的原始材料和全新上下文开始，没有先修依赖，不共享成果。端到端任务考察完整解决课题的能力。

开考前固定 ArcHa 版本、模型/预算、revision、题内材料哈希与工具访问边界；所有 Worker 工具须实际接入隔离环境，不能仅改变 cwd。由 ArcHa 从 Markdown 题面执行 Map/Task/Onboard/Loop，操作者不提供预制研究路线。候选按明确版本交给外置验收，验收材料不进入 Worker 上下文。

结果分别报告题目完成情况、必要证据和框架行为：计划/执行是否关联，反证是否反馈决策，会话/依赖恢复是否正确，观察器能否追溯交接与停止原因。模型输出不自动等于硬件真值；未知、预算退出、环境故障与验收失败分开表达。

框架缺口回相应阶段修复，只重测受影响项；改变任务目标/验收时按 S0 创建新 revision 和 Run。不得因失败降低标准。完成依据各题冻结验收；无需强制固定迭代次数、论文全量复现或另做直接 Agent 对照，若要宣称效率/泛化优势再补对应证据。
