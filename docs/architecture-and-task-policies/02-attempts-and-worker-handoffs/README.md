# S2 统一 Attempt、Worker 交接与运行观察

状态：S0 已确定共同边界，本阶段接口与实现细节待设计；本阶段可以在讨论后形成多份 spec 与多张 tickets。

入口：[总规划](../ArcHa_Phased_Development_Plan.md)。整体文档依据：[§8](../ArcHa_Overall_Architecture_and_Task_Policies.md#s08)、[§9](../ArcHa_Overall_Architecture_and_Task_Policies.md#s09)、[§14](../ArcHa_Overall_Architecture_and_Task_Policies.md#s14)。

**依赖：** S1。目标是把“工作尝试”从单一代码补丁和数值结果中解耦。

## S0 已确认的执行边界

专家调用方式已确认：按需发起 Call，默认续接同一 Run 的专家会话，CLI 返回决策后可退出，无需空闲常驻。每次请求独立记录调用身份和用量；会话失效或后端不支持恢复时，从持久化材料重建。后端续接能力、结果触发/汇集与故障恢复属于 S2 实现核查项，不能宣称现有适配器已支持。

用户已确认 Expert 归 Run 层，选定一项或多项计划后创建 Attempt 并调用 Designer。Expert 在 Run 内保持连续决策上下文，后端支持时复用或恢复会话，也可从持久材料重建；Designer 默认按具体工作使用独立上下文。详见 [S0 最新讨论](../../discussions/evaluation/s0-modeling-exploration/winson-whiteboard.md)。该约定替代“每个 Attempt 内先调用专家、所有角色 Call 默认新会话”的前序方案。

Run 引用生效 revision，承载一段可暂停恢复的持续执行；其中 Attempt 是有明确起点、工作目的和结果记录的一轮工作，Call 是一次完整角色派发。一次 Attempt 可包含多个 Call、测量和产物，不要求对应一个假设或代码补丁。Expert 在既有决策调用中复盘前轮并规划下一轮，无须新增总结调用。

Call 与会话身份分别记录；会话内多次模型请求、工具使用、编译调试不另拆 ArcHa Call/Attempt。创建 Run/Attempt 和保存记录不启动 Worker CLI；程序评价器直接运行。Onboard 与终验调用按准备或交付范围关联，不强制归入普通 Attempt。S2 复用现有记录与角色边界，细化交接和恢复，避免扩建常驻团队或强制逐轮审核。

用户已要求引擎维护增量 Attempt DAG。Expert 提供选定工作及所需前置成果，Engine 检查依赖、拒绝环并按资源和授权派发就绪节点。不同假设方向与同方向后续工作均以 Attempt 表达，显示标题标明方向/方向内序号/具体目的，稳定 ID 与依赖边不从标题推导。一次工作可关联多个方向，不引入子 Attempt。

并行使用独立工作区和固定输入版本，保留单引擎写入记录；性能测量等共享资源按冻结条件协调。依赖满足须核对需要的成果可用，不以“上游结束”或“假设成立”为统一条件；多分支结果不自动合并为代码。图随专家决策扩展，未选定的备选步骤无需预创建节点；已开始节点的输入与依赖保留原意。当前引擎仍为串行执行，上述是待实现要求。

## 需要讨论的方向

- 确定 Attempt 边界、公共身份与按角色划分的输入输出；普通开发无需填无意义的竞争假设字段。Expert 解释与决策、Designer 实施、Evaluator 验证、Reviewer 按需审核的责任保持清楚。
- 打通有代码修改、无补丁新测量、仅分析已有证据等最小路径；无需某个角色时可跳过。实际执行、产物引用、检查结果和资源记录分别表达，保留既有开发与优化行为。
- 定义调用失败、候选失败、无效测量、待分析、停止和恢复的语义；重试与新测量有明确关联，不把旧缓存当新实验，不因恢复重复记账。
- 同时交付节点开始/结束、交接引用、实际上下文、产物和错误的最小 trace。记录模型对外给出的理由与实际操作，不要求披露模型内部思维全文。

## 拟议结束条件

轻量案例能执行、暂停/恢复并定位失败；外部可按身份关联计划、调用、产物和结果。相关既有 Worker 后端同步适配或明确不支持，不能只让测试后端工作。

**本阶段不做：** 通用消息总线、任意工具节点编排、分布式调度或为每个内部步骤新增模型调用。实施有界的 Attempt DAG 与并发交接；策略的完整接纳与交付语义在 S4 收束。

## 优先收敛的问题

1. 工作尝试的边界怎样确定，哪些工作可以跳过 Designer 或正式评价？
2. 各角色最少需要哪些输入、可以返回哪些结果，计划偏差怎样被后续角色理解？
3. 外层从哪些已有事实辨认正在执行、已结束、未确认和可恢复；哪些错误需要重试或讨论？

本阶段使用必要的框架回归、夹具或轻量案例获得反馈；DeepStack 正式建模探索留到 S6。方法变化回写总规划中的测试方法约定，不在此提前运行研究。
