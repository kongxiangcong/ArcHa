- **继续**：关键前提仍获支持，阶段能力可信，尚有明确可检验的下一步；指标不涨不自动排除。
- **修正**：能力可以保留但原解释不充分、需要调整方案或补诊断；实现失败通常先考虑修复/重测，不能据此宣告理论错误。
- **放弃或搁置**：有效证据推翻必要前提、已不满足确认的目标约束，或多次实验没有形成新信息且没有具体可检验的新理由。停止投入保留档案、失败认识及重开条件；不等于删除成果或证明全局无解。
- **不确定也是有效输入**：证据不足不阻塞所有探索。可以安排诊断实验，但不能把未知写成已知来晋升成果；延续路线必须提出可检查的新预测，仅换说法不重置停滞，所有探索继续计成本。
- **MXU 假想走查**：专家事前约定流水模型与独立 RTL 参考在指定 cases 上一致；评价器确认这些结果，但系统误差未变；reviewer 记录“模块级一致性得到支持，系统瓶颈解释未验证”；下一 expert 选择从检查点接入层级模型，并给出连接正确性检查及能区分模块误差/调度误差的对照。该轮可续用模块，不可声称已解决系统瓶颈。

| --- | --- | --- |

- **工程续用资格**：正确完成一个必要模块、满足已有阶段验收，并明确下一步怎样使用它；仅能编译或专家自称“有潜力”不够。全局尚未达标与已实现部分违反硬约束要分开。损坏候选可留档作为明确的修复输入，不能标成已验证工程成果或携带有效性能结论。
- **两个比较对象**：新实验相对直接 parent 的变化说明本轮作用；相对 champion 的变化说明累计退化/收益与交付资格。只比 parent 会让“从更差恢复一点”伪装成全局进步。检查点快照与研究记录沿用单个 SQLite 账本管理身份/状态，Git 与 Markdown 保持投影或被引用产物，避免双重权威。
- **下一轮最小决策说明**：选择哪个已归档/已验证起点；采用或质疑哪条有来源结论；下一实验要补齐哪个能力或区分哪种解释。档案存在但没有这些消费规则，不构成积累。纯测量实验也应允许写有效证据与结论，无需为了改变状态硬造源码补丁。
- **防止无收益堆积**：检查点可保留，是否继续投入另判。事先说明预期后续用途及复核条件；根据实际阶段证据决定继续、搁置或回到冠军。新增叙述不自动重置停滞；所有探索都累计成本。若两条路径必须交替推进的真实需求反复出现，再扩大到多个活跃检查点。
- **结论有效范围**：容量扫描未改善性能，只能对已测配置、实现及测量分辨率下的解释提供证据；不能自动排除所有内存瓶颈。实现错误、环境故障或测量不可比应标未检验/证据不足。后续版本改变假设相关条件时，重判旧结论适用性，保留修订关系。
- **竞争路线**：若模块→层级→系统的依赖与阶段产物已明确，优先沿用阶段合同和独立验收，每阶段本身有真实完成标准；更简单。若方向必须靠实验发现、需要暂时中性/劣化的起点或纯取证，才需要工作检查点与冠军分离。无需把所有研究任务预先拆成固定流水线。
- **假想走查**：加入 MXU 流水模型，与独立 RTL 参考在指定 cases 上一致，但尚未连接层级模型，系统误差没有改善 → 保存带验证范围的工作检查点和“模块级一致、系统贡献未检验”结论 → 下一轮从该检查点接入层级模型，引用该结论说明为何能推进 → 通过完整验收并优于冠军后才更新最佳版本。若只是测量发现原假设不受支持，则保留证据与结论，代码起点无需变化。

### 减法、评测草案与下一步

- 保留四例为流程冒烟测试；不再通过加简单题、强制最低轮数或削弱 Codex 制造迭代优势。推迟全图调度、种群/Pareto 管理与 harness 自改，直到小实验暴露确切瓶颈。
- 两类任务分开验：**能力构建**可选缩小的 MXU→存储/流水交互→小系统性能模型，评价未见 cases 上的预测误差、功能/需求覆盖及独立参考的一致性；**搜索优化**可用强基线 kernel 的独立变体，评价正确性约束下的性能，以及瓶颈改变后能否修订方案。以上是候选设计，尚未校准任务或验证参考模型，不能当成已经就绪的 benchmark。
- 先做一个 CPU 搜索任务的辨别试验：A 完整持续 Codex；B 独立重启 Codex best-of-N；C ArcHa。共享模型/推理强度、初始工程、工具、知识材料、可见反馈及终验条件，允许 Codex 正常计划/改测/重规划。若需额外区分规划技能，在后续固定版本单独做消融，不先把工具使用方式误称为能力边界。
- 按预先指定的相同预算档位比较 best-so-far 有效分数、成功率/达标成本，并分别记录 token、墙钟和评价调用；三类成本不能强行假装同时完全相等。另设更大预算档观察能力上限，允许多花资源但按实际消耗比较，不把“更多钱跑得更好”归为反馈机制增益。设置真实停止条件，不保证最终达到不可行目标。
- 初步各 3 次只是辨别方向；最终可靠性需要更多独立任务实例与重复。校准实例和独立留出实例分开；搜索期间不暴露最终留出分数，禁止现成答案/历史解只向某一组开放。搜索器对照使用同一冻结任务；map/task/onboard 的端到端效果另算，避免用 ArcHa 生成的更好需求只给 ArcHa。
