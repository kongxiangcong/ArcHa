# Winson 讨论白板：OPC / Ge

更新：2026-10-22。

## 目标与边界

用户确认三部分：Winson 为独立需求顾问；Ge 是用户唯一运行入口与 CEO；下游专家提出实验、设计实现执行、独立验证双轴审核，再反馈下一轮。核心使用可执行状态机，而非仅技能提示词。

先前交付实现文档、合同模板和便宜的可运行探索验证。本轮进一步确认它必须可接入任意项目，参考 openTPU 的目录与生命周期、GSD 的合同模板和确定性校验；不把离线工程证据升级为真实模型科研或 PPA。原始交接文档保持不变。

## 当前判断与问题地图

合同/接纳服务是唯一业务权威；Argus 的执行会话/审核/UI 为首个真实接入候选。LangGraph 与 SQLite 在旧原型中实际复用，规则专家和模板设计器用于隔离验证控制逻辑。新增 v0.2 将项目身份、基线、需求、行为/关键连接和具体产物绑定纳入协议。下一返回点是通用接入合同到实际 provider/runner 的完整映射和受控 reviewer 权限。

## 减法记录

- 删除首轮公司式多层 agent 组织和多个 Master：不增加可验证能力。
- 推迟完整 UI、种群优化器、SoL-Pi、分布式与 harness 自改发布：到测出具体瓶颈后再加入。
- 缩小 openTPU 实验为 GEMV 行分块代码生成与精确整数执行：先验证流量模型、非法候选拒绝、预算与恢复。
- 目标项目保留原源码结构；只增加小型 `.opc`，工作区必须在项目外，证据默认 `.opc/local/artifacts` 或外置。配置、原件、工作区和缓存分离。
- 从 GSD 采用需求追踪、决策边界、行为/产物/连接与覆盖；不安装第二个 Master，不引入固定 phase/wave 或自动发布。模板由 Ge 按阶段生成，用户不需要填全套表。

## 证据与假设

- 固定 SHA 源码核查见 `docs/research/`；Argus 的 typed review 机制可借用，布尔完成门不是提交审核。
- 原型实际搜索和复核见 `docs/validation.md`，受限于四工作负载与简化模型。
- 独立审查发现 tile 计划与候选代码未绑定会误放行资源超限；已修复、补4个回归，审后12项测试通过，两轴独立复验关闭。正式运行见 `examples/gemv_loop/runs/final-reviewed-20261021/`。
- 待验证：真实模型提案质量、OS 权限、费用与外部仿真作业对账、通用合同到运行层映射。
- 本轮两种项目布局实际初始化，源码 hash 不变；合并测试 30 pass / 1 skip，新合同 10+7 反例拒绝。独立审核发现的文件祖先冲突和缺少产物 ID→原件映射已修复并复验关闭。完整记录见 `docs/integration-validation.md`。
- v0.2 接入工具仍是骨架/路径规划，未接管旧 GEMV。符号链接用例因本机权限跳过；不推定已经有 sandbox 或生产鉴权。

## 理解进展与下一步

用户明确要自动研发 harness，不是项目管理文档。已经把角色职责、状态所有权与接纳门区分；没有要求用户逐步确认本轮概念，按完整交付推进。

下一阶段：让一个组件在 v0.2 下完成登记、基线、runner 执行、冻结、独立审核和恢复，再接入真实三角色调用，保留冻结 evaluator 和失败注入验收。具体后端、隔离环境、资源与费用范围在派发该阶段前落定；本轮未推定外部模型/设备调用授权。
