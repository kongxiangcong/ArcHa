# ArcHa 开发执行提示词

以下正文供新开发会话完整使用。将其作为指令发出即授权按下述范围实施；本文件的存在不代表当前会话已经启动开发。

---

请在 https://github.com/kongxiangcong/ArcHa 的 PR #5 分支 `codex/task-completion-spec` 上，完成已规划的“以任务完成为主线”改造，并完成工程任务验收。此提示词确认该分支最新 spec、tickets 和 validation 方案，授权顺序实施与其中明确预算的一组真实对照；不要停在计划或要求我提供数据。

先检查工作区、项目约定与远端更新，保留用户其他修改，拉取该分支最新提交。读取：

1. `docs/design/task-completion/spec.md`
2. `docs/design/task-completion/tickets.md`
3. `docs/design/task-completion/validation.md`
4. 当前相关源码及项目测试/提交规范。

**实施方式**

- 按 T1 → T6 顺序逐票完成，不同时开展多张票。当前已有代码仅包括规划和验收素材，不要将素材自检当成框架改造已完成。
- 开工前在 tickets 中记录本次授权，当前票改为 in_progress；每票实现、针对性验证通过后改为 resolved，记录实际提交/验证/限制，单独提交后进入下一票。常规实现选择无需再次询问我。
- 保留一个引擎循环、现有专家与设计者分工。专家决定工作价值、路线、起点和停止；设计者连续实现与局部调试。完成条件负责交付，数值冠军只负责可比较的排名。
- 不新增角色、控制器、运行产物类型、摘要/RAG 服务、通用工作流层或恢复框架；不过度防御，不向模型硬塞全量机器数据、历史和背景。新增必要语义时删除被替代职责，不能把旧路径和特例层叠起来。
- 删除不再采用的已跟踪旧 benchmark 用例/脚本和 FP32 评测包及当前入口，不删除仍有价值的框架回归测试，不清理用户未跟踪实验原件，不新建 legacy 副本或 benchmark 平台。具体边界见 validation §8。
- 仓库内技能修改随 Git 提交，遵守适用技能维护规范；不擅自修改全局技能或其他项目 runtime。

**验证方式**

- 每票运行对应测试；最后执行完整 pytest 与 diff 检查，查看实际 CI，分别报告 Linux/Windows 结果。缺测试依赖可在隔离环境安装，不改变产品依赖来适应当前机器。
- 已备齐材料在 `tools/tests/fixtures/dma_backpressure/`，不需要我提供任何原始数据。先执行素材 unittest 自检，再按 validation 生成固定 82 个输入、检查起始功能失败和冻结数据摘要。
- 使用两个隔离的新会话和独立任务仓库执行同一 DMA 背压开发任务：直接 Codex vs 当前改造后的 ArcHa。只给相同 TASK.md、starter 和公开检查，不给参考实现、隐藏输入、另一组成果、本次框架改造 tickets 或预先分解的产品实现路线。
- 按 validation 的默认模型与预算执行：gpt-6.1-sol / medium；每组开发端到端 30 分钟、累计 input+output 2,000,000 token，ArcHa 最多 12 次 attempt；最终独立 review 每组另限 10 分钟/500,000 token，并归入总成本。只执行一组 pilot，不自动重试到成功或扩展实验矩阵。
- 共用相同运行条件，随机记录先后顺序。ArcHa 准备/onboard/expert/designer/收尾都计成本，不能只统计 run。外置终验脚本不调用模型；最终 reviewer 在新会话中尽力匿名审阅两份产物。
- 一轮完成同样有效，不强制多轮。不得让执行者在框架外代写产品、修框架或偷偷改冻结验收；若遇到框架故障，如实锁定该次失败。真实模型不可用时完成所有独立的代码/离线工作，将真实 pilot 标为 blocked/not_run，清楚说明具体障碍，不伪造成功或把总体验收标为完成。
- 两组终点锁定后统一进行外置终验。对照失败后可修复框架，但首次结果保持原样；再次真实实验需另有明确预算授权。验收不只看测试数量，还要看时序、数据语义、CLI、使用说明及适用边界。
- 复用 tickets 和现有报告记录结果，不增加中间报告链。只对实际测量下结论，不将合成时序任务解释为真实硬件性能证据，不用单次对照声称普遍优越。

**交付方式**

把全部实施提交推送到同一分支，更新 PR #5 的标题、描述和验收状态；完成所有验收后再将草稿设为可审阅，不自动合并。最终给出六张票的状态、主要删减与行为改变、测试与真实对照结果、剩余限制及 PR 链接。没有满足的项明确列出，不能用“框架已完成但未验证”代替用户可审阅的实际结果。
